# 机械臂推块：把运动学、力矩控制和接触反馈接起来

两根连杆绕竖直轴转动，末端的小球沿桌面方向接近方块，再把它向前推。一条看似简单的直线，串起了机器人实验中几件不能互相替代的事：给定目标轨迹、求关节目标、施加有限力矩、读取真实关节运动、计算实际末端误差，以及确认接触确实让另一件物体移动。

本课是首个教学包的机械臂综合实验，环境固定为Ubuntu 20.04、Gazebo Classic 11.15.1、ROS 1 Noetic、gazebo_plugins 2.9.3和Python 3.8，平台界面使用Qt 5.12。任务采用已知几何、已知物体初位姿与一条预先规定的推送方向。它帮助你把前面的知识接成一次可复查的接触操作；完整MoveIt规划、视觉定位、抓取、力控制和系统辨识需要另外建立问题与实验。

**自由度（DoF）**表示可独立改变的运动坐标。本课有肩、肘两个受控转动关节，因此是2自由度、2R机械臂。连接底座与世界的固定关节、连接末端球与前臂的测力固定关节，都没有新增受控自由度。FT输出六个力/力矩分量，也不意味着机器人变成六自由度。

**正运动学（FK）**回答“读到这两个实际关节角后，末端在哪里”；**逆运动学（IK）**回答“希望末端到这里，关节目标可以是多少”。IK算出的角度仍是目标，必须经过执行器与动力学才可能实现。

## 先沿完整信息流找一遍数据来源

```text
个人world.sdf + parameters.json + 当前源码
  → prepare.py校验输入、依赖与构建缓存
  → 本课私有Classic/ROS会话加载机械臂、动态方块和地面

模拟时间 → 期望末端直线x*(t),y*(t)
          → 连续选取同一IK分支 → 期望关节q*(t)
                                    ↓
实际关节q、q̇ → 原生插件计算PD → 力矩限幅 → Joint::SetForce
       ↑                                             ↓
       └──────── 刚体、惯性、关节约束与接触求解 ←───────┘
                            ├→ 实际末端位置 → FK交叉核对与跟踪误差
                            ├→ pusher/方块真实接触 → 方块实际运动
                            └→ wrist_joint反馈 → 系统ROS FT → /arm_push/wrench

mission.py → 同一持久arm_client：逐行JSON命令/带身份的新确认
              → 本次Classic会话内的原生插件

本轮实际状态 + 原始ROS消息 + 转移事件
  → 独立运行目录 → CSV + 四面板SVG + 结果与来源记录
```

本课使用原生ModelPlugin直接执行关节PD，便于把两条关节的算法完整放在眼前；第25课的controller_manager接口没有同时接管这两个关节。两套控制器同时写同一执行器会让力矩来源不清楚。ROS用于启动、观测、服务与记录，动力学运动仍由Classic物理引擎计算。

任务程序在自身生命周期内只启动一份持久`arm_client stream 0`，后续读状态、开始、保持、启停驱动和设置参数都走同一条连接。每条命令有独立id，必须收到匹配的新确认，不能用缓存状态冒充确认。若确认丢失，修改动作的命令不自动重发，客户端也不自动换一份；程序保留失败与停止确认状态。这样能区分“请求已经发出”和“实际结果已知”，同时避免每次采样都反复连接、断开Classic Master。

## 把机械臂和方块的几何读明白

模型`push_arm`包含`base`、`upper_arm`、`forearm`与`pusher`。`shoulder_joint`、`elbow_joint`都绕+Z轴转动，杆长分别为L1=L2=0.35 m。`anchor_joint`把底座固定到world，`wrist_joint`把末端球固定在前臂末端并提供真实关节wrench反馈。方块为`push_block::link`。

两根杆的运动位于水平XY平面，末端球心初始约为(0.40,0,0.10) m，球半径0.04 m、质量0.05 kg。方块边长0.12 m、质量0.20 kg，初始中心约为(0.51,0,0.0601) m，地面碰撞位于z=0。世界重力为(0,0,−9.81) m/s²，方块与地面形成真实承重和摩擦接触。

初始球的最前端为x=0.44 m，方块后表面为x=0.45 m，名义间隙0.01 m。小球首先跨过间隙，随后才可能推动方块。若跟踪足够好，末端球心最终接近x=0.64 m；保持接触时，方块中心的几何预测约为`0.64+0.04+0.06=0.74 m`。这只是几何预测，实际结果要读取方块位姿、速度、接触与误差；不能把0.74写进日志当作实测。

本课不是竖直平面的二连杆：重力不会以相同方式直接形成绕竖直轴的重力驱动力矩。它仍然决定末端球的竖直承重与方块的法向载荷。水平运动不等于世界关闭重力，也不等于FT各分量都应为零。

## 实际关节零位需要加上装配偏置

SDF在装配时已经把两杆折成初始姿态。Classic原生关节读数q1、q2初始接近0，并不代表两根杆都沿世界+X方向伸直。定义：

```text
a = acos(4/7)
θ1 = q1 − a
θ2 = q2 + 2a

x_FK = 0.35cosθ1 + 0.35cos(θ1+θ2)
y_FK = 0.35sinθ1 + 0.35sin(θ1+θ2)
```

θ1是第一杆相对世界+X的物理角，θ2是第二杆相对第一杆的物理转角；q是相对当前装配零位的关节读数。初始q=(0,0)代入得到x=0.40 m、y=0，而直接把q代入零偏置公式会误算成x=0.70 m。

课内verify用CSV中的实际关节角重算FK，并核对真实pusher link位置。前者来自实际关节读数与几何，后者来自Gazebo实体读回；两者应在有限容差内相符。若把期望q*代入FK，再称为“实际末端”，即使电机关闭也会画出漂亮直线，这会使整项实验失去意义。公式、逆解与雅可比的逐步推导见[参考页](reference.md)。

## 期望直线怎样变成有限力矩

默认推送段T=6模拟秒，从x*=0.40 m平滑移动到0.64 m，y*=0；开始前有0.8模拟秒SETTLE。推送段使用三次时间缩放：

```text
s = clip((t − t_push_start)/T, 0, 1)
h = 3s² − 2s³
x* = 0.40 + 0.24h，y* = 0
```

h在两端的速度为0，中点最快。默认平均期望速度0.04 m/s、最大期望速度0.06 m/s；这是期望轨迹的数值，实际末端和方块速度不会由此被强制设定。模拟暂停时轨迹时间不前进，计算机墙钟继续走；有限墙钟超时用于发现没有新反馈的会话。

这条固定路径先由几何证明可达，原生插件随后使用等长两杆、y*=0的解析逆解，始终选择与初始折叠一致的肘部构型。两杆最大伸展距离0.70 m，目标0.64 m保留伸直前的余量。接近伸直姿态时，末端某些方向的小速度可能需要很大的关节速度，称为运动学奇异性。若以后扩展任意目标，应增加可达性与关节限位检查；不能把目标移到可达圆外，再靠任意夹住acos输入“修好”任务。

物理角逆解还要减去装配偏置，得到原生关节目标q*。每个物理更新读取实际q和q̇，计算：

```text
e_i = q*_i − q_i
τ1_raw = 100e1 − 4q̇1
τ2_raw =  70e2 − 2q̇2
τ_i = clip(τi_raw, −torque_limit_nm, +torque_limit_nm)
```

角度单位rad、角速度rad/s、力矩N·m；P增益单位N·m/rad，D增益单位N·m·s/rad。本课路径保持同一连续分支，没有跨越±π，因此直接相减。扩展连续转动目标时才需要明确最短角差wrap及限位语义，不能不加区分地让有限范围关节“抄近路”穿越限位。D项采用实际速度阻尼；该式没有加入q̇*前馈，也没有积分项，所以接触负载下保持一小段静差是可能的。

默认每关节力矩上限6 N·m。两杆的惯性互相耦合，方块的接触反力与地面摩擦又形成外载，实际轨迹需要物理积分才能得到。提高上限只在控制输出发生限幅时改变这条受限链路，不保证跟踪误差必定降低；增加P、增加D、延长动作时间也不是同一个改动。

任务过程中使用`Joint::SetForce`施加受限关节力矩；没有用逐帧SetPosition、SetPose或SetVelocity写出实际轨迹。初次装载与明确的世界复位属于建立实验初态，要与连续控制产生的运动分开。[Classic关节施力与状态接口](https://github.com/gazebosim/gazebo-classic/blob/gazebo11_11.15.1/gazebo/physics/Joint.hh)

## FT测到了什么，哪些量不能叫接触力

`/arm_push/wrench`使用系统`libgazebo_ros_ft_sensor.so`，名义50 Hz，消息为`geometry_msgs/WrenchStamped`。它是ModelPlugin，直接读取`wrist_joint.GetForceTorque(0)`的body2反馈。该版本固定按child轴、child_to_parent方向输出，frame由child link名称`pusher`及可选tf_prefix产生；加一个任意frameName不会自动旋转读数。[2.9.3 FT实现](https://github.com/ros-simulation/gazebo_ros_pkgs/blob/2.9.3/gazebo_plugins/src/gazebo_ros_ft_sensor.cpp)

这里的F是末端球通过腕部传给前臂一侧的合载荷，单位N；τ是关于腕部关节参考点的力矩，单位N·m。pusher轴随前臂转动，局部Fx不能直接当作世界+X推力。若球推方块向世界+X，方块对球的接触作用大体朝−X；合量还包含球的加速和重力，动态样本不能逐条要求恰好等于一个静态摩擦估计。

末端球质量0.05 kg，在无接触、近静止且竖直轴对齐的窗口中，Fz的预测约为−0.4905 N。因此三维力模长并不接近零。比较接触前后时，应另看水平分量`Fxy=sqrt(Fx²+Fy²)`；绕Z换轴不改变这个水平模长。CSV保留原始Fx、Fy、Fz，raw_ros.jsonl保留完整六分量消息，不把重力项悄悄删去，也不把水平合量称为纯粹的接触点法向力。

`/arm_push/contacts`提供实际碰撞反馈，确认哪两个collision发生了接触。它与腕部wrench的测量位置和含义不同。可靠推送证据要把pusher/方块接触、方块的实际位移、末端误差和腕部水平载荷放在一起看；“力矩命令变大”本身不是测到了接触力。

系统FT在WorldUpdateBegin读取已有物理反馈，header标当前模拟时间。任务程序在顺序查询两关节、pusher和方块前后，各读取一次真实世界时间，以两者中点作为本组测量的时间标签；期望量、CSV的sim_time与实际pusher TF使用同一中点，并保留查询的前后时间边界。中点只是明确的近似，不能把顺序查询变成原子同时采样。FT仍保留自己的原stamp，`/clock`和FT回调在查询期间继续接收数据；比较动态数据时应检查时间差。坐标换轴、换点与采样流程见[参考页](reference.md)。

## 实验一：先完成健康推送，再看保持段

使用平台为本课打开的操作终端：

```sh
python3 lab.py ready
python3 lab.py bootstrap
python3 lab.py run
python3 lab.py snapshot
```

ready核对当前连接与准备输入，不主动推进物理；bootstrap在当前目标下至少推进0.60模拟秒取得真实初始采样，然后暂停。run恢复物理，等待本轮新反馈，执行有限任务，并打印结果与输出位置，结束后再暂停。观察机械臂是否先稳定、再接近方块，方块是否在接触之后才开始前进，终点附近是否经过一段真实减速和保持。需要重新从初态运行时，明确执行`python3 lab.py reset --world`。

任务状态依次为`IDLE→SETTLE→PUSH→HOLD→STOPPING→SUCCEEDED`，未满足实际条件则为FAILED。SETTLE建立初始状态，PUSH按时间推进期望直线，HOLD固定最终关节目标并继续施加PD力矩，STOPPING观察实际运动是否满足结束条件。最终保持不是断电：阻止方块回退或抵抗接触负载时，非零保持力矩和非零FT可以与很小的实际速度同时存在。

判断保持要看未暂停的物理窗口里实际q̇、末端速度、方块速度与末端误差持续受限，不能先冻结世界，再拿“画面不动”证明控制器已保持住。结果写完后的暂停用于留住现场，暂停本身不是成功判据。

| 结束条件 | 当前实现怎样检查 |
| --- | --- |
| 末端到位 | XY实际位置相对(0.64,0)的误差<0.025 m |
| 方块前进 | 实际x相对本轮起点增加>0.10 m，且\|y\|<0.08 m |
| 实际减速 | 末端和方块平面速率各<0.025 m/s，两关节\|q̇\|各<0.08 rad/s |
| 确有接触载荷 | 本轮收到实际接触，腕部水平力峰值>0.12 N；它不要求每帧持续同样的载荷 |
| 持续观察 | FT新鲜且上述实际条件在HOLD满足0.40模拟秒，再在STOPPING满足0.40模拟秒；条件丢失就重新累计 |

这是对持续推进世界中的离散测量窗口作检查，不代表记录了每个1 ms物理积分步。HOLD超过3模拟秒仍未稳定、全程超过T+7模拟秒、超过40墙钟秒或FT连续3墙钟秒无新反馈，都应产生有限失败及原因。失败时原生控制请求零力矩；成功时保持最终PD目标，二者的收尾语义不同。

订阅时，先在另一个本课终端启动，再运行有限任务：

```sh
rostopic echo -n 1 /arm_push/wrench
rostopic echo -n 1 /lesson37/state
rostopic echo -n 1 /lesson37/configuration
```

暂停时动态FT可能没有新消息；latched状态也可能来自刚完成的一轮。先核对任务身份与stamp，再解释数值。不要额外启动另一份roscore或gzserver，也不要用全局清理命令处理其它会话。

本轮measurements.csv与measurements.svg应共同回答：期望与实际末端轨迹是否一致，跟踪误差在接触前后怎样变化，水平载荷何时出现，以及方块是否产生与接触相符的位移。当前SVG有四个时间序列面板，依次为世界x、世界y、实际跟踪误差和腕部水平力；它没有把目标曲线当成实际运动，也没有另行补画未测到的点。

CSV保存模拟时间与phase、期望XY、实际末端XYZ、实际误差、方块XY与平面速度、实际q/q̇、最近原生确认中的τ、FT原stamp与Fx/Fy/Fz/水平模长、最近接触数。六分量wrench和接触消息的原始序列化字节保存在raw_ros.jsonl，events.jsonl保存转移、实际状态查询、原生命令确认与碰撞配对。不同服务调用与FT的时间不完全相同，数值列不能被解释为同一物理步的全量快照。

状态和结果中的native_client保留原生子进程pid、启动身份与独立进程组信息，命令事件保留request_id；同一会话多次任务复位仍使用同一客户端。stop_confirmation分别记录是否请求停止、是否收到确认及是否读到零力矩；通信已失效时，这些字段会明确保留未确认，不能把FAILED当成零力矩已执行。CSV的采样与日志写入受顺序查询和实际运行速度影响，不承诺等于FT的名义50 Hz，更不表示每个物理步都有一行。

需要课程自动验收时执行：

```sh
python3 verify.py
```

verify会先暂停并全模型复位、保留模拟时钟，再启动一轮新的真实推送；它会移动机械臂和方块，并非只读上一份图表。它核对完整状态顺序、实际位移和接触、FK与pusher读回的一致性及误差算式，不自动完成后面的失能与恢复实验。完整范围与容差见[参考页](reference.md)。

## 实验二：切断执行器，先留下真实失败

从明确世界初态开始，关闭本课关节施力：

```sh
python3 lab.py reset --world
python3 lab.py enable-arm --enabled false
python3 lab.py run
```

本轮应在有限时间内报告失败并保留输出，run的非零退出码是这次故障实验的预期。轨迹发生器仍可计算目标，但执行器力矩为0；实际关节与末端不会因此沿目标直线前进，方块也不应完成规定推送。查看实际误差如何增长、方块位移是否缺失，以及原始力矩与enable状态，不能只凭FAILED字符串验收。

恢复时保留失败目录，重新启用，再明确恢复世界初态后重跑：

```sh
python3 lab.py enable-arm --enabled true
python3 lab.py reset --world
python3 lab.py run
```

`reset`先暂停，保存上一轮未完成的结果，清理任务缓存、恢复启用并建立新的任务身份，但不把球或方块移回出生位置；`reset --world`还明确调用Gazebo的`reset_world`，复位所有模型的位姿、关节和运动状态，**保留当前模拟时间**。本课原生Reset保留已核对的时长、上限，清除旧轨迹并恢复初始保持目标。这些初态操作不能拼进上一轮连续运动，新一轮的start_sim从实际时钟重新记录。

为什么不直接倒回时钟？2.9.3系统FT插件按`当前时间−last_time_`控制发布频率，未在Reset中清除旧采样时间；若调用reset_simulation倒时，新FT可能被抑制到时钟追上旧值。模型复位和时钟归零因此需要区分。本课选择保留时钟的全模型复位；需要从t=0开始时，重新加载整课会话。这里说明接口实现边界，不把缓存问题解释为末端没有承重。[FT频率控制实现](https://github.com/ros-simulation/gazebo_ros_pkgs/blob/2.9.3/gazebo_plugins/src/gazebo_ros_ft_sensor.cpp)

恢复命令中的enable=true把操作意图写清楚，reset本身也会恢复启用；两者都不构成“已经恢复成功”。单独把enable改回true，不会把旧失败变成成功，也不能用随后一张正常截图覆盖失败证据。恢复必须由新的任务身份、真实接触、方块位移、误差与保持窗口证明。

## 单变量实验：先预测，再比较本轮数据

| 只改变一项 | 运行前的预测 | 实际需要比较的量 |
| --- | --- | --- |
| T从6改为4 s，保持力矩上限6 | 平均期望速度从0.04变0.06 m/s，峰值从0.06变0.09；加速要求提高 | 实际误差、限幅出现的时段、接触瞬态、方块末位姿与保持 |
| T从6改为8 s，上限仍6 | 平均期望速度0.03 m/s、峰值0.045；过程更慢 | 是否减小跟踪滞后，接触载荷与总模拟时长怎样变化 |
| 上限从6改为3 N·m，T仍6 | 仅受限输出链改变，是否明显变化取决于默认过程是否限幅 | 用native命令事件的target_q、q、q̇重算τ_raw，与受限τ样本和误差比较；不要预先宣布一定失败 |
| 上限从6改为9 N·m，T仍6 | 允许更大输出，但PD、惯量与接触未改变 | 之前的限幅是否解除，是否引入更强瞬态；不是越大越好 |

比较前都恢复同一物理初态，每次保存不同运行目录。参数改变、未重载、沿用上一轮末态，都会破坏单变量解释。摩擦力量级可用`μmg≈0.25×0.20×9.81≈0.49 N`帮助理解，但ODE实际接触、两个表面参数、静动过渡、姿态和加速共同决定结果；这不是要求每条FT都等于0.49 N的验收公式。

## 遇到异常，顺着因果链查

| 现象 | 先核对什么 |
| --- | --- |
| 目标线走完，机械臂没动 | enable状态、实际τ、关节身份、物理是否推进；别把q*当q |
| FK显示初始x=0.70，球却在0.40 | 是否漏加装配零位偏置，使用的是原生q还是物理θ |
| 机械臂动了，方块不动 | 实际球/块间隙、collision配对、球高度、摩擦和实际末端误差 |
| 接触后误差稍大、保持力矩非零 | PD静差与真实外载；先看误差和速度是否稳定，再决定调参 |
| 无接触时力模长约0.49 N | 末端球自重；检查Fz与水平模长，不能把全模长当碰撞检测 |
| 世界X方向推，局部Fx/Fy都变化 | pusher轴随前臂转动；统一表达轴再比较有符号分量 |
| 力矩符号或大小对不上 | 作用方向、参考点与r×F；关节电机τ不是腕部六维wrench |
| 偶尔一行力与位置不同步 | 原生回调、FT调度与ROS接收各有时序；保留原stamp与时差 |
| run超时、没有新数据 | 私有Master/Classic连接、暂停、插件加载日志与输入指纹 |
| 原生确认超时或客户端退出 | 查看native_client、request_id、stderr日志与stop_confirmation；结果未知时不重复发送动作命令，也不把未确认停止写成已停止 |
| 开回电机仍是旧失败 | 旧报告不改写；明确世界复位，发起并保存新任务 |

## 完成后，你应能独立解释什么

先用一次健康推送、一次禁用施力失败、一次恢复后的新推送组成完整证据链。自动检查、实际Gazebo运行和人工GUI观察应分别记录，不能把世界能加载、话题有消息或某张图好看写成“综合实验全部通过”。当前课内verify的具体检查范围见[参考页](reference.md)，故障与恢复仍需按上面的命令执行并保留各轮结果。

独立挑战：用实际q与装配偏置重算整段FK，和pusher真实位置比较；在同一图里叠加期望轨迹与实际轨迹，再标出实际接触窗口。选择一轮接触前近静止样本和一轮接触中样本，解释Fz为什么保留、水平力模长为什么有用，以及为什么不能从六维腕部wrench唯一反推出接触压力分布。

如果继续修改控制算法，说明修改后的完整流程：时间目标→IK分支与偏置→实际误差→PD/前馈/限幅→关节力矩→真实接触→测量与保持判据。改几何时同步重推FK、可达性和间隙；改采样时说明stamp与对齐方法；改成功条件时说明持续窗口和失败案例。只有明确要修改源码时才动代码；每次改动都应结合这条算法上下文解释，并重跑受到影响的真实实验。
