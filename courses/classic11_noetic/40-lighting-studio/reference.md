# 参考：光照测量的算法与边界

默认距离2.8m时，衰减因子为 `1/(1 + .12*2.8 + .04*2.8²)`，约0.6062。它不等于最终像素强度；实际渲染还叠加其他光源、材质反射和聚光因子。

流程：有限参数检查→SDF生成→三张灰卡和实际spot/point灯→CameraSensor真实渲染→保存RGB和FNV校验→验收等待新帧→计算ROI平均RGB。红灯卡片要求R明显高于G和B；蓝灯卡片要求B明显高于R和G，避免把黄色或青色错误地当作红蓝色偏。中间灰卡留作遮挡视觉比较，不使用它的暗部大小自动认证阴影正确。

灰卡世界坐标y=+1.8和-1.8投影到图像左右。验收ROI固定在各卡片内部；因此更改成像参数后，需要更新ROI。两盏spot向+x照射，灰卡前表面朝-x，避免用背面照明去解释错误的颜色。

传感器图像输出PPM只是无损承载原始RGB字节，不是另行渲染的参考图。帧回调每5帧保存一次；验收同时检查序号增长、仿真测量时间增长与字节校验一致。

手动检查：切换cast_shadows前后截图；固定光位转动用户相机观察高光；让摄影棚灰卡承受一盏单光源，逐项比较不同距离的衰减。不要同时改变光位、材质与相机，再把结果归因于某一个参数。

三类灯光的具体实现：两盏spot使用当前linear/quadratic参数，white_fill是固定衰减的point，neutral_directional使用directional_fill_intensity（默认.02），方向(1,0,-.5)。后者从.02单独增加到.10时，应观察中性卡的RGB共同升高，而不是把该变化解释为spot衰减改变。中性directional无距离衰减，过高强度可能造成饱和。

真实像素验收仍只检查色偏与图像推进；阴影与镜面随视角变化另做视觉检查，不用暗条存在当作投影正确的证据。相机编译显式合并OGRE相关pkg-config flags，FNV-1a64的offset basis为14695981039346656037。结果持久保存于build/verification.json。
