# ModelPlugin：用几行真实力矩驱动转子

本课在固定台座上放一只带有方向标记的转子。你编写并加载一个 Gazebo Classic 的 C++ `ModelPlugin`：每次物理更新前读取实际角速度，计算驱动力矩与线性阻力矩，再把合力矩交给关节。角度和角速度继续由物理引擎计算。

第10课学习过电机与反馈，第25课使用了现成的 ros_control 控制器。本课直接进入 Gazebo 的插件接口，重点是看清插件怎样被创建、怎样接到更新循环，以及哪些代码真正改变了物理状态。本课不需要运行 ROS。

## 先认识插件、共享库与对象

插件是编译后由运行中的程序加载的一段代码。Linux 下本课的输出是 `.so` 共享库；Gazebo 从 SDF 的 `<plugin>` 声明找到库，创建插件对象，再把具体模型交给它。

| 名称 | 本课中的含义 |
| --- | --- |
| ModelPlugin | 拥有某个模型接口的插件基类 |
| ModelPtr | 指向本课 `rotor_lab` 模型的接口对象 |
| JointPtr | 指向 `fan_joint` 的关节接口，可读取状态并施加 effort |
| Load | 取得模型和 SDF 配置，检查关节、准备通信和更新连接 |
| Init | 插件初始化阶段，本课记录一次初始化状态 |
| Reset | 模型复位流程中的回调，本课重新开始一轮实验记录 |
| WorldUpdateBegin | 世界更新开始事件，本课在此读取状态、施加力矩 |
| ConnectionPtr | 保存事件连接的对象，让回调连接随插件对象管理 |

`ModelPlugin` 的“Model”表示入口交给它一个模型；这使你能按模型组织状态和参数。C++ 接口的可访问范围仍很广，编写时应主动把操作限制在本课拥有的模型与关节。后续 WorldPlugin、SensorPlugin 等课程再比较不同入口。

不了解 C++ 的类、成员变量或指针，可先看 [C++ 类基础](https://www.learncpp.com/cpp-tutorial/introduction-to-classes/)，再对照本课文件阅读；`override` 表示这个函数实现基类已有的虚函数接口。不了解共享库与构建，可参考 [Gazebo Classic 插件入门](https://classic.gazebosim.org/tutorials?tut=plugins_hello_world&cat=write_plugin)及 [CMake 3.16 的库目标说明](https://cmake.org/cmake/help/v3.16/command/add_library.html)。教程中的旧版软件包名需按本机 Classic 11 SDK 理解，平台已经列出了本课实际编译命令。

## 从配置到运动的信息流

```text
parameters.json
  → 准备当前个人副本与真实插件库
  → SDF模型中的plugin声明
  → Load(ModelPtr, sdf::ElementPtr)
  → 找到fan_joint，读取驱动力矩与阻力系数
  → 保存WorldUpdateBegin事件连接，再进入Init
  → 每个实际更新读取omega，计算tau = drive_torque - drag × omega
  → fan_joint的第0轴SetForce
  → 物理引擎积分与约束求解
  → 转子的真实姿态、速度，以及下一步反馈
```

本课世界名为 `lesson26`，模型名为 `rotor_lab`，转子 link 为 `rotor`，转动关节为 `fan_joint`。关节绕 Z 轴转动，台座固定于世界；应沿实际关节轴理解角速度符号。

`joint->GetVelocity(0)` 读取第0轴实际角速度，单位是 rad/s。`SetForce(0, torque)` 对转动关节施加 N·m。此处的代码计算力矩，随后物理引擎完成积分；不要再把力矩乘一次步长当作 `SetForce` 的输入，那会把力矩与角冲量混在一起。

Classic 的 `SetForce` 在同一步中可累计多次施力，本课每个更新对这个轴调用一次。实际关节还有 effort 上限，本课将它设为10 N·m，让常规输入下的线性模型先能清楚显现；这个规格不表示运行时一定施加10 N·m。接口细节见 [Classic 11 Joint API](https://osrf-distributions.s3.amazonaws.com/gazebo/api/11.0.0/classgazebo_1_1physics_1_1Joint.html)。

## 转子模型与参数

转子的名义质量为0.48 kg、半径0.25 m、厚度0.04 m，绕圆柱对称轴的惯量为：

```text
Izz = 1/2 × m × r² = 0.015 kg·m²
```

关节没有额外的固有阻尼和摩擦，本课的线性阻力由插件显式计算。这样可以把“物理引擎中的被动参数”与“插件施加的力矩”分开研究，避免两套阻尼叠加后仍使用同一公式解释。

世界保留重力，固定竖直转轴让本课关注绕Z轴的驱动力矩与转动。圆柱方向标记用于看清姿态，名义惯量取模型实际声明的惯性张量。

基准个人配置为：

```json
{"drive_torque": 0.03, "drag": 0.015}
```

`drive_torque` 是恒定驱动力矩，单位 N·m；`drag` 是线性阻力系数，单位 N·m·s/rad。正的 `drag` 使阻力反抗当前转动：角速度为负时，`-drag × omega` 为正。它不是只在正转时减去一项固定力矩。

常规个人输入接受 `|drive_torque|`在[0.01,0.09]、`drag`在[0.005,0.06]内的有限数值。准备阶段把这两个值写入个人 `world.sdf` 的 `drive_torque` 与 `linear_drag`，并记录配置和生成世界的摘要；手工修改这两个SDF值后重新加载，会由JSON中的常规参数重新生成。

| 文件 | 阅读或修改目的 |
| --- | --- |
| parameters.json | 驱动力矩与线性阻力的单变量实验 |
| world.sdf | 模型、实际惯量、关节轴及插件SDF声明 |
| model_plugin.cc | 本课 ModelPlugin 的生命周期与力矩计算 |
| observer.cc | SDK观察工具，采集原生pose、world_stats及插件记录 |
| prepare.py | 检查输入、编译真实共享库并记录当前来源 |
| config.py | 输入约束、准备记录与文件一致性检查 |
| lab.py | 就绪、观察、暂停、步进、复位和有限实验 |
| verify.py | 本课实际实验验收入口 |
| build/lib/libgazeboteach_l26_model.so | 当前个人实验实际加载的插件入口 |
| build/model_observer | 当前个人实验使用的原生SDK观察工具 |
| build/model_lab.json | 配置、生成世界、源码、SDK、编译器及构建产物的准备记录 |

这些文件位于你的个人练习副本。修改 C++ 或配置后重新加载实验，让准备阶段重新核对并构建；磁盘保存、库文件生成和运行中的进程是不同阶段。已加载进 `gzserver` 的代码不会因为你刚保存了 `.cc` 就自动替换。

本课准备程序用实际 `g++` 和 `pkg-config gazebo` 输出的SDK参数直接构建共享库与观察工具。缓存身份包含两份C++源码、实际SDK版本/链接参数及编译器；相同代码可复用缓存，改变个人C++会得到新的构建。常规力矩与阻力来自SDF，改这两个运行配置不必假装每次都重新编译同一份库。

## 先预测，再看真实曲线

从静止开始，在没有额外阻尼、未触发约束和力矩截断时，绕固定轴的理想模型为：

```text
I × dω/dt = drive_torque - drag × ω
ω∞ = drive_torque / drag
T = I / drag
ω(t) = ω∞ × (1 - exp(-t/T))
θ(t) - θ(0) = ω∞ × [t - T × (1 - exp(-t/T))]
```

`T` 是时间常数：从静止启动，经过一个 T，理想角速度达到稳态值约63.2%。本课基准 `ω∞ = 2 rad/s`、`T = 1 s`；3 s时的理想角速度约1.9004 rad/s，相对本轮起始角度的转角增量约4.0996 rad。静止指角速度为零，本轮起始角度本身可以不为零；比较时使用 `θ(t)-θ(0)`。这些是待核对的预测，不是生成测量数据的算法，也不是要求离散物理在每一位小数上等于解析式。

先写下自己的判断：开始时合力矩是多少？越转越快时阻力怎样变化？接近稳态时，驱动力矩、阻力矩和合力矩各是多少？在基准输入下，稳态仍有驱动和阻力，二者相抵才使角加速度接近零。

## 从真实场景进入本课

点击“开始实验”，等待平台完成依赖检查、个人副本准备、SDK构建和世界就绪，再打开 Gazebo 与本课终端。转子的方向标记便于直接观察旋转；颜色与画面只帮助理解，数值验收仍要读取原始状态。

先运行：

```bash
python3 lab.py ready
python3 lab.py status
python3 lab.py predict
```

确认实际模型、关节、加载参数及生命周期记录属于本课。`ready`与`snapshot`相关操作通过只读查询确认状态；暂停时不会为了拿到新运动消息而偷偷推进物理。插件状态查询返回最近一次实际回调保存的记录，时间和采样阶段也应按那条记录解释。

随后运行有限实验：

```bash
python3 lab.py demo
```

这项实验先执行真实的model-only复位，保留当前内部转角、清零角速度并建立新的插件轮次，再执行受真实力矩驱动的运动。结束时再次暂停并执行同一种复位：清零角速度，保留运动到达的角度；原生姿态的复位前后比较用于核对这一行为。随后工具恢复进入时的暂停状态；原来正在运行时，真实力矩会再次驱动转子，屏幕可能已经继续转动。命令不还原任意中途运动快照，模拟时钟、原记录与累计复位次数也保留。

若要观察当前已经运行的实验，并保持它当前的运动过程，可以使用：

```bash
python3 lab.py watch --seconds 3
```

观察进程的墙钟时长、原消息的模拟时间和接收时间分别保留。分析动力学使用真实模拟时间，不因机器较慢就把3秒墙钟当作3秒物理运动。暂停时可能没有新的pose或更新记录，只读观察不等于解除暂停。

## 插件记录与独立观察怎样互相核对

本课插件用 Classic Transport 的 `Any.STRING` 发布JSON记录，主题为 `~/model_plugin/state`。这是插件内部记录，包含其实际读取的角度、角速度、力矩、配置和生命周期计数；它帮助解释插件做了什么。

`observer.cc` 还读取 Gazebo 自己发布的 `~/pose/info`（`PosesStamped`）和 `~/world_stats`。从转子真实姿态得到转角，再按原始时间差估计角速度，才形成另一条观测路径。不能仅让插件报告“我给了力矩、我在转”，便当作独立物理验收。

| 观察 | 实际含义 |
| --- | --- |
| 插件omega、q与applied_torque_nm字段 | 相应插件回调中读取的状态及传给SetForce的计算力矩 |
| 原生pose四元数及消息time | Gazebo实际发布的实体姿态与其标签 |
| 原生world_stats | 实际世界时间、暂停和迭代等状态 |
| 接收单调时间 | 观察进程收到消息的主机时刻 |

WorldUpdateBegin 记录发生在相应更新的物理积分之前，同一模拟时间标签下的pose可能处于另一阶段。只读查询仍返回原缓存时刻，不会给旧值换上查询时刻的新标签。比较两路数据要保留时间顺序、采样阶段和允许的离散/接收误差。

`last_hook`和`capture_hook`区分初始化、原生关节复位后与WorldUpdateBegin中的记录来源，`observation_phase`进一步标明阶段。`sim_time_s`是那次采样的世界时间，`epoch_time_s`保存本轮起点的世界时间；本轮已过多久应计算两者之差。`applied_torque_nm`来自本课提交值，不能当作独立力矩传感器；`q_rad`是SDK关节位置读回，累积圈数另外由连续原生姿态展开判断。

本课原生link pose按发布实现处于模型相对坐标；模型固定、轴与初始姿态已知，才可按本课约定比较yaw。把这个算法移到有运动父模型或嵌套坐标的项目时，应先变换到同一参考系。

四元数得到的yaw通常包在 `[-π, π]`。基准3 s累积转角超过π，直接对包裹角求差会出现一次接近2π的假跳变。应先按连续顺序展开角度（unwrap），再用相邻真实时间间隔估计速度。相邻采样之间若漏掉超过半圈的运动，仅凭这些角度无法恢复真实圈数；不要用排序、改时间戳或凭预测曲线补齐来掩盖缺失。

## 暂停与真实100步

在本课终端中执行：

```bash
python3 lab.py pause
python3 lab.py status
python3 lab.py step --steps 100
python3 lab.py status
python3 lab.py resume
```

暂停时没有新的正常物理更新，转子状态与插件更新计数应结合world_stats检查。100步命令发送一次真实步进请求，再等待实际世界时间与更新完成；不能通过重复发送步进来补一个没观察清楚的结果。

世界物理步长、插件调用次数和记录发布率各有含义。插件每步可工作，记录却只按较低节奏发布；所以“100步没有100条JSON”本身不表示少算了物理。还应分清生命周期中的 `updates`、当前复位轮次的 `epoch_updates` 和世界本身的迭代计数。

## 真正复位时，哪些东西重来

```bash
python3 lab.py pause
python3 lab.py reset
python3 lab.py status
```

本课请求的是model-only复位。这条路径复位模型层的pose、清理物理速度与关节受力，然后调用插件 `Reset`；在本课固定模型中，内部转子的相对角度继续保留。实际检查曾在非零转角约3.1328 rad处确认复位前后角度相同、角速度归零。因此不能仅凭“模型复位”这个名字，就预期所有内部关节角都会回到文件中的零角。

这一复位继续沿用当前模拟时钟；应从原始world_stats确认，也要对照原生转子pose的复位前后读数。模型层变换、内部link相对姿态、速度以及插件成员变量分别属于不同层次。

在已暂停的Classic世界中，处理这次控制请求可能消耗一个0.001 s的控制调度迭代，再执行模型复位并在正常物理更新前返回。本课用 `reset_clock_delta_s` 保留实际差值；这不会使模拟时钟倒回，也不能把它当作一次正常OnUpdate。`reset`命令保持暂停，继续运动时再执行 `resume`。

本课 `Reset` 增加 `reset_count`，清零当前轮次的 `epoch_updates`，把新轮次起点设为实际世界时间。插件生命期的 `updates` 保留，`load_count`和`init_count`也不靠手动重写伪装成重建过插件。暂停状态下观察复位后计数，再单步或继续，便能看见下一轮更新。

`Load`负责取得模型和配置，`Init`记录初始化，`Reset`处理同一对象的复位需求，三者不是同一个按钮的不同名字。平台“重载项目”会创建新的服务端、模型与插件实例，默认SDF在这个新实例中建立零角，并重新发生Load与Init；原实例的计数也不接续。第24课涉及的完整仿真时间重置又是另一条路径。本课不补写角度来把model-only复位伪装成重新加载。

`torque_command_issued=true`仅表示这条记录对应实际更新中的一次SetForce调用；Load、Init、Reset记录为false，此时力矩字段的0是“未发出本次命令”的占位，并非力矩测量。

## 单变量一：只改变驱动力矩方向

先恢复基准参数，只将 `drive_torque` 改为 `-0.03`，保留 `drag=0.015`，保存并重新加载实验。预测稳态方向、时间常数和3 s转角，再运行同样的有限实验。

理想模型给出 `ω∞=-2 rad/s`，T仍为1 s。原生转子姿态应朝相反方向累计，阻力仍反抗速度；不要把负角速度代入阻力后继续机械地减一个正数。

## 单变量二：只改变线性阻力

先恢复基准，只把 `drag` 改为 `0.03`，保留正的驱动力矩0.03。重新加载后比较原始数据。

理想稳态角速度变为1 rad/s，时间常数变为0.5 s。注意“时间常数变小”和“最终速度更大”是两件事：这次达到自己稳态比例的过程更快，最后速度却更低。比较相同模拟时刻和相同归一化比例时，应说明你正在比较哪一个指标。

不要同时改驱动力矩、阻力和惯量后仍把结果归因于一个参数。改变惯量时还需保持几何、质量与惯性张量一致，可回看第6课。

## 读懂C++中的关键几行

打开 `model_plugin.cc`，沿下面的顺序定位实际代码：

1. 类声明继承 `ModelPlugin`，注册宏使用 `GZ_REGISTER_MODEL_PLUGIN`。
2. `Load`取得 `_model` 与 `_sdf`，读取参数并核对 `fan_joint`。
3. 事件连接保存为成员，回调使用这个插件对象的成员状态。
4. 每次更新先读实际角速度，计算合力矩，只对目标关节第0轴施力。
5. 实际回调更新计数与采样记录，按配置节奏发布。
6. `Reset`只清本课规定的轮次状态；析构时释放连接等持有对象。

当前力矩路径的核心为：

```cpp
const double omega = joint->GetVelocity(0);
const double force = drive - drag * omega;
joint->SetForce(0, force);
```

第一行读取物理状态，第二行选择本课的力矩规律，第三行把输入交给物理接口。修改第二行就是修改模型受到的作用；后续姿态仍由Gazebo求解，插件没有把解析式中的角速度逐帧写回去。

若只把 `ConnectWorldUpdateBegin` 的返回值留在一个临时局部对象中，离开作用域后连接寿命便不能按预期维持。成员 `ConnectionPtr` 让连接跟随插件；修改时还要避免回调在对象销毁后访问失效的 `this`。

`Load`和更新回调也不适合无界等待输入、下载文件或进行大规模阻塞工作。初始化与构建由平台准备阶段完成，物理回调只处理本步必要计算。官方接口见 [ModelPlugin API](https://osrf-distributions.s3.amazonaws.com/gazebo/api/11.0.0/classgazebo_1_1ModelPlugin.html)和 [Classic ModelPlugin教程](https://classic.gazebosim.org/tutorials?tut=plugins_model&cat=write_plugin)。官方入门例子也包含直接设速度的演示，本课则沿真实力矩路径研究动力学。

## 常见错误与检查顺序

| 现象 | 检查与解释 |
| --- | --- |
| 编译找不到gazebo头文件 | 本机Classic 11开发SDK、pkg-config输出及实际编译命令 |
| 共享库生成了但加载失败 | SDF filename、当前实验GAZEBO_PLUGIN_PATH、SDK版本与所依赖库 |
| 插件加载但转子不动 | 正确模型/关节名、实际暂停状态、力矩和drag、回调连接以及原生pose |

| 改参数后仍见旧效果 | 修改个人文件后重新加载，核对准备记录与运行加载值 |
| 3秒记录的速度与预测不一致 | 原消息模拟跨度、初始状态、是否执行了真实复位及采样阶段 |

单看 `gzclient` 打开、进程还在或者库已加载，都不能替代实际旋转、方向、参数响应和复位行为的验收。

## 独立挑战

先完成一个能用现有原始记录判定的挑战，再决定是否修改物理或代码：

1. 从两组真实曲线估计稳态角速度和时间常数，写清拟合区间、模拟时刻、初态与误差来源。
2. 修改驱动力矩为另一个允许值，事先预测3 s角速度和转角，重载后用原生pose检验。
3. 把线性阻力改为与 `omega × abs(omega)` 成正比的阻力。先补充单位、预计稳态规律和验证办法，再改C++并重新构建；原线性解析式不再直接适用。
4. 设计第二个模型实例，规划独立的关节与记录标识，说明类的成员状态为何应属于每个插件实例。

## 原生辅助工具的退出流程

本课通信工具先核对编译SDK与实际Transport动态库均为Classic 11.15.1，并检查兼容层需要的符号；不匹配时在Transport初始化前报错。主线程随后持有一个未连接的Connection，再初始化通信。这个持有者保证异步回调不会成为共享IOManager的最后一个所有者。通信结束或出现异常时，先执行Transport fini，再在主线程调用公开IOManager.Stop并等待IO线程结束，最后释放订阅、发布器、节点和持有者；回调使用的对象一直保留到这两个停止屏障之后。

这段流程只负责独立辅助进程的资源寿命，插件宿主中不执行全局Transport退出。原有命令参数、测量输出与每次控制只发布一次的规则保持；它不写入预测姿态、力或轨迹。编译缓存包含本课变更的C++源码与SDK/链接参数，保存源码后须重新准备或重载。设置`GAZEBOTEACH_IO_DIAGNOSTICS=1`可在标准错误流保留实际IO join证据，不混入实验数据输出。
