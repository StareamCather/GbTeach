# 五站传感器展台：位置、磁场、高度、距离与模型名单

把试架升高1 m，GPS和高度计都能变化，它们报的却不是同一种“高度”。只把试架转90°，位置没变，磁力计的三列数值为什么会变？再看一个没有RGB图像、却直接知道模型名字的Logical Camera：它究竟知道了什么？

本课把GPS、Magnetometer、Altimeter、Sonar和Logical Camera放在一个离线场景里，逐站操纵真实模型、读取Classic原生传感器消息。五站采用不同的世界状态查询或物理几何计算；课程的消息桥只把原生字段转为便于观察的JSON，不根据教材公式生成“测量值”。公式先用于预测，再与运行结果比较。

## 先弄清五种输出分别在回答什么

| 展台 | 主要问题 | 本课输出与单位 | 需要知道的参考 |
| --- | --- | --- | --- |
| GPS | 我在所配置的地理坐标系哪里？ | 纬度/经度：度；高度：m；东/北/上速度：m/s | WGS84世界球面参考、heading |
| 磁力计Magnetometer | 当前传感器轴上的磁场分量是多少？ | field_tesla三分量，T | 世界磁场向量、传感器姿态 |
| 高度计Altimeter | 比初始化时高了多少？ | vertical_position：m；vertical_velocity：m/s | 加载时固定的vertical_reference |
| 声纳Sonar | 感知体与碰撞几何接触后得到多远的回波近似？ | range、min/max、radius：m | 本课向下的圆锥、接触体、量程 |
| Logical Camera | 哪些模型包围盒与视锥相交？ | 模型名字及相对位姿，位置m、姿态四元数 | 相机位姿、collision AABB与视锥 |

**参考系（reference frame）**决定坐标轴和原点；**参考值（reference value）**也可能只是一个被减去的零点。知道数据单位还不够，要知道它相对什么。高度计的零点不是GPS地理原点；声纳量程也不是高度计的相对高度。

本课的native传感器名称沿用Classic接口。它们的简化模型不等同于现实仪器的全部测量链路：GPS不接收真实卫星信号，Altimeter不计算气压，Sonar不传播真实声波，Logical Camera不识别图像。这些边界能帮助你正确选择实验，而不必先修完导航、测绘、声学和计算机视觉。

## 场景布局和信息流

nav_rig初始位于世界(0,0,1) m，GPS、磁力计、高度计共用零偏置安装位置。sonar_rig初始位于(−4,0,1.5) m，圆锥沿传感器局部−Z向下，min=0、max=3 m、radius=0.2 m。声纳试块高0.6 m，停放时偏在一侧，移到声纳正下方后顶面为z=0.6 m。

Logical Camera固定在(0,−4,1) m，零旋转时看向世界+X，near=0.1 m、far=5 m、水平FOV=60°、宽高比4:3。探针立方体边长0.2 m，初始中心(2,−4,1)，因此相对于相机的位置为(2,0,0) m。这里沿用Classic机体轴，不能把上一课RGB相机的optical +Z前方约定直接套上来。

```text
实际模型位姿、速度及世界配置
  ├─ GPS：局部坐标 → 地理坐标与ENU速度
  ├─ Magnetometer：世界磁场 → 传感器轴分量
  ├─ Altimeter：世界Z − 初始化参考Z
  ├─ Sonar：感知碰撞体 → 接触记录 → range
  └─ Logical Camera：模型collision AABB ∩ 视锥 → 名单/相对pose
       ↓ 原生Gazebo Transport消息
       本课桥逐字段保存 → ROS String中的JSON → 观察与验收
```

桥记录native时间、接收时的世界时间和自己的序号；它没有把所有消息改写成同一采样时刻，也不自动建立TF。课程初始化自动检查依赖并用本机已有SDK构建sensor_bridge.cc私有桥，无须先学C++插件；插件实现将在后续课程集中讲解。

nav_rig与sonar_rig禁用重力、关闭速度衰减，便于做可解释的测量台实验。静态比较时，控制命令将模型一次性放到目标位姿并清速度，随后让仿真继续。这是定位操作，不是飞行控制器；从z=1移到z=2，不表示传感器经历了某条真实爬升轨迹。静止后GPS速度和高度计垂直速度仍应接近0，不能用两次定位差除以命令耗时，冒充原生速度读数。

另一个nav_velocity阶段会一次性给nav_rig真正的world vz=+0.25 m/s，然后让物理引擎自由演化。此时连续样本里实际z应随时间升高，两类传感器的上向速度应接近+0.25 m/s。这个对照区分“修改一次位置”和“初始化速度后实际运动”，没有持续写位置伪造轨迹，也没有实现飞行器闭环控制。

## 第一站：GPS的经纬度不是世界x、y换个名字

**WGS84**用参考椭球描述地球；**ENU**表示East、North、Up，东、北、上。场景地理参考设为纬度0°、经度0°、elevation=100 m；这只是便于检查的教学原点，不表示设备真的搬到了该地。

本课显式设置heading=180°，使Classic 11.15.1这条LOCAL转换路径中的世界+X近似对应东、+Y近似对应北。该版本的历史转换在heading=0时含负XY，不能凭“常见ENU惯例”断言默认+x向东；读取配置并做一个已知方向的位移实验，才知道实际映射。具体源码依据见参考说明。

先预测三种静止状态：

| nav_rig位置/m | GPS预期 | Altimeter预期/m |
| --- | --- | --- |
| (0,0,1) | 纬度0°、经度0°、高度约101 m | 0 |
| (0,0,2) | 纬度/经度几乎不变、高度约102 m | +1 |
| (10,5,1) | 经度约+0.00008983°、纬度约+0.00004522° | 0 |

上表使用默认初始高度1 m。若只把SDF初始高度改成2 m并重载，GPS基线约102 m，而高度计会在加载时以2 m为新reference，基线仍是0。**改初始配置再重载**与**运行中升高1 m**不是同一个实验，必须分开记录。

经纬度是角度，不是米；东西方向相同米数对应多少经度，还与纬度有关。本课小区域近似足以判断变化方向，严格验收使用配置中的WGS84转换，不把示例小数当作适用于全球的常数。水平位移还会给椭球高度带来很小的曲率项，所以“GPS高度永远严格等于100+worldZ”不是通用恒等式。

这里的GPS高度来自所配置WGS84椭球/地理参考，不能直接称作距地距离，也没有添加大地水准面模型将它变成日常所说的海拔。把同一个试架放到高台上，worldZ、地理高度和距平台高度会是三种不同概念。

原生GPS把仿真位置转换为地理坐标，可按配置添加位置/速度噪声；本课基准不加噪声。它没有模拟卫星星座、伪距求解、遮挡失锁、多路径或接收机质量。模型移到建筑物内仍能输出位置，并不能证明现实GPS也能这样工作。不了解GPS定位，可先看[GPS.gov基础介绍](https://www.gps.gov/gps)；想理解ENU和地心坐标的关系，可看[ESA Navipedia坐标变换图解](https://gssc.esa.int/navipedia/index.php/Transformations_between_ECEF_and_ENU_coordinates)。

## 第二站：磁力计的向量为什么随转身变化

世界磁感应强度固定为B_world=(20,0,−40) μT，即(20×10⁻⁶,0,−40×10⁻⁶) T。1 T=10⁶ μT。原生字段叫field_tesla，直接把0.000020读成“几乎没有磁场”会弄错数量级。

若R把传感器坐标转换到世界坐标，那么本课无噪声读数为：

```text
B_sensor = transpose(R) × B_world
yaw=0°   → (20,  0,−40) μT
yaw=+90° → ( 0,−20,−40) μT
两者模长均约44.72 μT
```

向量变的是表达分量，世界磁场没有因为你转身而改变。本课yaw只旋转水平轴，竖直分量不变。若读数分量变化而模长稳定，先检查姿态与坐标约定，不要立即解释成“磁场变强了”。

这个世界磁场是显式配置的向量，GPS地理heading不会自动把它校准成当地真实地磁场。磁北也不必等于地理北，现实还有磁偏角、倾斜、硬铁/软铁干扰等问题。仅凭一个磁分量不能得到任意姿态下可靠的北向；本课不把简化磁力计宣传成万能航向解算器。想了解真实地磁方向与模型，可看[NOAA World Magnetic Model说明](https://www.ncei.noaa.gov/products/world-magnetic-model)。

## 第三站：高度计的“0”是加载时的高度

本场景加载时nav_rig传感器worldZ=1 m，因此vertical_reference=1 m。原生Altimeter直接报告：

```text
vertical_position = 当前sensor worldZ − vertical_reference
vertical_velocity = 当前sensor位置的world方向竖直速度
```

把试架放到z=2，vertical_position约+1；放回z=1，约0。这个参考值不会因为每次定位自动重新设为当前高度。只绕竖直轴旋转也不会改变它；它没有把worldZ投影到朝向已经旋转的机体Z轴上。

它既不测“离最近地面多远”，也不通过气压、温度或大气模型估算高度。高度计与GPS对同一次升高都变化1 m，仍然不能据此说两者具有相同零点、误差或测量原理。请同时读出vertical_reference，避免只看一列数字就误判负值或初始0。

## 第四站：声纳的感知体不是一条理想激光线

先让声纳正下方只有地面。声纳在z=1.5 m，读数应接近1.5 m；把0.6 m高的试块移到正下方，读数应接近0.9 m。试块的collision参与测距，不能只画一个visual、就期待物理接触体必然检测到它。

Classic本实现建立圆锥或球形碰撞体，再从物理引擎提供的接触位置/穿透深度近似计算range。本课选min=0，避免把这版实现直接等同于带近裁剪的单射线接口；radius描述感知体的横向范围，不是激光束数量，也不是声速。

不了解现实声纳如何从声波往返时间得到距离，可看[NOAA声纳基础介绍](https://oceanexplorer.noaa.gov/technology/sonar/)。它帮助区分真实声学仪器与本课简化接口，不是本课程额外启用的声传播仿真。

它未模拟声波传播时间、镜面/漫反射、吸声材质、频率或多次回波。接触点数量有限，不能保证任意复杂场景都得到几何上的全局最近点；接触点偏轴及穿透深度修正，也可能使读数与理想竖直间距有小差。保留原始测量，不把它改写成恰好1.500 m。透明visual也不意味着对这个碰撞体透明。本课用正下方平面/试块作可解释基准，而不把结果泛化成完整超声传播。

再把声纳放到z=4 m，此时地面超过max=3 m，最终range回到有限的3 m。**range=max既可能表示没有获得更近接触，也不能证明恰在3 m处存在目标。**它不是本课激光扫描里的+inf。离开障碍后实现还会短时保留旧range，验收留出足够仿真时间；暂停时等墙钟不能冲掉这段迟滞。contact字段可能仍留着上一接触，不能只凭它存在就判定当前命中。

contact还是物理引擎的原始接触位置经局部换轴后的值，没有按穿透深度修正成声波反射点；不要期待它一定等于(0,0,−range)。range的计算另用了原始接触深度，而Sonar消息没有提供这个深度字段，所以仅凭contact向量也无法严格重算range。

## 第五站：Logical Camera为什么不用“看图识物”

初始探针在相机前方2 m，名单里应包含它，relative pose约(2,0,0)。场景还在相机与探针之间放置带collision的遮挡件，观察被它挡在后面的探针仍能出现在名单中，直接检查“不剔除遮挡”的边界。把探针移到相机后方(−2,−4,1)，它应退出名单；再移回去重新出现。验收关心这个探针的进出和相对位姿，不要求名单中只能有它：例如地面大包围盒也可能与视锥相交。

**AABB（axis-aligned bounding box）**是与世界坐标轴平行、包住模型collision几何的盒子；**frustum（视锥）**是近/远裁剪面和FOV围成的可感知区域。此实现测试两者是否相交，不要求模型原点必须在内，也不逐像素分辨轮廓。大包围盒伸入视锥，即使模型原点在外，仍可能被上报。

名单里的name来自仿真模型的scoped name，pose来自仿真场景状态。它不输出神经网络类别、置信度或图像边界框，也不剔除被其他模型遮住的对象。因此“名单里有这个模型”与“真实RGB相机能看见并识别它”不是等价判断。所属model本身会被排除，嵌套model另有递归检查。详见[Classic Logical Camera官方教程](https://classic.gazebosim.org/tutorials?tut=logical_camera_sensor)。

消息顶层pose是相机的世界位姿，model条目中的pose是模型相对相机的位姿。相机不转时位置可以直接相减；一旦旋转，就要先变换坐标轴，不能对所有情况只做世界坐标相减。

## 时间：有数据，不表示五路同一时刻采样

GPS、磁力计、高度计、SonarStamped原生消息有time；本课把它保存为source_stamp_ns，表示原生仿真时间，不是UTC或真实GPS卫星时间。LogicalCameraImage原生定义没有time字段，它的source_stamp_ns明确为null。

桥另记receipt_world_time_ns和bridge_sequence，分别表示回调接收时读到的世界时间和该站桥实例的序号，各站独立递增。它们可以证明观察到了新消息，但接收时间不能补成Logical Camera原本不存在的测量时间。桥序号也不是传感器硬件帧号或五路全局排序。即使五站都设为10 Hz，也不能凭相同频率或相邻到达顺序声称严格同步；接收频率和原生采样频率须分别看待。

这些纳秒值和序号在JSON中存成十进制字符串，避免通用JSON数字表示损失整数精度；Logical的source_stamp_ns仍为真正的null，不是字符串“null”或数字0。观察工具会负责解析，手动写程序时要按字段契约转为整数。

仿真秒与墙钟秒也要分清：10 Hz是每仿真秒约10次。计算机运行慢时，每真实秒收到的条数可能更少；暂停后原生仿真时间停止，长时间没有新测量本来就是预期行为。

## 开始实验与单变量练习

使用平台打开的本课操作终端，先保持运行，再执行：

```sh
python3 lab.py observe --seconds 3
python3 verify.py
```

observe只读当前数据，按墙钟限时；verify会依次定位试架/探针并采集完整窗口，所以它会改变实验状态。请先保存你关心的当前观察。验收完成或发生错误时，应恢复进入验收时本课可移动模型的位姿、速度和暂停状态；已流逝的仿真时间不会倒回，原生迟滞/历史缓存也不等于被重置。

`lab.py probe --seconds 3 --report build/probe.json`可保存只读诊断。probe/observe证明收到原生输出，不代替九阶段行为验收。完整验收每阶段都检查五路，每路至少12条新事件、跨度至少1仿真秒，目标10 Hz、窗口要求8至12 Hz；四路按不同native时间计数，Logical按独立桥序号和receipt时间计数，不宣称原生同步。

一般阶段先留0.3仿真秒传播时间，声纳超量程阶段留0.8秒，等待首条符合新状态的数据后连续检查后续窗口。平台为整次验收配置180秒墙钟超时。报告默认放在会话目录stand-verify-唯一编号.json，终端打印trace_path；也可执行`python3 verify.py --report build/my-stand-check.json`。报告保留原始wire_json、native字段、时间、各帧判据、实际状态与恢复结果。

下表给出默认初始高度1 m的控制命令；已改成2 m时，导航台基线z用2，上移1 m则用3。move只改变指定站，不自动恢复其他站；它会将roll/pitch和未指定的速度清零，默认yaw=0°、vz=0，并保持进入时的暂停状态。如果实验原本暂停，执行后要点“继续”才有新测量与运动。

| 操作 | 命令 |
| --- | --- |
| 导航台上移1 m | python3 lab.py move --station nav --x 0 --y 0 --z 2 |
| 向东10 m、向北5 m | python3 lab.py move --station nav --x 10 --y 5 --z 1 |
| 原位偏航+90° | python3 lab.py move --station nav --x 0 --y 0 --z 1 --yaw 90 |
| 一次初始化真实上行速度 | python3 lab.py move --station nav --x 0 --y 0 --z 1 --vz 0.25 |
| 导航台停止并回基线 | python3 lab.py move --station nav --x 0 --y 0 --z 1 |
| 试块移到声纳正下方 | python3 lab.py move --station obstacle --x -4 --y 0 --z 0.3 |
| 试块移回停放处 | python3 lab.py move --station obstacle --x -4 --y 2 --z 0.3 |
| 声纳升高至超量程 | python3 lab.py move --station sonar --x -4 --y 0 --z 4 |
| 声纳回到基线高度 | python3 lab.py move --station sonar --x -4 --y 0 --z 1.5 |
| Logical探针移到相机后方 | python3 lab.py move --station target --x -2 --y -4 --z 1 |
| Logical探针回到前方 | python3 lab.py move --station target --x 2 --y -4 --z 1 |

真实速度实验只需初始化一次，观察后用“停止并回基线”结束；重复执行上行命令会重置起点，打断要观察的自由运动。

按下列顺序预测、操作、记录，每次只改变一个因素：

1. **高度实验**：只改nav_rig的z。并列记GPS高度、Altimeter位置及reference、两路速度，解释“同增量、不同零点”。
2. **水平实验**：保持z与yaw，改x、y。检查经/纬变化方向；Altimeter应保持0附近。不要将度数差直接写成米。
3. **转向实验**：保持位置，只改yaw。记录B三分量及模长，检查90°换轴的符号；GPS静止位置与高度计不应因此产生1 m跳变。另开一次只将world magnetic_field放大2倍的重载实验，检查各分量和模长是否同倍变化。
4. **障碍实验**：保持声纳高度，只把试块移到正下方。对照可视顶面和真实range，再移走、观察迟滞；不要在过渡一帧下结论。
5. **量程实验**：保持max=3 m，升高声纳至4 m，等足够仿真时间后解释有限max输出。
6. **视锥实验**：只移动Logical探针，比较前方、后方和恢复时的名单与相对位姿。区别“名单为空”和“没有收到新消息”。
7. **速度实验**：一次初始化向上0.25 m/s，随后只读状态和原生数据。检查GPS velocity_up与Altimeter vertical_velocity，以及实际z随仿真时间的增长；不要重复执行定位命令打断自由运动。

本课支持保存的单变量为world磁场倍数1/2、nav初始高度1/2 m；两者均直接修改个人world.sdf，保存后需要重载。其余传感器配置和基准几何由预检固定，避免改了几何却仍沿用原验收假设。运行时定位不等于把新位置写回模板。练习副本会保留个人修改，参考答案单独查看；不要在平台课程源目录中用临时试验覆盖模板。

参数入口分别为`python3 lab.py config --field-scale 2`与`python3 lab.py config --initial-height 2`。每次只做一项、重载后观察；用同一参数改回1，再重载恢复默认后，才做另一项。

## 出错时按信息流定位

| 现象 | 先核对什么 |
| --- | --- |
| 五路都不更新 | 实验是否暂停、ROS/Gazebo Master是否属于本课、桥是否已就绪 |
| GPS东西方向与预期相反 | world spherical_coordinates的heading与当前Classic版本，不先改原生消息符号 |
| GPS约101，高度计却0 | 查看elevation、worldZ和vertical_reference，三个零点并不相同 |
| 磁场数值约0.00002 | 单位是T；转成μT再比较，检查姿态和世界B向量 |
| 声纳不随外观模型改变 | 检查collision而不仅是visual、目标是否进入圆锥、是否留够仿真时间 |
| 试块移走仍短时保留旧值 | 原生接触迟滞；检查后续新消息，不能只看缓存contact字段 |
| Logical上报被遮住的模型 | AABB/视锥接口本来不做遮挡剔除，不是RGB识别失败 |
| Logical没有source时间 | 原生proto没有该字段；receipt时间是另一个概念 |
| 看见模型不等于收到传感器输出 | Gazebo GUI、原生传感器、桥、ROS观察各有一层，分别核查日志和消息 |

## 独立挑战

制作一张“我在测什么”的五行记录表，逐项填写单位、参考原点/轴、原生时间是否存在、无目标时的含义、一个现实物理过程没有被本模型模拟的例子。再设计一个反例：让两个叫作“高度”的读数不相等，或让Logical名单包含RGB外观被挡住的模型。先写预测与原因，再用实际消息检查，保留原始数据；不要通过改写消息来使结论成立。

完成后，你应能根据测量量、参考系与仿真假设选择传感器，并说明一条数据究竟证明了什么。五路主题都能输出，只是实验入口；解释并验证它们随真实场景改变的方式，才完成这一课。
