# 附加专项51 · FAST-LIO2 的直接匹配与增量地图

把同一段激光与IMU记录交给同一个FAST-LIO2估计器，分别打开和关闭特征提取。点数、匹配误差和计算时间会怎样变？这一课用同源对照解释直接点到地图匹配、迭代误差状态更新和ikd-Tree。建议先完成第50课的点时间、IMU传播和去畸变。

## 两种输入选择，一套地图残差

FAST-LIO2的直接模式将通过基本筛选的原始回波交给去畸变与体素降采样，再逐点匹配局部地图。直接的意思是省去显式边面特征分类。输入审计检查有限值与采样时间。预处理筛除盲区回波，后端从保留点中寻找能稳定拟合平面的地图邻域。近邻搜索、平面验证和残差筛选仍会改变最终进入更新的点数。[FAST-LIO2论文](https://arxiv.org/abs/2107.06829) · [固定源码](https://github.com/hku-mars/FAST_LIO/tree/7cc4175de6f8ba2edf34bab02a42195b141027e9)

启用`feature_extract_enable`后，预处理按垂直束编号整理点，利用同束相邻点几何分类。所选源码将面特征集合送给后续估计。两种模式都使用同一FAST-LIO2后端、地图组织和点到平面残差。本课的特征组用来隔离同一实现的前端开关。第50课固定历史树的第一代系统需要用独立实验比较。[Velodyne预处理实现](https://github.com/hku-mars/FAST_LIO/blob/7cc4175de6f8ba2edf34bab02a42195b141027e9/src/preprocess.cpp#L284)

一个角落附近可能同时存在两面墙。直接模式保留更多可参与匹配的点，但若一个局部邻域横跨两面墙，它可能拟合不出可靠的单个平面。特征模式提前挑出一些平滑面段，可减少工作量，也可能删掉提供稀缺法向的点。最终效果取决于扫描、场景、筛选参数和地图几何。

## 相同观测怎样进入两次运行

本课复用第50课的分时Gazebo传感器装配。0.5ms物理步内做一列ODE射线查询，同一列16束共用实际采样时刻，200列形成一圈。IMU来自原生传感器。独立真值用于评估。采集的同一段雷达与IMU分别回放到新启动的估计器，固定传感器数据、外参、回放节奏和评估规则，只切换特征提取模式。

本课使用Velodyne式ROS `sensor_msgs/PointCloud2`。点字段包含`x/y/z/intensity`、`ring`和`time`。其中`ring`是实际垂直束编号，`time`是相对扫描首列的秒数。消息头时间与点偏移相加才得到点采样时间。`timestamp_unit`必须与编码相符，固定源码随后将偏移统一换算成毫秒供去畸变使用。最后一点的有效时间尤其关键。该版本在点云尾部时间不大于零时会进入按方位角估时的路径。课程构建对按束分组的面点做稳定时间排序，并用末个保留点的偏移确定后端参考时刻。不同模式的末个保留点可以来自不同射线。[点类型与时间单位](https://github.com/hku-mars/FAST_LIO/blob/7cc4175de6f8ba2edf34bab02a42195b141027e9/src/preprocess.h#L40) · [Velodyne时间分支](https://github.com/hku-mars/FAST_LIO/blob/7cc4175de6f8ba2edf34bab02a42195b141027e9/src/preprocess.cpp#L284)

## IKFoM更新沿哪条路径运行

先用IMU数据传播姿态、位置、速度与误差协方差，再根据点采样时刻补偿到统一的扫描参考系。用当前迭代的状态将每个候选点变换到世界坐标。记T_WI为IMU在世界系的变换，T_IL为LiDAR到IMU的固定外参，则世界点是T_WI T_IL p_L。外参平移表达在IMU系。转动时要保留该力臂，才会得到正确的LiDAR原点轨迹。

用局部地图中的近邻拟合平面。设n为单位法向、q为面上一点、p为估计的世界点，则r=nᵀ(p−q)是有符号正交距离。在当前状态处线性化，平移部分的雅可比为nᵀ，旋转部分反映转动造成的点位移。IKFoM把旋转保留在SO(3)，用局部小向量表达旋转误差，更新时再映射回旋转群。位置和速度等欧氏状态可直接加误差。源码还以球面流形表示重力方向，并包含两传感器之间的外参状态。两次运行关闭在线外参估计，使用同轴旋转以及实际安装的(0.04165, 0.02326, −0.0284)m平移。[状态流形定义](https://github.com/hku-mars/FAST_LIO/blob/7cc4175de6f8ba2edf34bab02a42195b141027e9/include/use-ikfom.hpp#L12)

`h_share_model`构造有效平面残差和雅可比。`update_iterated_dyn_share_modified`从同一传播先验出发，随状态变化重新线性化，收敛或到迭代上限后提交当前帧估计。输出点的位姿与地图写入要使用更新后的状态。日志里的迭代次数指同一批观测的求解过程，不能当成新收集的扫描数。[匹配与测量雅可比](https://github.com/hku-mars/FAST_LIO/blob/7cc4175de6f8ba2edf34bab02a42195b141027e9/src/laserMapping.cpp#L638) · [滤波调用与地图更新](https://github.com/hku-mars/FAST_LIO/blob/7cc4175de6f8ba2edf34bab02a42195b141027e9/src/laserMapping.cpp#L955)

## ikd-Tree怎样维护移动的局部地图

k-d树按坐标轴递归划分空间，近邻搜索时可根据空间边界跳过无关子树。建图中机器人不断移动，既要插入新点，也要把离开局部区域的旧点移出。ikd-Tree用增量操作更新树，并监测局部平衡。

| 操作 | 在FAST-LIO2中的用途 |
|---|---|
| 近邻查询 | 从当前局部地图取邻域点供平面拟合 |
| 插入与降采样 | 更新状态后将新点投到世界系，对部分候选执行按体素的树内降采样 |
| 盒删除 | 移动局部地图边界后，按空间盒标记不再需要的点 |
| 子树重建 | 当子树过度失衡或删除点比例偏大时重建，维持后续近邻查询效率 |

盒删除可先设置延迟删除标记，由查询逻辑排除已删除点。重建时再清理相应节点。树的增量插入与扫描降采样位于不同环节。前者控制地图保留哪些点，后者控制当前帧有多少候选送入匹配。地图点数和处理时间可以观察整体行为。要确认某一帧确实发生子树重建，需要重建事件本身的记录。[FAST-LIO2建图章节](https://arxiv.org/html/2107.06829) · [ikd-Tree论文](https://arxiv.org/abs/2102.10808) · [固定树实现](https://github.com/hku-mars/ikd-Tree/tree/e2e3f4e9d3b95a9e66b1ba83dc98d4a05ed8a3c4)

## 用场景判断可观测方向

若墙面法向为(1,0,0)，沿X偏移0.2m会在点到面残差里出现0.2m。沿墙面Y方向移动同样距离，理想平面的这一项保持原值。成千上万个共面的点也可能主要约束同一个方向。增加法向不同的墙面、横梁或立柱，可给其他方向提供几何约束。旋转的可观测性还与点到旋转中心的力臂分布有关。沿长走廊退化时，常见表现是某些方向的不确定性或漂移增大，即使多数平面残差很小。

## 在课程终端运行对照

启动课程时，`prepare.py`准备原生扫描插件，`build_fast_lio2.py --download`构建独立Noetic工作区。FAST-LIO2、ikd-Tree和Livox消息定义均按固定提交与归档SHA256复取，缓存可供重复运行。已有固定归档可用`python3 build_fast_lio2.py --archives /实际归档目录`离线准备。构建信息写入`build/fast-lio2.json`。开始实验后保持Gazebo运行，在课程终端执行以下命令。

```bash
python3 adapter.py run
```

适配器采集一次，生成一份传感器bag，其话题为`/gt_lio/replay_points`和`/gt_lio/replay_imu`。两次均按0.8倍墙钟节奏回放，各自从新启动的估计器开始。报告核对两次读取同一bag的SHA256。两组都设置`point_filter_num=1`，当前扫描与地图的体素尺寸均为0.2m。独立真值保留给离线评估。位置按对应时刻插值，姿态用四元数球面插值，每组分别用首个匹配位姿做一次SE(3)对齐。两组的比例固定为1。

`PointCloud2`中的位置、强度和时间均为FLOAT32，`ring`为UINT16。`timestamp_unit=0`选择秒。各点采样偏移和bag记录时刻各自保留，回放倍率改变消息到达节奏。点时间、估计输出时刻与离线真值匹配仍基于原始仿真时钟。

## 两处可独立复查的数值练习

在个人`learner.py`填写`voxel_key(point, leaf_m)`和`translation_jacobian(unit_normal_world)`。体素索引用每轴坐标除以体素边长后向下取整。比如边长0.2m时，−0.01m位于索引−1，直接转整数会错误地把它放到索引0。第二处从r=nᵀ(Rp+t−q)求对世界平移t的导数。保持法向和对应面不变，依次对三个平移分量求偏导。

```bash
python3 student_check.py
```

局部检查用于核对公式。原生采集、两组估计和对照证据由`adapter.py run`产生。

## 读两组结果

先预测哪组会保留更多候选，哪组的耗时差异可能来自特征处理或后端近邻。检查两次运行的源数据标识和有效输出覆盖率，再比较候选点、参与残差的点、地图和轨迹。如果两模式保留的特征末点不同，同一原始扫描对应的状态时间也可能略有不同。逐点配对前先核对估计时间戳，按各自处理时间与真值对齐。

结果写入`results/run-<uuid>/`，最新报告为`build/verification.json`。运行目录保存同源`sensors.bag`、`native.jsonl`及`paired-timing.json`。子目录`direct/`与`feature/`各含`trajectory-comparison.json`、`native-timing.json`、估计器与回放日志，以及隔离话题的`odometry`、`map`、`registered`摘要。每组`laser-map.pcd`来自实际ikd-Tree局部地图快照，报告给出坐标系、时间戳、点数和SHA256。验收分别检查每组估计覆盖、地图与运动，并对齐后量化位置及姿态误差。

把扫描周期、回放墙钟节奏与单帧处理时间分开读。原生PRE计时覆盖点云回调中解码、筛选及特征模式所需的排序。SCAN测量主循环t0到t5，覆盖IMU传播与去畸变、局部地图处理、降采样、迭代更新和地图插入，也含位于此区间的里程计发布调用。它在后续路径、点云发布和地图快照导出前停止。两段时长相加仍只代表选定的处理区间，实际消息从采集到接收还经过队列、传输和回放调度。

`paired-timing.json`仅对两模式都完成处理的扫描按原始扫描首时刻精确配对。每行同时列出PRE、SCAN、两段之和、预处理点数、降采样点数、有效对应数及局部地图点数。报告给出中位数与95分位。高分位有助于看到慢帧，配对样本量反映实际交集。实验结果对应本设备、本配置和本场景。

单变量挑战可在同一记录和一个模式中调整扫描体素尺寸，再观察参与匹配的点数、各方向漂移和耗时。另一种挑战是保持点数近似相同，比较只有平行墙与存在横向结构的轨迹段。将结果与法向分布和实际运动结合起来解释。

地图点数是读数时刻的活动点统计。ikd-Tree 若正在异步重建，原生接口可能返回 `-1` 表示计数暂不可用。报告把该项记为缺测，列出可用样本数；这时扫描及其处理时间仍有效，实际地图另查 PCD 和地图话题。
