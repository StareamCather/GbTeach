# 参考：单关节PID的力矩平衡与原生语义

本页只读，不覆盖个人练习。以下标称参数及公式结果是理论预测，不作为真实Gazebo测量；实际数据应从关节、PID状态和仿真时钟记录独立计算。

## 转子与恒转矩预测

M=1 kg、R=0.25 m，均匀转子绕中心Z轴J=MR²/2=0.03125 kg·m²，黏性阻尼b=0.1 N·m·s/rad。正向控制转矩u、反向负载幅值τ_L满足：

```text
J ω˙ + bω = u − τ_L
```

恒定u=0.4、τ_L=0、初始ω=0时：

```text
τ_mech = J/b = 0.3125 s
ω(t) = (u/b)(1−exp(−bt/J)) = 4(1−exp(−3.2t)) rad/s
q(t)−q(0) = (u/b)[t−(J/b)(1−exp(−bt/J))]
```

最终速度由转矩平衡决定，惯量主要影响到达过程。连续解不是逐步ODE实测值；与离散仿真比较时应使用真实采样时间，不用墙钟耗时或GUI转动观感代替。

## 原生误差、积分项与输出

本课按Classic 11.15.1实际实现使用e=y−r，因此u=−Kp e−Ki∫e−Kd de/dt。若改为误差r−y，则公式符号也须一起变换。速度误差的单位为rad/s，位置误差为rad；两种环的增益单位不同。

common::PID先累计误差，计算并夹紧I项，再算差分D和总命令，最后限制输出。Imax/min夹的是Ki乘积分后的输出项，其单位N·m；GetErrors中的累计误差并不是这个已经乘增益的项。即使Ki或Kd为0，原生内部误差仍可更新；判断实际I/D贡献须乘对应增益，不能仅凭非零内部量说P模式已启用I/D。命令限幅不自动冻结积分，也没有在该路径中按输出饱和差作回算。[原生PID实现](https://github.com/gazebosim/gazebo-classic/blob/gazebo11_11.15.1/gazebo/common/PID.cc)是版本依据。

例如速度Ki=0.8、I项范围±0.8 N·m，对应累计误差范围±1 rad。要在误差接近0时提供+0.6 N·m，按本符号需I项约−0.6 N·m、累计误差约−0.75 rad；最终输出对该项取负号。不要把负的原生误差或I项直接当作方向错误。

JointCmd.reset只删除对应关节的force、position、velocity目标记录；完整JointController::Reset还会清除两类PID内部误差。位置、速度和直接转矩目标不是自动互斥的，本课每相位清理旧目标并只保留相应控制模式。[原生JointController](https://github.com/gazebosim/gazebo-classic/blob/gazebo11_11.15.1/gazebo/physics/JointController.cc)可核对该流程。

## 速度P为什么保留偏差

速度P的u=Kp(ω_ref−ω)。未饱和、处于恒速时：

```text
ω_ss = (Kp ω_ref − τ_L)/(Kp+b)
ω_ref−ω_ss = (bω_ref+τ_L)/(Kp+b)
```

标称ω_ref=4、Kp=0.4：无额外负载时ω_ss=3.2 rad/s，反向负载0.2 N·m时ω_ss=2.8 rad/s。误差需保持非零，P项才能持续提供克服阻尼和负载的转矩；这不必然表示求解器未收敛。

单变量挑战只把speed_p_kp改为0.8，PI使用独立增益、保持原值：无额外负载ω_ss≈3.555556，负载0.2时≈3.333333 rad/s，负载后的偏差从1.2减至约0.666667 rad/s。未饱和一阶模型的时间常数J/(Kp+b)由0.0625减至约0.034722 s；更一般的暂态、噪声和离散效果仍须实际检查，不能据此承诺任何环节加Kp都更好。

这个时间常数不适用于整段挑战初始响应：ω=0时，Kp=0.8请求0.8×4=3.2 N·m，先被±2 N·m上限截断；当P请求回到上限内后，才适用相应的未饱和线性模型。稳态平衡计算与初始饱和暂态是两个不同判断。

## PI能补负载，但不能越过力矩上限

足够输出与积分范围内，PI可在ω=ω_ref时依靠保留的积分项提供稳态转矩。标称负载下需要b×4+0.2=0.6 N·m，正常cmd上限2和I项上限0.8均足够。

忽略饱和、连续近似的速度PI特征多项式为：

```text
J s² + (b+Kp)s + Ki = 0
标称：0.03125 s²+0.5 s+0.8 = 0
```

Kp与Ki共同决定暂态；更大的Kp不意味着积分消除偏差必然更快。若命令上限降为0.35 N·m、反向负载0.2 N·m，最大可维持速度预测为(0.35−0.2)/0.1=1.5 rad/s。即使积分达到自身限值，执行器仍没有0.6 N·m可用，不可能维持4 rad/s。

I项夹紧可限制积累幅度，但最终输出饱和并不反馈给原生积分更新。不要把此机制描述成完整的输出感知抗积分饱和；若研究解除饱和后的恢复，需要另设目标/负载变化并保留积分状态进行实际观测。

## 位置P/PD、阻尼与微分突跳

固定目标、无负载时，位置PD的连续近似为：

```text
J q¨ + (b+Kd)q˙ + Kp q = Kp q_ref
ω_n = sqrt(Kp/J)
ζ = (b+Kd)/(2sqrt(J Kp))
```

Kp=2时ω_n=8 rad/s；位置P的Kd=0，ζ=0.2；PD的Kd=0.35，ζ=0.9。该关系解释固定参考期间的阻尼趋势，不把未饱和、无突跳的理想二阶阶跃曲线直接当成本课原生响应。

原生D对误差差分而非只对测量值微分。若Reset后e_prev=0、q初始0、q_ref阶跃0.8、首有效dt=0.001 s，则：

```text
e_first = −0.8 rad
D对控制输出贡献 = −0.35×(−0.8−0)/0.001 = +280 N·m
P对输出贡献 = +1.6 N·m
未限幅总输出 = 281.6 N·m → 按±2 N·m命令范围截断
```

这是给定初态/步长的首步代数预测，实际第一有效更新时刻仍需从记录核对。目标平滑或采用不同微分结构可用于另一个设计，本课保留原生行为。无恒定负载且最后静止时，阻尼转矩为0，位置P允许零稳态误差；不能照搬速度P必须提供持续阻尼转矩的结论。

## 六相位与独立预测

固定转子为均匀圆柱，厚度h_disc=0.06 m，Ixx=Iyy=M(3R²+h_disc²)/12=0.015925 kg·m²，Izz=0.03125 kg·m²。关节的SDK effort上限3 N·m高于本课正常PID命令上限2 N·m，避免把另一个更小上限混进对照；负载通过独立反向力矩施加。

world里的指针、底座与标记只有visual，不增加碰撞或转子质量/惯量。该模型以理想关节转矩为输入，没有电枢电压、电流或反电动势状态；不能把它的结果直接称为已验证的物理直流驱动器。[UMich直流电机模型](https://ctms.engin.umich.edu/CTMS/?example=MotorSpeed&section=SystemModeling)可作为愿深入者的电机电气背景，本题无需另学电路才能完成。

## 修改、重载与测量信息流

只编辑个人parameters.json；主编辑按钮默认打开world.sdf，应使用课程参数编辑命令或 `gedit --new-window parameters.json`。保存→重载项目→inspect核对实际配置与源指纹→运行相位/六相位验收；world、工具源码和固定模型保持原样，参考页不覆盖个人文件。

native Model每1 ms更新JointController一次。工具只在阶段边界建立真实初态，运动中设置原生模式、记录实际状态和施加独立负载，不额外再调用一次Update，也不持续改写位姿或速度代替力矩闭环。完整初始化清旧目标和历史，然后分别配置转矩、位置PID或速度PID，防止不同target map残留。

固定ODE课包的初始化还需区分几何朝向与累计角：同一朝向可以对应相差整圈的q。工具恢复加载时捕获的初始绝对位姿并清零速度，验证几何后，经公开ODELink::GetODEId取得body，核验唯一连接world且锚点/轴向匹配的hinge，再调用设备SDK公开OpenDE C API的dJointSetHingeCumulativeAngle(...,0)一次同步计数参考。随后严格读回q、ω和实际位姿，再建立新PID及目标；保持原有关节，后续全部由原生力矩控制。学员无需掌握这些API即可操作参数实验。

原始q可包含整圈计数，四元数或指针朝向本身不能恢复完整圈数；工具另保留逐步展开角进行轨迹一致性核对，不把几何朝向相同直接当成累计角零位。

记录把每步前关节q/ω、原生PID误差与GetCmd、负载、SDK力矩、物理推进后的q/ω和dt配对。PID误差对应步前量；不能把post-state与pre-command交错回算。GetForce是SDK施加输入的记录，不是支座反作用力或力矩传感器；黏性阻尼另进入运动方程。

负载按相位步前时间≥2 s施加，因此首个带负载的第2001步对应步后2.001 s，不把步后2.000 s的无负载行误判成漏施。单个Begin/End回调可能带同一个世界时钟戳，不能只将两戳相减就认定物理步长为0；工具按物理步序与实际dt标记配对的相位前/后时刻，世界时钟另用于序列推进核对。端到端耗时不能替代仿真时间或物理步长。

原始记录与预测分开，首个有效PID更新、负载开关和饱和不能用稀疏截图证明。

愿深入原生通信时需按版本核对：Classic 11此JointController接收Ignition Transport的ignition.msgs.JointCmd，课程工具负责类型与目标配置；旧例中的gazebo.msgs.JointCmd不能直接当作本接口类型。学生完成参数实验不需要掌握这些底层调用，也不需要ROS。

运行结束清除原生控制目标，读回确认原pause；不恢复已经发生的轨迹与世界时间，原来运行时仍会继续自然演化。验收必须取得当前配置全部六相位的真实数据，即使默认演示已结束也不把它当作本次结果。
