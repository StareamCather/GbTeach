# 可复用的障碍物模型包

## 一个定义，四个独立箱子
把箱子的几何、碰撞和惯性复制四次，可以得到四个物体，但修改设计也要维护四份。本课把设计放进离线模型包 `teach_crate`，用四个 include 布置 `crate_left`、`crate_right`、`crate_back`、`crate_front`。它们共享文件来源，运行时却是独立实体。

先预测：移动右箱会不会带动其他箱子？修改模型文件后，正在运行的箱子会不会立即变形？本课不用 ROS、编译工具或在线模型库。

## 分清三层对象和目录
1. **课程原始模板**：安装目录中的课包，用来建立练习；不要在这里修改。
2. **个人副本中的共享模型定义**：工作目录下的 `models/teach_crate`，供本课多次 include，是你可以编辑的设计文件。
3. **运行实例**：服务器解析文件后创建的模型，各有名称、位姿和物理状态。

点击“编辑练习文件”先打开个人 world.sdf。要编辑模型包，可从同一编辑器的“打开”功能进入旁边的 models/teach_crate，或使用“项目与命令”的文件入口。先核对目录来自当前个人练习。

```text
个人练习目录/
  world.sdf
  models/
    teach_crate/
      model.config
      model.sdf
```

`model.config` 的 name 是可读名称，version 是模型自身的发布版本；`<sdf version="1.6">model.sdf</sdf>` 声明入口文件及其 SDF 格式。`model.sdf` 定义 link、visual、collision、质量和惯性。本课采用 SDF 1.6；素材版本1.0、SDF格式1.6、Gazebo版本11是三件事。本地模型集合不需要在线仓库用的 database.config。

## 从 URI 到实例
`model://teach_crate` 是模型资源 URI，不是网页地址。解析流程为：

**include URI → 本地模型目录 → model.config → model.sdf → 实例名称和初始pose → 各自的运行状态。**

- `GAZEBO_MODEL_PATH` 查找模型包，应包含上图的 models，而不是 models/teach_crate 或 model.sdf 文件本身。
- `GAZEBO_RESOURCE_PATH` 查找世界文件、媒体等其他资源，不能代替本课模型入口链。
- 包内若有网格、纹理和材质脚本，还需携带它们并检查相应引用；仅复制 model.sdf 未必足够。

Linux 路径列表用冒号分隔。应用先保留系统 Gazebo 的资源，再添加本课路径；终端已继承这些设置，不需要永久改写用户配置。同名模型可能发生搜索冲突，排错时要核对实际路径。

## include 覆盖什么
本课使用以下 SDF 1.6 写法：

```xml
<include>
  <uri>model://teach_crate</uri>
  <name>crate_left</name>
  <pose>-1.5 0 1.25 0 0 0</pose>
</include>
```

name 指定运行实例名，pose 给出 world 中的初始模型位姿。模型文件的根 pose 保持零，内部 link 和几何局部定义保持原样。include 不是任意 XML 参数替换器；改变尺寸要编辑模型定义，不在 include 中另造 size 等字段。各实例名称必须唯一；查询时用实例名，不用 model.config 的展示名称。

## 引导实验：运行位置与设计分开改变
1. 开始实验并查询四箱。边长0.5 m，include 的初始中心高度为1.25 m；落地后中心约为0.25 m。窗口出现时可能已经落地，这不是 include 位姿被忽略。
2. 在步骤1的基准0.5 m箱子全部稳定落地后，先暂停，再执行“只移动右箱（基准0.5m已落地，先暂停）”。该命令只将右箱 x 从1.5改为2，其余分量按基准完整位姿填写，包括 z=0.25、yaw=0.35；预测并查询其他箱子不动。此步在修改尺寸前完成。挑战尺寸或自定义布局时不要照搬这组数，应先恢复并重载基准，或按自己的完整位姿只改 x。打开 world.sdf，确认命令没有自动改写 include；重载项目后应回到文件中的初始布局并再次落地。
3. 在个人模型文件中保持质量1 kg，只把高度从0.5改为0.6 m；同步修改 collision 与 visual 的 size，并按均匀长方体公式更新惯性。这些同步配置用于保持同一设计一致。先预测所有实例稳定高度的变化，再保存。
4. 点击“结束实验”再“开始实验”，让新服务器重新解析模型包；“重载项目”同样结束并重建会话。四箱应使用新高度，稳定中心约为0.3 m。只重开 GUI 或重置模型状态不会重读设计。
5. 恢复基准，结束实验后将个人包目录临时改为 teach_crate_missing，URI不变；再次开始并查看资源解析日志。结束失败会话，将目录名恢复再开始。不要依赖其他缓存里的同名素材掩盖错误。

## 独立挑战与验收
把共享箱子改成0.8×0.5×0.6 m、质量仍为1 kg的均匀长方体，计算惯性和稳定中心高度。保持实例足够分散。可进一步改某个 include 的名称或 x/y、yaw，再按新名字查询；保留2至4个实例，本课自动验收限定该范围，更多实例留后续批量课。本课限定中心对齐 box、零 roll/pitch 和动态模型，不扩展为任意网格参数化。

自动验收从当前副本读取 include、入口和模型参数，对照真实几何、质量、惯性与布局，再临时暂停并抬升实例，继续仿真检查实际落点，最后恢复验收前的位姿和暂停状态。验收期间不要手动操作。颜色、目录讲解和“文件共享、实例独立”的解释仍由你人工完成。

不了解模型包？[查看官方模型结构](https://classic.gazebosim.org/tutorials?tut=model_structure&cat=build_robot)。不了解资源路径？[查看组件与环境变量](https://classic.gazebosim.org/tutorials?tut=components&cat=get_started)。需要核对 include？[查看 SDF 1.6 规范](https://sdformat.org/spec/1.6/world/)。

## 实时模型位姿的读取流程

验收中的模型位姿优先从持久Classic SDK辅助进程读取：同一Python进程、master与世界复用一个连接；一组请求发布器和响应订阅器保留到辅助进程退出。工具发送只读`entity_info`，检查响应ID、类型、模型名及实际`Model.pose`，返回真实位置和单位四元数。RPY由当前SDK的四元数Euler转换产生，沿用Classic的奇点约定；位置没有用保存SDF或理论预测补齐。

请求前后还分别等待新的WorldStatistics，保留接收顺序与源时间，二者不构成原子物理快照。反向响应通道初次发现较慢时，在同一总截止时间内最多再发一次只读查询，并使用新ID拒绝迟到旧响应。SDK缺失或不在精确支持范围内时，会在标准错误流说明原因并保留原有CLI读取，基础课仍可只安装运行时；已支持SDK上的编译、协议或查询失败会直接报告，不静默换路重试。原有模型移动和世界控制的单次发布规则、接触实验及物理求解保持原流程。
