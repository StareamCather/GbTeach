# 第28课参考：真实测距、递推与证据

先比较自己对距离和滤波响应的预测，再阅读参考。修改的是个人练习副本；此文不覆盖自己的代码或参数。

目标方块中心沿 x 轴、边长0.4 m时，中心射线的表面距离为 `x−0.2`，斜射线到同一前表面的距离为 `(x−0.2)/cos(theta)`。几何预测必须满足光线仍击中方块、没有更近遮挡且返回在有效量程内；应以原生消息确认这些前提。

对一帧中的有限、有效回波求最小值 `d_k`。有有效历史时，指数移动平均为 `y_k = alpha*d_k + (1−alpha)*y_(k−1)`。第一帧没有旧状态，可用本帧距离初始化。无有效回波应保留未知状态，避免用0、量程上限或上一次滤波值冒充本次新测量。

## 几何答案与有效束数

| 位置命令 | 方块中心x(m) | 最近有效距离(m) | 预期有效束数 |
| --- | --- | --- | --- |
| home | 1.4 | 1.2 | 3 |
| near | .8 | .6 | 3 |
| far | 3.2 | 3 | 1 |
| noecho | 8 | 无有效值 | 0 |

三束角度为−.1、0、+.1 rad。home的侧束约为 `1.2/cos(.1)`，near的侧束约为 `.6/cos(.1)`；它们仍落在方块前表面。far时，斜束到前表面的横向位置为 `±3*tan(.1)≈±.301m`，超过半宽.2m，因此不是“三束都等于3/cos(.1)”。noecho表示当前这只传感器没有本课定义下的有效回波，不能从中推导整个环境确定无障碍。

scanner外壳仅为外观，避免人为加入遮挡；目标的真实collision才参与CPU射线。若自己添加遮挡或移动方块离开视场，应重新列出几何前提。图中看见方块并不保证每条射线击中它，截图不能替代数组。

## 递推与阈值答案

默认 `threshold_m=.9`，`alpha=.35`。假设先前已稳定为1.2m，实际输入变成.6m：

```text
y1 = .35*.6 + .65*1.2 = .99
y2 = .35*.6 + .65*.99 = .8535
y3 = .35*.6 + .65*.8535 = .764775
```

因此默认第2个近处有效采样才从clear变为near。alpha=.7时第一帧 `.7*.6+.3*1.2=.78`，当帧即可near。不要把该结果强套到任意history：若回到home后尚未收敛，初始状态可能不是1.2，必须用记录中的真实 `previous_filtered_m` 验算。

只把阈值改为1.3m时，home的约1.2m有效滤波值即可near；真实三束测距应保持。阈值更改影响判断，不应反向改变传感器几何。只改alpha则影响过渡过程，在持续相同有效输入下，最终滤波值仍趋近同一个最近距离。

进入noecho时，valid_count=0、nearest_m=null、filtered_m=null、previous_filtered_m=null，alarm_state=unknown。回到任何有回波位置后，第一帧直接使用本帧最近距离初始化；因此不能用进入unknown之前的旧滤波值跨越空白段继续递推。`filter_initialized_from_current` 帮助区分重新初始化与普通更新。

验收中的连续性检查同样以有效段为界：当前帧有效且同epoch连续时，只有前帧也有效才继承其filtered，前帧无效则previous应为null；当前帧无效时三项距离均须为null并为unknown，不以旧有效值填补状态空白。

本课没有人为噪声；EMA造成的阶跃延迟是真实的软件结果。未来加入噪声时，应先说明噪声模型和实测统计，再评价平滑收益。更低的alpha不等同于更准确的环境理解，尤其不能消除量程边界或视场限制。

## 生命周期与时钟答案

Load读取父传感器/参数并保存事件连接；Init对应本次初始化。SensorPlugin虽然有Reset虚函数，本课Classic传感器调度不应被描述为每次世界复位都自动调用它。应读取各自计数，并把SensorManager的采样时钟复位与插件软件状态分开解释。

当真实测量时间回退时，本课插件递增epoch/rewind_count并清除EMA历史；下一次有效测量重新初始化。它保留原生回退时间，并没有把新数据强行改为单调时间。没有时间回退的模型位置复位，也不能自动推导出滤波历史必被清除。真正重载会建立新的插件对象，再执行Load/Init。

暂停时的snapshot是最后已处理帧的缓存。新nonce只表示这次查询被匹配，并不表示采样发生。检查 `source_time_ns`、`callback_count` 和原生时间，才能判断是否有新测量。`duplicate_stamp_count` 保留重复源时间的事实；分析记录时也应保留重复、原始次序和各epoch，不能通过排序或改标签制造同步。

home/near/far/noecho均先暂停、改真实目标位姿并查询实际应用；继续世界后才期待新测量。暂停之前已进入异步处理的回调可能稍后结束，关键是测量时间不超过冻结的世界时间，不是要求点击暂停瞬间所有软件工作同时消失。demo/verify恢复目标进入时位姿及暂停状态，但不倒回软件历史；reset则执行全世界复位并等候回退后的新测量，不恢复旧目标位置。

20Hz对应名义.05模拟秒周期。接收端的每墙钟秒消息数会受实时因子影响，不能直接当模拟采样率。暂停后100个1ms物理tick对应.1模拟秒；非lockstep传感器线程的实际回调数需要观察，不能直接补出“100帧”或保证任何一次快速多步都恰好两帧。

SetActive(true)显式开启本传感器；RaySensor的活动判断还考虑原生scan订阅。因此有原生观察者时，仅设置active=false不一定停止采样。停世界、停订阅、停插件发布和停传感器不是同一种操作。

## 对照代码与验收证据

代码信息流应可逐段对应：

```text
实际RaySensor及参数检查
→ 成功测量后的ConnectUpdated
→ 读取原生Ranges和LastMeasurementTime
→ 检查时间回退与上一状态
→ 只保留有限且min≤r<max的回波
→ nearest或unknown
→ 首帧初始化/EMA递推/阈值判断
→ 发布带原测量标签的Any JSON
```

native `LaserScanStamped` 是独立测量证据，自定义JSON是处理结果。应按真实source stamp对照同一测量帧，并分别核验有效束、最近值、旧状态、新状态和判断。不要只检查插件给出的nearest是否等于它自己给出的filtered。完整记录包含原生protobuf、自定义载荷、实际模型位姿和世界统计，额外的接收时间只描述传输观察过程。

构建阶段会校验参数、个人SDF及源摘要，源或参数修改后必须重载。缓存按实际SDK/编译器/源键锁定；不覆盖原始模板。观测客户端的退出兼容层明确等待Transport和异步IO结束后才释放对象，已验证边界为Classic11.15.1；私有ABI符号或运行库全版本不符时拒绝。这个维护层不属于SensorPlugin算法，也不会向传感器回填距离。

静态图形可检查模型、射线展示和窗口是否真实存在；原生数据才用于频率、滤波响应与无效回波的验收。自动验收、图形观察与尚未做的自行扩展需要分别记录。

## 挑战提示

滞回至少需要两个阈值和上一判断状态，例如进入near用较小阈值，退出near用较大阈值；先写清边界等号和unknown转移，再实现。不要同时改alpha、阈值和目标路径，导致无法归因。

按时间常数设计alpha时，可从连续一阶系统的离散形式考虑 `alpha_k=1−exp(−delta_t/tau)`。这是扩展提示，默认实现仍按采样次数使用固定alpha。时间回退、delta_t≤0、无回波和首次有效帧都需要额外状态规则；默认课程通过并不能证明扩展算法已经通过。
