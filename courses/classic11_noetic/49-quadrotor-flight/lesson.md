# 附加专项49 · 四旋翼悬停与阵风恢复

怎样把世界坐标中的悬停目标换成四个旋翼的推力？本课在Gazebo中闭环控制一个可平移和旋转的刚体。模型采用理想推力执行器和仿真真值反馈，把注意力集中在级联控制、坐标变换与执行器分配。建议先做第03课的坐标、第06课的惯性、第10课的PID和第41课的风扰动。

## 机体轴、旋翼与力矩

世界Z向上。机体X向前、Y向左、Z向上，正转遵循右手法则。roll、pitch、yaw分别对应横滚、俯仰与偏航。位置和线速度以世界坐标表达，内环阻尼项使用机体角速度。在这里，控制器直接用机体角速度抑制转动。机体角速度与欧拉角导数之间的换算取决于姿态。

| 编号 | 旋翼位置 | 相对质心的位置 | 正推力产生的偏航反力矩符号 |
|---|---|---|---|
| 0 | 前 | (+L,0,0) | + |
| 1 | 左 | (0,+L,0) | − |
| 2 | 后 | (−L,0,0) | + |
| 3 | 右 | (0,−L,0) | − |

十字布局的臂长L=0.22m，机身质量1kg，惯性对角项为(0.025, 0.025, 0.045)kg·m²。每个旋翼推力范围为0到6N，方向为机体+Z。水平悬停所需总推力为mg=9.81N，每个旋翼约2.4525N。模型中的圆盘标出旋翼位置。

推力产生的力矩由力臂叉乘力得到。例如左旋翼的力臂为(0,L,0)，向上的力为(0,0,f1)，叉乘得到正横滚力矩Lf1。插件用当前姿态把每个旋翼的推力旋转到世界坐标，再调用`AddForceAtRelativePosition`。该接口接收世界坐标的力以及机体坐标中相对质心的位置。偏航反力矩由`AddRelativeTorque`沿机体Z单独施加，比例系数k=0.018N·m/N。重力、各推力的力臂效应和刚体运动都由Gazebo ODE处理。[Gazebo Classic Link接口定义](https://github.com/gazebosim/gazebo/blob/gazebo11/gazebo/physics/Link.hh#L168)

## 级联控制怎样从位置走到姿态

每个控制周期先读真值状态。位置环把目标(0,0,1)m与当前状态转成期望加速度，姿态环再给出机体系力矩。级联指外层目标成为内层的输入。本课各层在同一控制周期计算，姿态内环用更直接的角度和角速度反馈。

```text
e_z = 1 - z
I_z = clip(I_z + e_z * dt, -0.6, 0.6)
a_z = clip(3*e_z - 2.6*v_z + 0.15*I_z, -4, 4)
a_x = clip(-1.4*x - 1.8*v_x, -2, 2)
a_y = clip(-1.4*y - 1.8*v_y, -2, 2)
```

正高度误差要求加大推力，正上升速度让速度反馈减小所需向上加速度。积分记录持续误差，限幅约束积分累积量。重力前馈提供悬停附近的主要推力，PID修正剩余误差。设roll为φ、pitch为θ、yaw为ψ，期望水平加速度先按偏航反向旋转到机体水平轴，再用小角度关系映射到期望倾角。

```text
pitch_ref = clip((cos(psi)*a_x + sin(psi)*a_y)/g, -0.25, 0.25)
roll_ref  = clip((sin(psi)*a_x - cos(psi)*a_y)/g, -0.25, 0.25)
T = (g + a_z) / max(0.65, cos(roll)*cos(pitch))  # m=1 kg
tau_x = 0.9*(roll_ref - roll) - 0.24*omega_x
tau_y = 0.9*(pitch_ref - pitch) - 0.24*omega_y
tau_z = 0.5*wrap(-yaw) - 0.2*omega_z
```

偏航目标为0。`wrap`把偏航误差映射到[−π,π)，使接近角度分界时仍沿较短方向纠正。以偏航为0为例，正pitch把向上的机体推力倾向世界+X，正roll把它倾向世界−Y。倾斜时竖直推力为T cos(roll) cos(pitch)，因此计算T时补偿竖直分量。分母下界与倾角限幅配合，适用范围是近悬停。可通过PX4的框图认识真实飞控如何分层并加入其他模块。[PX4多旋翼控制框图](https://docs.px4.io/main/en/flight_stack/controller_diagrams)

## 混控把一个请求分给四个旋翼

混控也称控制分配。控制器请求总推力T和三个力矩，混控求四个旋翼推力。

```text
T     = f0 + f1 + f2 + f3
tau_x = L*(f1 - f3)
tau_y = L*(f2 - f0)
tau_z = k*(f0 - f1 + f2 - f3)
```

先求前后两路之和与左右两路之和。两组的和为T，差为tau_z/k。再由pitch和roll方程求各组内部差，便能得到每个f。预测在T保持9.81N、tau_x=0.044N·m、其余力矩为0时，左旋翼比右旋翼多0.2N，二者各在悬停推力上加减0.1N。将结果代回四个式子，交叉项应抵消。

控制器将四个解逐个限制在[0,6]N。饱和会改变实际总推力和力矩。观察大误差时的推力限幅，并用同一组混控方程反算实际四个合量，就能查出哪部分请求未得到满足。

平台编译插件并打开独立的实验会话。客户端连接本课私有socket。回合开始时，物理线程设置初始姿态与速度并推进一个辅助物理步。第一条控制命令使用实际读回的初态。之后Python依次计算四个推力，原生工作线程在暂停世界中请求推进20个1ms步，物理回调在每一步施加推力和扰动。读回动作前后的原生状态与迭代数，下一条命令依据真实反馈计算。飞行中的位姿变化来自物理积分，重置只发生在回合边界。[Gazebo Classic的World::Step实现](https://github.com/gazebosim/gazebo/blob/gazebo11/gazebo/physics/World.cc#L807)

每次控制周期对应0.02s仿真时间。高度积分使用从原生步长或上一次动作前后时间差得到的周期。两个动作之间的Python计算耗时不会推进物理。两个回合各有400条动作和一次辅助重置，预期共16002个物理步。正常退出确认恢复原暂停状态。请求超时后如结果未知，结束本次实验并检查日志。实验运行中应保持独占，避免在GUI同时操作继续或单步。

## 先观察悬停，再分析扰动

```bash
python3 lab.py ready
python3 lab.py demo
```

两次重置分别请求0.45m和1.55m高度，起始roll为0.1rad，yaw为0.25rad，目标高度为1m。绿色标记显示目标高度。先预测哪次应增加初始总推力，哪次应减少，并观察偏航回正。两个回合的控制区间各8s。

以重置后的读回时刻为回合起点，控制步100至174施加世界水平力(0.45,−0.25)N，对应仿真时间[2,3.5)s。阵风是一个按仿真步调度的外力，叠加在线性阻力上。插件按世界线速度施加−0.12v的力，按机体角速度施加−0.008ω的力矩。观察其施加、撤去及恢复三个阶段。靠近悬停时，抵消+X和−Y方向推移通常需要把推力倾向−X和+Y，预测相应roll和pitch的符号，再到记录中找实际响应。

报告取(6.5,8]s的75个动作后样本。RMS先对误差平方取平均再开方。高度用z−1，水平用sqrt(mean(x²+y²))，姿态把三个欧拉角分量合并计算RMS。对应门槛为0.09m、0.14m和0.09rad。每个动作后还检查高度在[0.18,2.5]m内，roll与pitch的绝对值均不超过0.65rad。报告另给出阵风开始后相对施加前位置的最大水平偏移，反映这条轨迹的偏离与恢复过程。要量化阵风单独带来的影响，可另跑一条相同起点的零阵风轨迹。

`results/run-<uuid>/flight-trace.jsonl`每行保存一个回合，含请求与实际初态以及逐动作`trace`。从`control`读取期望加速度和姿态、积分、请求合力/力矩、限幅前后推力以及反算合量。再用`applied_rotors_n`、`wind_force_n`与前后原生状态核对执行。另一次状态请求读取物理更新完成时保存的快照，用于检查动作之间是否多走了物理步。

`report.json`保存本次指标和暂停恢复结果。最近一次报告也写到`results/flight-report.json`与`build/verification.json`。参考演示的`assignment_pass`为false。

## 单变量实验

先记录基准轨迹，再单独减小高度D增益。比较从低处和高处起飞时的最大高度误差、回中时间和末端RMS，判断速度反馈如何影响超调。也可固定其余参数，改变阵风幅值，观察撤去扰动后的横向回中。实验的评价窗口和起点应一致。

若出现立即翻转，依次查旋翼编号、姿态轴正向和混控符号。若高度长期偏低，检查四路推力、饱和和倾斜补偿。若阵风撤去后横移持续，先核对外力确实归零，再看期望倾角和实际角速度。保存失败轨迹，用动作与状态时序定位问题。

独立挑战可以在现有模型上加入一阶推力响应，固定控制增益比较恢复时间。也可在高度环中增加持续竖直扰动，比较有无积分项的稳态高度偏差。现有实验的证据范围是理想执行器、真值反馈和指定扰动的近悬停任务。
