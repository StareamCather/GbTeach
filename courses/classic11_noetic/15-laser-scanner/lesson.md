# 激光扫描：距离如何变成数组

一个静止扫描台面对黄色墙体，同时输出CPU ray与GPU ray两路LaserScan。默认正前方读数约2.9 m；墙体向远处移动1 m，读数应增加约1 m。不过在左右斜向，两路扫描有意看到不同的东西：一侧只有碰撞体，另一侧只有可见模型。它们测量的是同一个世界，却不一定依据同一套几何。

本课不需要先做SLAM或安装导航系统。你将从一束射线的方向、数组索引和几何预测入手，读真实消息，移动真实墙体，再判断数据支持什么结论。这里的ray表示理想射线测距，不含实体激光的全部光学与电子特性。

## 开始后先找到两路真实数据

平台自动准备独立ROS和Gazebo环境。CPU使用系统Noetic激光插件；GPU使用本课准备好的小型ROS适配器，将真正的原生GPU扫描消息转发为LaserScan。首次进入时，prepare.py会用已安装的Gazebo 11和ROS开发包离线编译适配器，后续复用匹配缓存；界面显示准备进度，不需要你先学习C++插件。使用本课终端，避免连接另一个实验的Master。

```sh
rostopic type /lesson15/scan
rostopic echo -n 1 /lesson15/scan
rostopic echo -n 1 /lesson15/gpu_scan
python3 lab.py observe --seconds 3
python3 lab.py ready
```

两路消息类型均为sensor_msgs/LaserScan。observe进行有界只读观察，不移动墙体；ready检查本课输入和数据准备情况。暂停世界会停止新的传感器更新，不能把等待不到新数据立即归因于网络。ROS topic、Master与消息订阅在第14课已作最少说明，第22课继续系统展开。

GPU ray需要可用的渲染上下文，即使只运行服务器、没有gzclient窗口，也不意味着它不需要图形设备。CPU数据正常、GPU一直没有数据时，要看服务器的渲染与插件日志。本课在真实桌面环境验证两路数据，不用预置数组替代GPU测量。

## LaserScan不是一张照片

LaserScan描述一个平面上的有序距离数组。**视场角（FOV）**是扫描覆盖的角度范围，**角分辨率**是相邻输出方向的角度间隔。按照[LaserScan定义](https://github.com/ros/common_msgs/blob/noetic-devel/sensor_msgs/msg/LaserScan.msg)，零角沿测量坐标系+X，角度绕+Z增加；Z向上时，从上方看正角是逆时针。

本课扫描原点在世界(0,0,0.7) m，传感器与世界坐标轴对齐；默认覆盖−90°到+90°，181个输出，水平resolution=1。因此索引从0到180，增量约1°：

```text
theta(i) = angle_min + i × angle_increment
theta_rad = theta_deg × pi/180
i_nearest = round((theta_wanted-angle_min)/angle_increment)
```

先确认所求方向在FOV内，再检查0≤i_nearest<len(ranges)，最后算回实际采样角。不能把超出FOV的方向硬夹到边缘索引，或因“数组中间”看起来合理就永远取中间；非对称视场、不同束数或没有恰好零角束时，这些捷径会出错。

| 默认索引i | 方向 | 本课的意义 |
| --- | --- | --- |
| 0 | −90° | 正右侧边界 |
| 45 | −45° | 仅碰撞几何的方块所在方向 |
| 60 | −30° | 用于墙面几何比较 |
| 90 | 0° | 正前方，默认约2.9 m |
| 120 | +30° | 用于墙面几何比较 |
| 135 | +45° | 仅可见几何的方块所在方向 |
| 180 | +90° | 正左侧边界 |

已知点坐标(x,y)时，用`atan2(y,x)`求方向，可以保留象限信息；`atan(y/x)`在x=0及后方象限会出问题。有限有效测距r可转成传感器平面中的`x=r cos(theta), y=r sin(theta)`。这不是自动得到地图世界坐标：若扫描台移动或旋转，还要用正确时刻的位姿变换。

## 一堵平墙为什么不是常数数组

黄色墙中心默认X=3 m，厚度0.2 m，朝向扫描器的表面在X=2.9 m。墙宽8 m，Y范围为[−4,+4]，覆盖扫描高度。设前表面距扫描器的垂直距离d，一束方向theta与表面相交时：

```text
r cos(theta) = d
r = d / cos(theta)
y_hit = d tan(theta)
```

公式成立还要求射线朝前、交点在墙面边界内，且r处在有效量程内、前面没有更近的物体。它不是对整个180°数组无条件套用的公式。默认d=2.9 m，中心束为2.9 m，±30°约3.349 m；墙中心移到4 m，d=3.9 m，中心为3.9 m，±30°约4.503 m。斜向路程更长，并不表示墙被测成弯曲。

本课±60°已经超出有限墙宽：即使理论无限平面交点存在，实际也没有这块墙面。边缘束得到无回波数据是正常现象，不能让d/cos(theta)生成一个不存在的无限墙。

## CPU与GPU：两种几何来源

```text
同一SDF传感器位姿、扫描角与量程
  ├─ CPU ray → 物理collision射线检测 → 原生扫描 → 系统ROS插件
  └─ GPU ray → 渲染场景深度采样 → 原生扫描 → 本课ROS适配器
        → 各自LaserScan → 几何与数据检查
```

CPU ray使用物理碰撞几何；GPU ray依据渲染场景。**visual与collision可以不同**，所以“GUI看见它”不保证CPU射线能碰到它，“GUI看不见它”也不保证CPU路径畅通。原生实现可查[RaySensor](https://github.com/gazebosim/gazebo-classic/blob/gazebo11_11.15.1/gazebo/sensors/RaySensor.cc)与[GpuRaySensor](https://github.com/gazebosim/gazebo-classic/blob/gazebo11_11.15.1/gazebo/sensors/GpuRaySensor.cc)；不同渲染后端的透明、遮罩等细节应实测，不能据此把GPU ray当作真实材料反射模型。

本课没有同时加载两个系统ROS激光包装库：它们在当前安装版本存在同名插件类冲突，上游[问题768](https://github.com/ros-simulation/gazebo_ros_pkgs/issues/768)也记录了这一情况。GPU侧的gpu_bridge.cc使用独立类名，只复制原生扫描的时间戳、角度、距离和强度，不用解析公式生成测量，也不改变GPU测距或渲染几何。你不必先修复系统插件才能做本课，Sensor Plugin实现留到第28课展开。

两个辅助方块边长0.4 m，中心位于(1.5,−1.5,0.7)和(1.5,+1.5,0.7) m：

| 方向 | 专门设置 | CPU预期 | GPU预期 |
| --- | --- | --- | --- |
| −45° | 只有collision | 测到较近方块，约1.838 m | 忽略这个无visual方块，默认测到远墙约4.101 m |
| +45° | 只有visual | 穿过这个无collision方块，默认测到远墙约4.101 m | 测到较近方块，约1.838 m |

上述远墙数字针对默认中心X=3 m。墙更远时，±45°交点可能落在墙宽之外，正确答案会变成无回波。请按当前场景边界判断，不背一个永远有效的固定数组。两路在0°与±30°应符合相同墙面几何；它们在专门设置的±45°不同，恰好是本课要验证的结果。

## 无穷、NaN与量程边界

不要直接对全部ranges求平均。先分类，再将有限且位于range_min到range_max内的值用于几何计算，同时保留无回波或无效计数。

| 数据 | 通用解释与处理 |
| --- | --- |
| 有限值且在量程内 | 可作为候选距离，仍需结合实现和场景判断 |
| +Inf | 按REP117表示量程内无回波/超远，不能当作一块无穷远墙来求平均 |
| −Inf | 按REP117表示过近、无法定量的检测，不是负距离 |
| NaN | 无有效数值，应单独统计；比较运算常会使它悄悄漏过错误过滤 |
| 有限但超出消息量程 | 按消息定义丢弃，检查来源与异常 |

[REP117](https://github.com/ros-infrastructure/rep/blob/master/rep-0117.rst)规定特殊值的语义，但不保证每个驱动或每种几何情况都恰好产生它们。Classic 11这两条原生路径把原始距离≥max映射成+Inf、≤min映射成−Inf；有效中间距离添加噪声后还会夹到[min,max]，GPU另有NaN转为有限max的处理。因此有限max不一定证明在那个位置命中了实体。近裁剪还可能让完全位于盲区的物体不参与检测，不能说“所有过近物体一定报告−Inf”。

不要用`r != NaN`检测NaN；应使用isfinite/isnan等浮点分类。实际分析时既报告有效值，也说明未参与平均的类别和数量。没有数据、空数组与一条含+Inf的有效扫描，也不是同一件事。

## frame、时间和频率的三个边界

本课两路frameName都标为laser_frame，因为它们在同一个原点、同一组坐标轴测量。插件填写header.frame_id，不会自动向TF广播world→laser_frame变换，也不会因为把标签改成world就旋转数组。TF和RViz从第24课继续；当前可以直接读数组，不把“没有TF”误判成传感器没测距。

LaserScan规范用header表示首束获取时间，time_increment表示束间间隔，scan_time表示扫描间隔。本课实际加载的Noetic [CPU插件](https://github.com/ros-simulation/gazebo_ros_pkgs/blob/noetic-devel/gazebo_plugins/src/gazebo_ros_laser.cpp)和自带GPU适配器均将time_increment与scan_time设为0，GPU适配器沿用原生瞬时扫描及上游包装约定；[系统GPU包装源码](https://github.com/ros-simulation/gazebo_ros_pkgs/blob/noetic-devel/gazebo_plugins/src/gazebo_ros_gpu_laser.cpp)可作对照，但这个系统库未在本课加载。**不能把181束解释为真实机械转子在0.05 s内依次采集，也不能用两个零字段计算扫描频率。** 本课不模拟这种逐束运动畸变或其去畸变算法。

更新率配置20 Hz指目标每仿真秒约20帧。实际频率用不同header时间的首末跨度估计；电脑墙钟接收频率受实时因子、渲染负载和消息调度影响，两路也未必恰好同一时刻更新。静止墙比较无需硬造同步；移动场景的对应关系要看新鲜时间戳，不能拿CPU旧帧与GPU新帧宣称测距不一致。

## 单变量实验与测量流程

world.sdf是实际个人输入，准备工具只检查，不重写。保存参数后须重载，运行中的场景不会自动采用文件中的新束数。

```sh
python3 lab.py config --samples 361
python3 lab.py config --distance 3.5
```

每次只执行一项再重载并观察。samples同步修改两路；181→361时FOV不变，间隔从1°变成0.5°，正前方仍测同一墙面，不能把更多数组项直接解释成更高距离精度。墙中心允许2.5到4 m，束数允许181或361；其它结构保持固定以便比较。

要只改变运行中的墙位置而不改起点文件，可用`python3 lab.py wall --distance 4`。它明确移动本课target_wall，保留原暂停状态；继续后观察新的扫描。这个静态墙是教学用可控目标，不是靠动力学行走的机器人。

```sh
python3 verify.py
```

完整验收先记录进入时的真实墙状态，再主动建立保存配置中的基线位置，比较“配置基线→沿+X移动1 m→回到配置基线”三个阶段，同时检查数组元数据、几何、两种辅助方块和无回波方向。每阶段的每路至少12条不同时间戳消息，跨度至少0.5仿真秒；选取−90°、−60°、−45°、−30°、0°、30°、45°、60°、90°九个实际束，有限距离误差不超过0.08 m，预期无回波须读到+Inf，仿真时间估计频率在15到25 Hz内。

最后恢复**进入验收时**的墙位姿、速度和暂停状态，即使你事先用wall命令移过墙，也不把它擅自留在配置起点。它不倒回世界时间，也不恢复此前终端打印。原始扫描与分项结果保存在本会话的laser-verify-唯一编号.json，终端打印trace_path；也可用`python3 verify.py --report build/my-laser-check.json`指定个人报告。报告将非有限值保存为字符串`+inf`、`-inf`、`nan`，保留类别，不把它们替换成0或普通最大量程。测量期间不要同时移动墙、重置或执行另一个验收。

## 噪声与混叠：知道当前模型省略了什么

正式几何对照使用零噪声，避免把随机性和几何错误混在一起。Gaussian噪声是按给定均值、标准差扰动距离的模型，stddev单位为m，不等于角分辨率；平均多帧可减小某些独立随机波动，但不会消除系统性偏差，也不会把夹断的边界数据恢复成真实距离。range/resolution虽是长度字段，本版本的这两条更新路径不据此将所有读数量化到1 cm网格，不能把文件中的0.01直接当成已证明的测量精度。[Classic噪声教程](https://classic.gazebosim.org/tutorials?tut=sensor_noise)是拓展入口；本课固定结构检查不开放任意noise修改，拓展请先在独立副本进行。

**混叠（aliasing）**指采样无法唯一反映更细或更快的变化。空间上，细柱可能恰好落在两束之间，增加束数才有机会发现；时间上，运动目标可能在两帧之间穿过路径，提高更新率或改变相对运动后结果会变。不能把某一帧未检测当成整段时间和整个角区都绝对空闲。

## 文件、故障和独立挑战

| 文件 | 职责 |
| --- | --- |
| world.sdf | 同位CPU/GPU扫描器、墙、只碰撞/只可见方块 |
| prepare.py | 检查输入与依赖，离线编译或复用GPU适配器，记录源码和库指纹 |
| gpu_bridge.cc | 将真实原生GPU扫描复制为ROS消息，不负责生成距离 |
| lab.py | 只读观察、局部参数编辑、明确移动墙与公共测量逻辑 |
| verify.py | 三阶段真实测量、原始数据与分项验收 |
| reference.md | 索引、交点推导和示例答案，只读查看 |

| 现象 | 先查什么 |
| --- | --- |
| GPU没有数据，CPU正常 | 图形上下文、服务器渲染日志、本课适配器的准备与加载日志 |
| 中心距离总差0.1 m | 是否把墙中心当作朝向扫描器的表面 |
| 两路±45°不同 | 是否正好是本课visual/collision专门对照，而非立刻判坏 |
| 算出来的束落到另一侧 | 角度符号、rad/deg、零基索引与实际采样角 |
| 新样本仍对应旧墙 | 运行位置、header新鲜度、渲染更新与是否暂停 |
| 有frame但RViz不能定位 | header标签不等于TF变换已经发布 |
| 除以scan_time得到异常 | 当前插件的该字段为0，频率应从不同时间戳估计 |

独立挑战：只使用实际消息的角度字段和有效值，给正前方±20°输出最近距离、所处角度和有效/无回波计数。提示一：先按方向筛选索引；提示二：浮点分类后再求最小；提示三：若没有有效值，明确报告“没有可用距离”，不要伪造为0 m或保证无障碍。参考答案不替你完成这段数组处理。
