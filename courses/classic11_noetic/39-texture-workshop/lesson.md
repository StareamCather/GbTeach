# 附加专项 39：用一张纹理做出可测量的材质实验

这间贴图工坊有三张卡片。从相机图像的左边到右边，依次是一倍 UV 棋盘、四倍 UV 棋盘、红色透明层叠在蓝色底板上。你要解释：**同一张 PNG 为什么能显示出不同尺寸的格子？图像清楚是否代表纹理密度合理？透明材质为什么还需要考虑遮挡排序？**

## 从文件到像素

纹理是二维像素数组；UV 是表面顶点在二维纹理中的坐标。一个三角形内部的 UV 经插值后决定从纹理哪处取色。UV 超过 0～1 时，`tex_address_mode wrap` 让纹理重复。采样和缩小时的滤波决定边缘是否锯齿、细纹是否闪烁。

本课材质使用 Classic 的 OGRE 材质脚本。**这里是传统渲染工作流**；金属度、粗糙度与现代 Gazebo 的 PBR 材质不是可以任意互换的参数。材质脚本关闭光照，让 UV 实验的颜色不受灯光方向干扰；研究漫反射和阴影请去下一专项。

## 文件结构

| 文件 | 负责的输入或输出 |
|---|---|
| `parameters.json` | 左/中卡片 UV 重复次数，右卡片玻璃不透明度 |
| `texture_builder.py` | 标准库生成128×128 RGB棋盘PNG；源文件可直接修改 |
| `models/texture_cards/materials/textures/checker.png` | 已附带的离线纹理，不需要下载 |
| `models/texture_cards/materials/scripts/cards.material` | OGRE纹理单元、wrap、双线性滤波和剔除设置 |
| `scene.py` | 生成带UV的DAE卡片和SDF，启动时按个人参数重建 |
| `native/camera.cc` | CameraSensor的真实渲染回调，将帧与序号存入本会话目录 |
| `verify.py` | 从真实相机像素测边界次数、纹理对比与透明混色 |

初始化：检查参数→生成卡片UV与个人世界→通过pkg-config读取Gazebo及OGRE/Paging/Terrain/RTShaderSystem头文件与链接参数→编译相机SensorPlugin→真实相机渲染→每5帧保存一组图像和元数据→验收确认帧时间前进及字节校验一致→在指定图像区域测量。图像并非Python合成的参考图；Python生成的只有作为输入的PNG纹理。

## 第一次运行

1. 开始实验，等待相机有图像。点击“运行真实行为验收”。
2. 在操作终端运行 `python3 lab.py image`，复制输出的 `ACTUAL_CAMERA_FRAME` 路径，用系统图像查看器打开 `camera.ppm`。它是传感器看到的画面，与自由移动的Gazebo用户相机分开。
3. 找到左、中两张棋盘卡：中卡片一条边覆盖4倍UV，所以单位长度格子更多。右卡片同时保留红色和蓝色分量，而不是纯红。
4. 对照验收中的 `uv_boundary_counts`、`mean_rgb` 和 `image_path`。验收统计的是相机中部的一条水平线跨过多少深浅边界，而不是数SDF中的参数。随后用当前UV重复次数、已声明相机投影和卡片宽度推导边界密度，允许端点相位与像素滤波带来的±2条误差，分别比较两张卡片；因此左2倍、中3倍这种合法组合也能按自身预测验收，不要求固定比例。

相机水平视场1.3 rad，分辨率640×360，前方4 m布置卡片。固定成像几何使自动测量区域可重复。移动相机、卡片位置或分辨率时，应重新推导ROI，不能保留旧像素窗口却宣称测量仍正确。

## 单变量实验一：UV平铺与texel密度

默认左卡片重复1次，中卡片重复4次。把 `uv_repeat_right` 从4改成3，其他参数不动，重启实验。先预测：中卡片的格子更大，横向边界次数下降；但仍比左卡片多。

每张卡片边长1.6 m、纹理宽128 px、纹理自身每边4格。重复1次时，纹理密度约80 px/m；重复4次时约320 px/m。这里只计算输入纹理密度，**屏幕上的像素密度还取决于视距、投影和输出分辨率**。

将相机视角调成斜视，观察远处小格是否闪烁。这是人工观察实验，自动正视ROI验收不认证斜视滤波质量。可在材质脚本中试验 `filtering none` 与 `filtering bilinear`，逐次重启并保存相同视角截图。

## 单变量实验二：改变真实纹理文件

打开 `texture_builder.py`，把 `cell_pixels=32` 改为16，然后运行 `python3 texture_builder.py`，重启实验。现在同一128×128纹理包含每边8格；保持UV不变，卡片上的格子数量翻倍。更换两个RGB颜色同样会改变真实相机输出。

启动流程只生成卡片DAE和SDF，不覆盖个人PNG。恢复默认PNG可将脚本参数改回32并重新运行。修改UV和修改PNG都能改变格子大小，但意义不同：前者改变表面到纹理的映射，后者改变纹理本身的内容。

## 单变量实验三：透明度与深度

`glass_alpha` 表示不透明度，默认0.45；本课将它写入独立生成的 `glass.material` 中的 `alpha_op_ex`，用 `scene_blend alpha_blend` 混合单层红色网格面与蓝色底板。增加alpha，右卡片更偏红；减小alpha，蓝色底板更明显。普通SDF的 `transparency` 使用 `1-alpha` 这一相反约定，但本课不再同时设置SDF透明度，以免两次应用透明度。

简单的前后两层可用近似混合 `Cout = alpha × Cred + (1-alpha) × Cblue` 理解。实际图像还会受渲染状态、颜色空间和表面方向影响，因此本课既检查红蓝分量均存在，也要求它们明显高于绿色，拒绝“白色不透明面”这种假混合；再比较 `R/(R+B)` 与当前alpha的关系，允许渲染颜色空间和整数采样带来的0.18差异，不把RGB逐位相等当作物理正确标准。将alpha单独改为0.7后，重启并对比实际红色占比应上升。

多个相互穿插的透明面可能需要排序，并涉及深度测试、深度写入与背面剔除。透明外观并不自动减少碰撞：本课卡片仅用于视觉，不将alpha当作碰撞开关。

## 常见错误

| 现象 | 可能原因与定位方法 |
|---|---|
| 全部白色或纯色 | PNG搜索路径错误、OGRE脚本名不匹配，查看运行日志中的材质/纹理提示 |
| 卡片从某面消失 | 三角形绕序/法线与背面剔除；本课OGRE脚本关闭剔除，仍应学习正确方向 |
| UV改了没变化 | 当前服务器仍持有旧网格；重启实验，检查生成后的DAE |
| 越远越出现条纹 | 高频纹理与屏幕采样的混叠，尝试降低重复次数或改善滤波 |
| 自动验收提示帧不前进 | 世界暂停、DISPLAY/渲染失败、相机插件未加载；不要拿文件存在当作实时数据 |
| 更换纹理颜色后原验收失败 | 本课阈值针对高对比棋盘；新材质应设计新测量目标与阈值 |

## 独立挑战

制作地板、墙面和设备警示条三种材质，使用同一模型目录组织纹理。保证它们的目标texel密度接近，并解释为什么一张大平面与一个小标牌可能需要不同纹理分辨率。附上正视与斜视两张真实相机图像；说明UV重复、纹理本身频率和屏幕采样分别起什么作用。

自动验收覆盖真实帧推进、UV频率差异与透明叠层混色。UV接缝是否自然、斜视闪烁、透明排序、美术质量仍是视觉验收项目。

不了解材质与纹理？[Classic官方颜色与纹理教程](https://classic.gazebosim.org/tutorials?tut=color_model)。不熟悉纹理文件放哪里？[官方模型目录规范](https://classic.gazebosim.org/tutorials?tut=model_structure)。

相机插件包含实际 `rendering/Camera.hh`，其传递依赖涉及OGRE分页、地形与RTShader头文件。因此准备程序显式合并这几组pkg-config编译/链接参数，不能仅凭gazebo.pc可用就认定相机开发环境完整。缺少OGRE开发包会在进入课程前列为依赖问题；不会自动下载。

本课使用单层玻璃网格面，避免薄箱体前后两个透明表面重复混合。关闭光照时，单写diffuse并不能可靠产生手动红色；生成的OGRE脚本使用 `colour_op_ex` 明确输出红色，并关闭depth_write、保留depth_check。其模式与Classic内置RedTransparent材质一致。
