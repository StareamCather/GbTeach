# 参考：贴图信息流与测量

默认左、中卡片每边4格、16格。相机内测量线未覆盖全部卡片，因此实际边界次数比理论格子数略少；关键是中卡片有明显更高的频率。验收要求两张卡片均有明显亮暗对比，并按当前UV重复次数分别推导边界数。640px宽、水平视场1.3rad的相机焦距为 `640/(2*tan(.65))≈420.94px`，1.6m宽卡片在4m前方投影宽约168.38px。130个采样像素覆盖129个像素间隔，边界密度预测为 `4*repeat*129/168.38`，允许±2条边界，以容纳采样线端点相位、双线性滤波和离散像素。默认1/4倍时约3.06/12.26条；合法2/3倍时约6.13/9.19条，不再硬编码至少1.8倍的比值。中卡仍需比左卡边界多。

UV生成：四个顶点形成x=0的YZ平面，`quad(repeat)` 将UV由0扩展到repeat。三角形绕序朝向相机，OGRE材质使用wrap；PNG由标准库输出合法IHDR、压缩IDAT和CRC，不依赖外部下载或图像库。

真实相机插件的流程：接收CameraSensor→连接NewImageFrame回调→确认RGB8三通道→记录原始帧→计算64位FNV校验→原子替换PPM与JSON。验收读取时重新计算校验，若两文件恰好跨帧，则在18秒有界等待内重读。随后确认sequence和测量仿真时间增加，避免旧图冒充新帧。

自动检测ROI依赖固定相机与卡片几何。不能把移动相机后的阈值失败解释为Gazebo材质失效，应重新标定ROI或改用模型投影来定位卡片。

透明玻璃必须呈红蓝混合且绿色显著更低；白色同时含红蓝，不能仅用R>阈值、B>阈值证明透明链路。额外检查 `R/(R+B)` 与当前alpha的关系，并用alpha单变量变更后的真实像素确认响应；它不证明全场景透明排序正确。查看斜视和交叠玻璃时应人工检查深度和排序。

离线编译依赖：Camera.hh包含OGRE相关渲染头文件；prepare显式合并gazebo、OGRE、OGRE-Paging、OGRE-Terrain、OGRE-RTShaderSystem的cflags和libs。缓存键包含这些完整flags、SDK版本、编译器标识和插件源；补全头文件路径后会形成新的缓存键，不复用早先失败构建。

玻璃生成流程：参数alpha→独立glass.material的manual红色和alpha_op_ex→alpha_blend、depth_write关闭、depth_check保持→单层DAE平面→实际蓝底混合像素。单层平面避免透明箱体的两层表面叠加；不同时填写SDF transparency。关闭lighting时不能只靠diffuse指定红色，需手动颜色运算。
