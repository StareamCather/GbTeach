# 参考推导：接触双方、方向与首次反弹峰

本页只读，不改写个人练习。以下数值是基准参数下的理论预测，真实观测以 experiment 的实际 pose/stats 和报告为准。

## 找到正确的 surface

路径是 `world/model/link/collision/surface`。滑块沿坡接触属性的关键结构如下；其他几何、惯性和接触设置保留本课原值：

```xml
<surface>
  <friction>
    <ode>
      <mu>0.1</mu>
      <mu2>0.8</mu2>
      <fdir1>1 0 0</fdir1>
    </ode>
  </friction>
  <bounce>
    <restitution_coefficient>0</restitution_coefficient>
    <threshold>0.1</threshold>
  </bounce>
</surface>
```

本课 Classic 11/ODE 对接触双方的 mu、mu2、恢复系数和阈值分别取 min。mu/mu2是正交切向方向系数，与“静摩擦/动摩擦”没有字段对应关系。阈值具有速度单位 m/s，恢复系数与摩擦系数无量纲；摩擦系数可大于1，恢复系数的本课范围为0至1。[Classic 摩擦教程](https://classic.gazebosim.org/tutorials?cat=physics&tut=friction)、[SDF 1.7 surface 字段](https://sdformat.org/spec/1.7/collision/)及[ODEPhysics 接触配对源码](https://github.com/gazebosim/gazebo-classic/blob/gazebo11/gazebo/physics/ode/ODEPhysics.cc)分别支持这些定义与后端规则。

fdir1 在 collision 固连坐标系中给出，再通过 collision 的世界姿态旋转。第一方向与接触法线正交，第二方向位于同一切平面。本课三处斜面接触坐标系初始方向相同，因此局部X沿坡、局部Y横坡；将三处一起换成Y，会交换本次沿坡运动使用的系数。不要由此推断任意两种冲突方向的接触会自动按你期望合并。

摩擦金字塔对两个切向分量分别施加约束，是接触模型的近似。即使两个系数相等，也不宜把任意合成方向的结果直接当成理想圆锥摩擦的精确解；本课沿切向主轴做直线比较。[ODE 手册](https://www.ode.org/ode-latest-userguide.html)解释了该近似及方向标志。

## 斜面滑移计算

θ=20°、g=9.81 m/s²，斜面mu/mu2=1/1，低滑块0.1/0.8，高滑块0.8/0.8。基准fdir1沿坡，所以系数取第一项：

| 接触 | 配对mu | 配对mu2 | 基准沿坡结果 |
| --- | --- | --- | --- |
| slider_low与斜面 | 0.1 | 0.8 | 预计滑动 |
| slider_high与斜面 | 0.8 | 0.8 | 预计静止 |

静止所需摩擦与法向力之比为 tan20°≈0.36397。高滑块的上限足以满足平衡，实际静摩擦取所需值；低滑块上限不足，进入滑移。

```text
low：a ≈ 9.81(sin20°−0.1cos20°) = 2.43338 m/s²
t = 800×0.001 = 0.8 s
s ≈ a t²/2 = 0.77868 m

只改low.mu为0.2：
a ≈ 1.51154 m/s²
s ≈ 0.48369 m
```

这些是贴合斜面、从静止开始、无滚转的连续近似，不把接触建立瞬间或有限步长误差伪装成精确理论。高滑块保持平衡，不使用“mu乘法向力始终取满”去预测它向坡上加速。

方向挑战只把 friction_ramp 和两滑块的 fdir1 同步从X转Y。此时沿坡使用 mu2；双方配对后均为0.8，所以低滑块也应保持近似静止。mu和mu2的数值不变，改变的是所选空间方向。

2026-10-30 ikaros 的Y方向变式实测两滑块均移动0.0004001636 m，属于初始微小间隙沉降后的近静止，并非数学上的绝对零；对照X方向低块0.779768 m，支持本次沿坡取mu2的方向解释。

## 恢复系数与高度

球半径r=0.12 m，初始中心z₀=1.8 m，垫顶z_pad=0.2 m：

```text
接触球心高度 z_contact = z_pad+r = 0.32 m
自由落差 H = z₀−z_contact = 1.48 m
碰撞前法向速度大小 v_in ≈ √(2gH) = 5.38865 m/s
碰撞后速度大小 v_out ≈ e_pair v_in
首次反弹上升高度 h ≈ v_out²/(2g) = e_pair²H
```

pad_dead、pad_bouncy的恢复系数均为1；球分别为0、0.8，故配对为0、0.8。ball_bouncy 的理想首次rise为0.9472 m，球心峰高0.32+0.9472=1.2672 m。ball_dead 的恢复项为零；有限步长接触纠正仍可能产生很小的位移。

只把 ball_bouncy.e 改为0.6，理想rise变为0.5328 m、中心峰高0.8528 m，高度增量相对基准比为 `(0.6/0.8)²=0.5625`。e是法向速度比；对应的法向动能比例才为 e²，不能把它当作所有平动、转动能量的统一保留比例。

本课测量按实际采样点检查先升后降，再拟合首次反弹峰。用来比较的rise应是 `实际峰球心z−垫顶z−球半径`，不是直接拿球心z与 e²H 比。首次峰附近的数值求解、接触修正和拟合误差以实际报告与容差评估。

拟合使用三个实际点 `(t₁,z₁)、(t₂,z₂)、(t₃,z₃)`：先确认中间高度比两侧均高至少0.002 m，再拟合向下开口的抛物线，要求顶点位于三点时间括区内、曲率接近自由飞行的−g/2。报告分别保存 sample_peak_z（采样点最大值）和 fitted_peak_z（拟合顶点），不把插值顶点当成直接读到的一帧。ball_dead采用碰撞后采样高度作无显著反弹对照，不强行为它拟造一个自由飞行峰。

2026-10-30 ikaros 正式基准实测：低/高滑块位移0.779768/0.000400164 m；球的sample最大z为1.22539 m，拟合峰z为1.2258801 m，rise为0.9058801 m，对照理想0.9472 m低约4.4%，dead的rise为0。g=8、mu=0.2、e=0.6变式实测低/高滑块0.395157/0.0003796 m，拟合峰z=0.8251559 m、rise=0.5051559 m，相比理想0.5328 m低约5.2%，dead仍为0。真实软接触与离散求解体现了与理想瞬时碰撞的差别，实际采样、拟合结果和理论预测应分别保留。

## 阈值挑战的两次预测

基准双方threshold=0.1 m/s，接近速度约5.389 m/s，恢复项激活。只把球threshold改为10，垫仍0.1，则配对仍0.1，预计仍反弹；再把垫也改为10，配对才为10，预计恢复项关闭。恢复系数本身仍可为0.8，但此次碰撞不会按它产生恢复项。

两侧高阈值是合法的接触场景，却不适合本课的清晰反弹峰测量；predict会给出量程拒绝。要看关闭反弹的现象，可保存、重载后暂停，重置模型状态再继续；随后恢复双方0.1并重载，才回到定量仪器与自动验收。不要把量程拒绝说成Gazebo不支持这种运动。

SDF默认threshold为100000；需要检查接触双方的实际值。`bounce/threshold` 对应 ODE bounce_vel；本课没有 surface/min_vel 字段。`contact/ode/max_vel` 是另一项接触速度上限，当前QuickStep还会用它限制加入恢复项后的约束目标，不能替代反弹阈值，也不能普遍说它只影响纠穿。

本课固定全局 contact_max_correcting_vel=10 m/s，两球同为max_vel=10 m/s、min_depth=0.001 m、kp=10⁸ N/m、kd=1 N·s/m；两球这四项数值须相同，仍以恢复系数作为接触对照变量。1 mm的min_depth用于降低离散纠穿给e=0对照带来的微小伪弹，不单独控制某一颗球。滑块和垫面保留原来的max_vel=0.1、min_depth=0.0001，避免混改滑移条件。

版本边界来自实际求解路径：11.15.1的[contact.cpp](https://github.com/gazebosim/gazebo-classic/blob/gazebo11_11.15.1/deps/opende/src/joints/contact.cpp#L201)先设置包含恢复项的接触目标，[quickstep.cpp](https://github.com/gazebosim/gazebo-classic/blob/gazebo11_11.15.1/deps/opende/src/quickstep.cpp#L394)随后仍按c_v_max夹紧该目标。因此只修改e而保留过低上限可能遮蔽反弹。本课要求全局和两球上限各自≥`max(e_pair×impact_speed)+0.5 m/s`，默认下界约4.810924 m/s，g=8/e=0.6变式约3.419726 m/s；predict的contact_velocity_limits列出当前、所需上限与预留裕量。这是当前实现及仪器的防截断条件，不是恢复系数的定义或所有引擎的统一规则。

## 当前仪器的支持边界

这些范围用于隔离变量、避免信号低于分辨率或物体离开实验区，不作为物理引擎的通用极限。predict先完成全部校验，失败时不暂停、重置或发送控制消息。

| 项目 | 本课支持范围与条件 |
| --- | --- |
| 时间、重力、斜坡 | dt为0.0005至0.002 s；竖直向下g为5至12 m/s²；坡角12至25° |
| 主方向摩擦 | mu/mu2为0至2；slip1/slip2保持0；斜面与两滑块同为切向±X或同为±Y |
| 滑块采样 | slide_steps为50至1800；滑动预测位移≥0.15 m；距静滑边界至少0.04 |
| 跑道与初始条件 | 滑块距坡面0至0.003 m；横向留边≥0.05 m；初始位置沿坡两端的盒包络均留边≥0.15 m，全事件采样结束前沿坡仍留边≥0.15 m，并检查高度避免先倾覆 |
| 刚体与几何 | 单link、居中且匹配的collision/visual；动态质量0.1至10 kg，均匀几何中心惯量一致；两球同半径、同净落高及垫面高度 |
| 球与恢复系数 | 净落高H为0.6至2.5 m；dead配对e=0；bouncy配对e为0.4至0.9且e²H≥0.12 m |
| 阈值 | 各侧0至100 m/s；定量反弹要求配对threshold严格小于预计撞速−0.3 m/s |
| 峰采样 | 请求半窗0.04至0.15 s，实际取其与0.4倍上升时间的较小值；实际半窗≥0.04 s且g×半窗²/2≥0.004 m |

接触数值参数保持模板值。本课校验接受文件声明的 kp为10⁷至10¹² N/m、kd为0至10 N·s/m、min_depth为0至0.001 m；两球max_vel声明范围为0.001至20 m/s，其余模型为0.001至0.2 m/s。全局与两球上限还须通过上述防截断条件，不能只检查落在字段范围内；这些设置的数值稳定性含义留后续课程讨论，不与当前单变量实验混改。

文件声明与运行消息之间可能存在明确的引擎转换：Classic/ODE 读取 SDF 后，会在加载静态 collision 时强制其 maxVel=0，因此本课静态斜面和垫面虽声明 max_vel=0.1，真实消息读到0符合预期。报告分开保留 saved_surface、expected_runtime_surface、actual_surface，仅对已确认的静态max_vel作这一映射，动态表面和其他字段仍严格比较。这是纠穿参数的加载规则，恢复系数与 bounce/threshold 继续单独核对。[11.15.1 的 ODECollision::Load](https://github.com/gazebosim/gazebo-classic/blob/gazebo11_11.15.1/gazebo/physics/ode/ODECollision.cc#L65)记录了该转换。

基准按预测安排的事件为519、549、589、800、889、989、1089步，分别覆盖触地前后、滑块0.8 s位移及反弹峰三点。事件全局排序，多个事件落在同一步时共用采样；改变e或g后按当前配置重新安排，不固守这组步数。滑移容差为预测位移的18%与0.045 m的较大值，held为0.025 m；反弹rise容差为预测值的15%与0.045 m的较大值。它们是本课连续近似与有限步长观测的判定范围，不表示所有配置都达到某个统一精度。

## 从文件修改到真实证据

一次只改变指定的独立变量，遵循：记录预测 → 修改个人world → 保存 → predict → 应用“重载项目” → experiment并保存报告。方向挑战中的三处同步编辑，用于维持接触双方一致的方向约定；不要同时更改mu、坡角或初始速度。

```bash
python3 lab.py predict
python3 lab.py experiment --report measurements-current.json
```

predict检查当前文件并安排窗口，experiment还要核对真实已加载的surface、几何和初始条件。初始化先暂停并推进一步排空历史输入，再reset ALL和采实际stats基线；正式事件按物理步数排序，避免滑移采样遮住更早的球峰。报告保留实际采样，最终仅恢复原暂停状态，不还原原位姿、速度或仿真时间。

检查证据时依次看：文件配对规则是否算对、真实surface是否与文件一致、当前fdir1对应哪一主方向、实际时间与位移是否匹配、球的上升/下降是否确实括住首次峰。接触传感器和求解器稳定性留后续课程；本课不把一个PASS扩大解释为任意碰撞场景都准确。
