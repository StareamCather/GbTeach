# 积木房间：外观与碰撞

## 先预测两个落点
房间里有两块外观、尺寸、高度都相同的绿色平台。黄色和紫色方块从相同高度释放：它们最后会停在同样的高度吗？先写下预测，再检查 `solid_platform` 与 `ghost_platform` 的定义。本课只改变“是否有 collision”这个关键条件，使用相同物理参数的两枚探针比较结果。

目标是读懂 SDF 的对象层级，理解看得到与接触得到的区别，并分清场景保存、运行状态和文件重载。

## 最少必要背景
`sdf` 是描述文档的根，`world` 是仿真世界，`model` 是可整体命名和放置的模型，`link` 表示刚体。link 下的 `visual` 交给渲染系统，`collision` 交给物理系统，`inertial` 描述质量分布。一个 link 可以组合多组几何，也可以有意只提供外观。右平台没有 collision 是有效的教学配置，不是缺字段就一定出错。

本课各物体都采用一个 link、零转角，几何中心与模型原点对齐；这是为了让落点能直接计算，并非所有模型的通用规则。平台中心高度1 m、厚度0.2 m，所以顶面高度1.1 m。探针高0.3 m，中心到下表面是0.15 m。

`static=true` 表示模型不由刚体动力学推进，适合墙体和平台；不是将质量改成一个巨大数字。静态模型有 collision 时仍能支撑动态物体。探针 `static=false`，因重力运动，接触后受约束而停下。

## 两条输入信息流
SDF中的 collision → 服务端碰撞检测与接触约束 → 探针速度和位置 → 状态消息。

SDF中的 visual、材质和状态消息 → Gazebo 客户端渲染 → 屏幕上的平台与方块。

左平台两条通路都存在；右平台只进入显示通路。颜色、透明度或贴图不会自动生成物理支撑。复杂模型可以用精细外观配简化碰撞，但应明确这种近似的用途。

## 文件检查与基准实验
1. 开始实验。在 Gazebo 窗口左侧实体树查看两平台与两探针，注意它不是应用的课程地图。
2. 窗口打开时探针可能已经落地。先“暂停”→“重置模型状态”，确认两探针回到初始高度，再“继续”观察。每次“重载项目”后都重复这个准备过程。
3. 查询两枚探针的实时位姿。先手算：黄色由左平台支撑，中心约1.25 m；紫色穿过右平台的外观，由地面支撑，中心约0.15 m，差值约1.10 m。
4. 点击“编辑练习文件”，在 `world.sdf` 中沿 world→model→link 的缩进寻找平台。对比两处 visual：它们相同；再找 collision：右平台有意没有。
5. 在 Gazebo 的 View/视图菜单打开 Collisions/碰撞显示，对照外观和碰撞几何。不同语言界面的菜单文字可能略有不同；观察目标是左平台有碰撞几何，右平台没有。

## 单变量修改与独立挑战
挑战A：在 `ghost_platform` 的 body link 内添加与其 visual 尺寸一致、中心对齐的 box collision，保留其他参数。先预测两枚探针都应停在1.25 m，再保存→“重载项目”→暂停并重置→继续验证。参考页给出具体位置和片段，不会替你覆盖文件。

挑战B：保持平台厚度0.2 m，只把左平台模型 pose 的 z 从1改为1.4 m。预测黄色探针中心应为 `1.4+0.2/2+0.3/2=1.65 m`。若右平台尚无 collision，紫色仍约0.15 m；若已完成挑战A，紫色约1.25 m。分别记录当前配置，不能混用两轮实验结果。

可选反例：只修改左平台的 collision 厚度，visual 不变，再打开碰撞显示。方块可能看起来悬空，但落点仍由 collision 顶面决定。这个差异有时是合理近似，有时是建模失误，需结合模型用途判断。

## 保存场景与重载入口
在 Gazebo 窗口用 File/文件→Save World As/另存世界，把快照保存到当前练习目录，例如 `room_snapshot.world`，再用文本编辑器检查其模型、位姿与描述内容。保存场景不等于保存所有插件内部状态、随机数状态或整个运行会话。

应用的默认重载入口仍是练习目录的 `world.sdf`。另存了 `room_snapshot.world`，下一次点击“重载项目”不会自动改为读取它。若希望将快照作为入口，应先保留自己的原文件，再明确把所需描述整理到 `world.sdf`。本课的“重置模型状态”也不会重新解析刚保存的文件。

## 排错和验收边界
穿透先查 collision 是否存在、尺寸和位置是否正确，再讨论求解器；不要首先把模型质量无限增大。修改后无变化，先检查是否编辑了当前工作副本、是否保存并“重载项目”。无碰撞平台本来就应被穿过；探针缺 collision 则无法得到本课预期落点。

自动验收读取当前工作副本，按实际平台碰撞顶面与探针半高预测落点；临时暂停并抬升两枚探针，确认位置后继续，检查真实稳定高度，最后恢复原暂停状态。补 collision 后两枚探针同高、调整平台高度后落点变化，都能按新配置正确验收。它会改变探针运行位置，执行时不要手动拖动模型。

人工项目包括展示实体层级、切换碰撞显示、解释 static 与 dynamic、另存并检查世界文件。自动验收没有替你评分这些 GUI 操作。增加桌子或更多墙体可以作为开放拓展，但不在本课两枚探针的自动评分范围。
