# 外观与碰撞：参考与预测

本页为只读参考，查看不会改变练习副本。先对照自己的预测，再通过“编辑练习文件”操作。

## 基准配置的两个高度
两平台的 visual 都是 `1 1 0.2` m、中心高度1 m、相同绿色材质。左右两枚探针都是0.3 m高、质量1 kg的方块，区别仅用颜色和名称标识。

左平台拥有 collision：碰撞顶面 `1+0.2/2=1.1 m`，探针中心高度 `1.1+0.3/2=1.25 m`。

右平台没有 collision：其外观不提供支撑；地面碰撞平面在 z=0，探针中心高度 `0+0.3/2=0.15 m`。两个落点差约1.10 m。实际值应与容差比较，不能要求二进制浮点逐位等于预测。

## 挑战A：给右平台补碰撞
在 `model name="ghost_platform"` 的 `link name="body"` 内、与 visual 同级的位置添加：

```xml
<collision name="collision">
  <geometry>
    <box>
      <size>1 1 0.2</size>
    </box>
  </geometry>
</collision>
```

不要把 collision 放到 visual 内，不要放在 model 下，也不要添加到 `ghost_probe`。这个片段没有单独 pose，因而采用 link 的默认相对位置。link 与模型原点已在本课模板中对齐。

保存并点击“重载项目”，之后先暂停、重置，再继续。此时两枚探针都约为1.25 m。自动验收会从你实际的工作副本读取新增 collision，计算新预测；它不会因为紫色方块没有落到0.15 m而拒绝正确的挑战答案。

## 挑战B：只改变左平台的高度
将 `solid_platform` 的模型 pose 改为：

```xml
<pose>-1 0 1.4 0 0 0</pose>
```

平台厚度仍0.2 m，探针高度仍0.3 m。黄色探针中心预测为 `1.4+0.1+0.15=1.65 m`。右平台无 collision 时，紫色仍0.15 m；已补 collision 时，紫色为1.25 m。

如果改变的是碰撞体 thickness 而不是模型中心高度，则公式相应为“碰撞体中心世界z + 碰撞厚度/2 + 探针高度/2”。visual 的厚度可以有意不同，只有 collision 参与这个支撑高度计算。

## 为什么 static 不等于没有碰撞
平台为静态模型，计算器不会用重力让它自由下落，但碰撞体仍属于物理场景的一部分，能够限制动态探针的运动。右平台虽然同样 static，却因为缺少 collision 而不提供支撑。由此可见，static/dynamic 和有无 collision 回答的是两个不同的问题。

## 文件与运行状态检查
编辑和保存改变磁盘文件；点击“重载项目”让服务器重新解析默认入口 `world.sdf`；“重置模型状态”只操作已经加载的对象。GUI 另存的 `room_snapshot.world` 是另一个文件，不自动替代默认入口，也不是所有插件内部状态的完整检查点。

自动验收的流程是：读取练习配置→预测两个落点→记录原暂停状态→暂停并确认→将探针抬到所有平台上方→继续真实落体→轮询稳定高度→恢复原暂停状态。预测和测量不符时，先排查是否已重载、碰撞是否覆盖落线，再看服务器日志。

人工展示仍包括实体树、碰撞显示与另存文件。本课不会根据“点击过某按钮”直接记为实验成功。
