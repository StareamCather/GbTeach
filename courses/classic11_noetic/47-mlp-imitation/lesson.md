# 附加专项47：MLP模仿学习，把真实专家轨迹变成反馈控制器

为什么训练集上的动作误差已经很小，滑块却仍可能振荡？这一课从一个可复查的小项目回答：采集专家在真实Gazebo中的状态与施力记录，用NumPy训练一个多层感知机，再让它亲自闭环控制滑块。

先修09课关节、10课PID；矩阵乘法和求导只需会读下面的维度与链式法则。MLP（Multi-Layer Perceptron，多层感知机）由全连接层与非线性激活构成。策略是把观察映射成动作的函数，本课动作是力，单位N。模仿学习利用专家示范；其中行为克隆（Behavior Cloning，BC）把“专家当时做了什么”作为监督标签。这里没有奖励函数，也不靠试错搜索专家控制律。[imitation项目的BC说明](https://imitation.readthedocs.io/en/latest/algorithms/bc.html)可作为术语背景，本课无需安装该框架。

## 物理问题与已知结构

蓝色滑块质量1kg，由沿X轴的prismatic joint约束，行程±1.2m，关节粘性阻尼0.4N·s/m，施力限制±8N。绿色标线是零位参考线，不随测试目标移动。滑块关闭重力作用，输入直接来自原生关节位置、速度；这使我们能先分清学习控制与视觉感知。SDF的物理步长为1ms。

专家给定为：

```text
e = target - x                       # m
u_expert = clip(6 * e - 3 * v, -8, 8) # N
```

位置误差项负责拉向目标，速度项负责制动。例：target=0、x=0.5m、v=-0.4m/s，得到u=-1.8N。向左运动已经帮助滑块接近目标，因此制动项为正。先在纸上检查这个符号，再看实际轨迹。

策略输入为原始特征s=[target-x, v]，再按固定物理尺度归一化。只用这两个特征，是人为加入了**平移不变的结构先验**：在未接触行程限位、物理参数不随位置改变的区间，相同相对误差和速度应给出相同动作。训练专家轨迹的target均为0；测试target改变，并不表示网络从未见过的任务描述中自行理解了目标，目标已经通过误差计算进入网络。

真实闭环测试都从x=0、v=0开始，目标分别为−0.3m和+0.3m，每个目标170次动作。它们是训练中未使用的目标；不要把“新初始位置、目标仍为0”的实验说成新目标测试。分清二者，才能准确描述证据范围。该台架验证的是一维、已知状态、固定质量和阻尼下的模仿控制；它不足以证明机器人能处理图像、接触、未知负载或任意任务。

## 文件与真实转移的信息流

| 文件 | 内容 |
|---|---|
| `world.sdf` | 实际滑块、滑动关节、惯性、阻尼、限位和物理步长 |
| `plant.cc` | Classic原生ModelPlugin、会话私有socket、实际施力与受控步进 |
| `plant.py` | 有超时的Python客户端、状态/动作检查及特征提取 |
| `network.py` | 2→12→1的MLP、显式反向传播和梯度更新 |
| `lab.py` | 专家采集、按episode划分、训练与真实闭环验收 |
| `learner.py` | 学员填写的前向计算和损失导数 |
| `reference.py` | 独立的两处代数答案；不自动填入个人练习 |
| `prepare.py` | 在个人副本编译本课插件，记录构建来源 |
| `results/run-<uuid>/` | 每次独立保存的专家数据、训练记录、策略、闭环轨迹与报告 |

开始实验后，平台准备个人练习、编译插件并启动Gazebo；编译缓存对应源码与SDK，不覆盖个人`learner.py`。程序通过本会话的Unix socket控制当前实验，不连接其他Gazebo世界。

运行过程分三段：**真实专家采集→固定数据上的监督训练→真实学习策略闭环**。Python不积分滑块动力学。每个动作交给原生插件，Gazebo/ODE推进实际物理，返回原生关节状态，再计算下个动作。训练完成后把权重保存并重新加载，再由MLP独立产生控制动作；闭环过程中不调用专家来纠错或接管。

本课的离散接口在暂停世界中请求`World::Step(20)`：一次动作对应20个1ms物理步，名义仿真间隔0.02s。插件从独立工作线程提出步进请求，更新回调只负责每个物理步施力；不能在同一个物理更新回调里阻塞等待世界自己完成步进；[Classic World::Step源码](https://github.com/gazebosim/gazebo/blob/gazebo11/gazebo/physics/World.cc#L807)展示了其等待逻辑。前后原生Iterations和施力回调次数均必须相差20，仿真时间差必须等于20×原生dt。客户端还核对上次读回与这次动作前快照一致，再用另一条`state`请求核对动作后快照。该RPC读取插件在真实`UpdateEnd`保存的快照缓存及版本，不是第二个独立物理传感器或另一套动力学API；它用于发现协议间隙的状态变化，不能只凭Python循环计数认定产生了20个真实步。

因此CPU训练所需墙钟时间不会让滑块在后台自由滑行，普通GUI刷新也不是控制采样。运行前保存世界的原暂停状态，结束后恢复；不要在训练过程中同时点击GUI的继续/单步或启动另一个控制客户端。墙钟超时表示请求结果可能未知，不代表Gazebo已取消，也不能自动重发动作。正常结束使用`end`请求确认暂停状态恢复；结果未知时仅断开连接让原生端收尾，报告标记恢复未确认，不再发送可能与未完成Step竞争的结束请求。遇到这种错误应结束本次实验、查看日志并重启，而不是继续使用旧状态。

## 一行数据到底是什么

一个episode是一段从指定起点连续运行的轨迹；一个row是一轮“观察→专家动作→真实推进→新观察”。默认10个episode，每段60次转移，共600行。起点既有正负位置，也有非零初始速度，避免数据只有“静止时朝原点推”的单一情况。

先从`results/imitation-report.json`的`data`找到本次`results/run-<uuid>/expert.json`，其顶层包含归一化尺度、episode划分、完整性标志和`rows`列表。逐行核对：

| 信息 | 含义与检查 |
|---|---|
| `episode`、`step` | 哪段轨迹、第几次动作；不能把它们当状态输入 |
| `x_m`、`v_m_s`、`target_m`、`features` | 动作前原生位置/速度、位置目标及已经归一化的两维特征 |
| `expert_force_n`、`expert_action_normalized` | 根据动作前状态计算的专家力及力/8N监督标签 |
| `before`、`after` | 原生快照，含`sim_time_s`、`iterations`、`callbacks`、`x_m`、`v_m_s`、`paused` |
| `transition` | 请求编号、实际力、步数、物理dt及完整原生确认；迭代数和施力回调数均应增加20 |
| `independent_native_readback` | 动作后另一条`state`RPC读取真实UpdateEnd快照缓存，确认版本/数值与动作后一致；不是另一个物理API |

专家力必须由动作前的状态计算。把`after.x_m`混进输入，会把未来信息泄漏给策略，部署时根本拿不到同样的信息。也不要用最终是否接近目标来倒写每步专家标签。

采集时的`reset`把指定关节位置/速度交给物理线程设置，并真实执行一次`World::Step(1)`，再读取结果。这个辅助1ms物理步包含阻尼等实际作用，返回的初态可能与请求值有微小差异；后续专家动作依据返回值，而非把命令值伪装成测量值。请求与前后原生快照均保留：报告的`reset_observations`列出`requested_x_m/requested_v_m_s`、`actual_x_m/actual_v_m_s`和完整`native_reply`；闭环trial还保存`actual_initial_state`与`reset_native_reply`。

默认有10次专家起点重置、2次闭环起点重置，辅助步与940次标准20步动作分开统计，预期总物理步为940×20+12=18812；核验应读实际报告，不能忽略这12步或把它们算成训练样本。episode边界必须保留，不能把上一段终点与下一段起点当成连续动力学。这也不是把整个世界的时钟回拨到0。

## 整段留出与固定物理尺度归一化

整段episode0—7的480行训练；整段8—9的120行留出。邻近时刻的状态高度相关，如果把600行随机打散，很可能把一条轨迹的相邻样本同时放进训练和测试，得到过于乐观的误差。

本课留出集来自两段完整专家轨迹，与真实闭环测试还不同。两段数据量很小，不能用于推断广泛任务分布上的成功率。如果你反复看它调学习率或网络大小，它实际上已经成为验证集；严谨比较还需要另留最终测试轨迹。

位置和速度的单位不同。我们事先选定物理尺度，把输入与动作转成便于优化的无量纲数：

```text
Z[:, 0] = (target - x) / 1 m
Z[:, 1] = v / (2 m/s)
y = expert_force / 8 N
```

这些尺度在采集前已经确定，不从训练或留出样本估计；因此本课没有“用整个数据集拟合均值/标准差”的步骤。它也不保证每个新输入都在[−1,1]内。网络输出预测归一化动作a，执行时转换成力u=8N×a，再限幅±8N；尺度与结构先验写入报告，尺度元数据也随策略NPZ存储，部署必须使用同一变换。

常见的z-score标准化则是(s−训练均值)/训练标准差，与这里的固定尺度归一化不同。如果你把它作为拓展，必须先拆分，再只用训练集拟合均值/标准差、保护零方差，并保存到部署文件；不能每个新状态重新拟合。[NumPy标准差定义](https://numpy.org/doc/stable/reference/generated/numpy.std.html)可帮助核对`axis`与默认`ddof=0`。归一化改善优化尺度，不能修复错误单位、错误符号或分布外状态。

## 从矩阵前向到一次更新

N是批次样本数。输入Z为[N,2]；隐藏层12个单元，输出只有一个归一化动作：

```text
A = Z @ W1 + b1       # [N,12], W1:[2,12], b1:[12]
H = tanh(A)          # [N,12]
a_hat = (H @ W2 + b2).reshape(-1) # [N], W2:[12,1], b2:[1]
L = mean((a_hat - y)^2) # y = expert_force / 8 N
```

偏置通过广播加到每一行。tanh提供非线性，输出层保持线性，允许正负归一化动作。实际施力前乘以8N再限幅±8N；该执行器保护不能代替学习正确动作。训练损失是归一化动作的均方误差（MSE），无量纲；报告中的留出力MSE乘回8²，单位N²，平方根才与力同单位。[NumPy矩阵乘法](https://numpy.org/doc/stable/reference/generated/numpy.matmul.html)和[tanh](https://numpy.org/doc/stable/reference/generated/numpy.tanh.html)可帮助核对操作。

反向传播按链式法则，把输出误差传回参数。令D=2(a_hat-y)/N，并整理成[N,1]列向量，则：

```text
grad_W2 = H.T @ D
grad_b2 = sum(D, axis=0)
dA = (D @ W2.T) * (1 - H**2)
grad_W1 = Z.T @ dA
grad_b1 = sum(dA, axis=0)
```

计算所有梯度后再更新参数，不能更新W2后又用新W2计算隐藏层梯度。默认参数初始化seed=7，全批次更新2600次，学习率0.025；不是2600次Gazebo动作。固定seed便于本机复查，不证明跨随机种子的鲁棒性。普通梯度下降为theta←theta−learning_rate×gradient。

实现先把四组参数梯度合起来计算总L2范数；超过5时，所有梯度乘以同一个缩放系数，使方向保持、总范数受限。这是全局梯度范数裁剪，和逐元素裁剪、动作限幅是三件事。它能限制一次更新的步幅，不能证明训练必然收敛，也不能替代合理学习率。

## 第一遍：运行完整参考实验

在本课终端先确认原生接口，再执行：

```bash
python3 lab.py ready
python3 lab.py demo
```

程序先在Gazebo采集专家数据，再做NumPy训练，最后从静止零位分别向两个未训练目标测试学习策略。观察报告里的原始轨迹，而不只看GUI是否“到了附近”：

- `test_mse_before/after`（N²）：策略在整段留出轨迹上，换回实际力后的动作与标签差多少；训练记录的`training_mse_normalized`仍无量纲。
- 真实闭环轨迹：策略施力改变状态后，下次又会访问什么状态。
- `terminal_error_rms_m`、`terminal_velocity_rms_m_s`、`peak_abs_x_m`：最后30步相对目标的误差、速度和全程位置幅值；不要用x本身代替x−target。默认验收分别要求<0.07m、<0.12m/s、<0.95m，并要求实际位移>0.2m；它们是本课任务门槛，不是稳定性定理。
- 原生步数与时间：每个请求是否推进了规定的实际物理步。
- `execution_mode`、`assignment_pass`：参考演示与个人作业是否区分。

`results/imitation-report.json`和`build/verification.json`指向最近一次结果；每次独立`results/run-<uuid>/`保留`expert.json`、`training.json`、`imitation-policy.npz`、`rollouts.json`、`report.json`。策略还记录SHA256，正常报告包含暂停恢复确认；失败报告也保存原因。参考演示即使物理验收通过，也保持`assignment_pass=false`。比较实验时沿报告中的路径找对应运行，不把旧快捷报告当成本次成功。

真实闭环误差比静态MSE多了一层问题：稍小的动作误差会改变下一时刻的位置/速度，使策略遇到专家数据中较少出现的状态，随后误差可能继续累积。这称为分布偏移。低留出MSE不等于稳定性证明；有限初始条件的成功也不等于任意状态均收敛。[Ross等人的DAgger原论文](https://proceedings.mlr.press/v15/ross11a.html)讨论了这种序列决策中的分布问题，本课没有实现DAgger。

## 两处关键代码练习

只填写个人`learner.py`中的两处`raise NotImplementedError`，先保留其它接口。

1. `forward(X,W1,b1,W2,b2)`：输入已经是固定尺度归一化特征，返回[N]预测归一化动作；要同时支持单样本[2]和批次[N,2]。提示：先用`np.atleast_2d`统一批次维，再按上面的矩阵尺寸走两层；不要再做一次归一化或在这里乘8。
2. `mse_derivative(prediction,target)`：返回单样本平方损失对归一化预测动作的导数。这里参数名`target`指监督动作标签，不是滑块的位置目标。提示：先从标量(a-b)²求导，再让NumPy逐元素执行。批次平均由`network.backward`统一除以N，不能除两次。

```bash
python3 lab.py student-check
python3 lab.py student
```

`student-check`检查代数和接口，仍为`assignment_pass=false`。`student`先检查个人函数，再重新采集、训练，用个人实现产生控制动作并接受真实物理验收。只有这条完整路径成功才能记个人作业完成；把参考报告改成true没有意义。

不要把输出层也改成tanh却沿用当前反传：这会同时改变归一化动作范围与导数。个人前向若用了与`network.backward`不同的激活，训练计算图就不一致。确认矩阵尺寸→手算一个损失导数→对比单元检查→最后运行真实闭环，是比盲调训练轮次更有效的顺序。

## 预测、单变量比较与诊断

每次先写预测，只改一个因素，保存新旧配置和报告；探索修改后，恢复默认配置再做本课作业验收。

| 只改变什么 | 先预测与观察什么 |
|---|---|
| 训练更新2600→100次 | 留出动作误差、正负两个目标的末段误差是否一起变差；不要只看训练loss |
| 学习率0.025→0.01 | 固定2600次时是否更慢；梯度裁剪是否真的在触发 |
| 缩小采集初始位置/速度范围 | 固定闭环条件，哪些状态超出训练覆盖，错误先出现在何处 |
| 只改变一个闭环目标 | 区分目标变化与起点变化；比较相同相对误差下的动作 |

可以另开一份实验删除速度输入的有效信息，但必须让训练、留出与闭环采取完全相同的特征处理。此时位置相同而速度不同的样本会要求不同制动力，不能仅靠更多轮次补回被丢掉的信息；这不是默认验收路径。

“socket连接失败”：确认本课实验已开始、使用本课终端、插件编译/加载成功，不复制别的会话token。“步数不是20/世界非预期继续”：停止并重启实验，排除GUI或第二客户端干预，不重发未知结果的动作。“shape不匹配”：列出[N,2]→[N,12]→[N,1]→[N]，留意[N]与[N,1]相减可能广播成[N,N]。“loss低但运动差”：查输入/输出尺度、速度符号、未见状态、命令限幅与实际20步间隔，再画x、v、u随**仿真时间**的曲线。“恢复后突然移动”：训练结束可能恢复原先运行状态，惯性速度不会因Python退出而自动消失。

## 独立挑战

先做线性回归基线，与MLP用同一episode划分、归一化和真实闭环条件比较。本课专家在未饱和区就是线性PD，复杂网络并不天然优于简单模型。随后可做多目标切换、增加质量扰动、扩展专家覆盖，分别解释是特征先验、动力学改变还是数据覆盖导致差异。

更进阶的挑战是：让当前策略在真实Gazebo中访问状态，再请专家为这些状态标注动作，保留每轮数据来源，研究数据聚合能否缓解分布偏移。先明确查询预算、独立最终测试与危险状态边界，再讨论算法；不要把一次成功轨迹当成通用学习控制结论。下一个专项将研究不用专家动作标签的奖励学习，与本课区别在于训练信号。
