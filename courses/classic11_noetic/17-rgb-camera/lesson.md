# RGB相机：像素如何对应三维世界

同一块红色板，离相机更远时在图像里变小，向世界+Y移动时却往图像左边走。再把分辨率加倍，像素面积会变大，物体本身有没有变大？本课用红、绿、蓝三个已知尺寸的目标，把真实渲染图像、相机参数与三维几何联系起来。

这里使用Gazebo Classic camera和系统Noetic相机插件，图像来自真正的渲染采样。程序读取实际ROS Image与CameraInfo，分析颜色区域并保存原始帧，不根据公式画一张“应该看见的图”充作相机输出。你不需要先学神经网络、目标检测或相机标定算法。

## 先看到本课相机真正拍到的画面

相机位于世界(0,0,1) m，朝+X看。默认图像320×240像素，水平视场60°，目标更新率20 Hz。Gazebo观察窗口是你从外部看场景的视角；它与这台传感器拍到的图像不是同一个窗口。

```sh
python3 lab.py observe --seconds 3
python3 lab.py view
```

observe进行有界数据观察，view打开本课ROS图像查看器。请确认画面里有中央红色板、偏右绿色板和偏上蓝色板；即使能在Gazebo外部窗口看到目标，也必须检查真实相机画面，不能把服务器存活当成图像课程通过。

两路主题是`/lesson17/camera/image_raw`与`/lesson17/camera/camera_info`。查看器关闭即可结束，也可运行`python3 lab.py view --seconds 3 --capture build/my-camera.png`限时观察并保存实际图像；PNG来自本次接收的真实字节，屏幕窗口大小不会改变相机原始分辨率。

相机需要可用的图形渲染上下文。没有gzclient窗口也不代表渲染相机不需要图形设备。暂停时没有新的仿真采样，查看器可能继续显示最后一帧；那不等于传感器还在不断拍新照片，应同时看时间戳。

## 一张Image是怎样存成字节的

**像素（pixel）**是图像的离散采样位置。用(u,v)表示列和行，左上角是(0,0)，u向右、v向下；默认有效范围是u=0…319、v=0…239，不是1…320。

| 字段 | 含义 | 本课要检查什么 |
| --- | --- | --- |
| width、height | 每行像素数、行数 | 默认320、240，修改分辨率后两者相应变化 |
| encoding | 通道顺序、位深与解释方式 | 本课rgb8，每通道8位，顺序R、G、B |
| step | 一整行占用的字节数 | 本课紧密排列时为3×width，一般图像也可能有行填充 |
| is_bigendian | 多字节数值的字节序标志 | 本课为0；rgb8每通道仅1字节，不因此交换RGB顺序 |
| data | 实际像素字节 | 大小应为height×step |
| header | 图像时间与光学坐标系标签 | 要与同帧CameraInfo匹配 |

本课像素起始偏移为`offset=v×step+3×u`，随后三字节是R、G、B。**stride（步幅）**就是跨过一整行时要前进的字节数，不能在所有图像里都假定step等于width×通道数。先读encoding和step，再解释data，详见[ROS Image定义](https://github.com/ros/common_msgs/blob/noetic-devel/sensor_msgs/msg/Image.msg)。

RGB与BGR都可以是三通道，但红蓝位置相反。部分图像工具采用BGR默认顺序，直接把rgb8当BGR会让红板变蓝；改一个文件扩展名不能修复通道解释。PNG是保存图像的文件编码，ROS Image的rgb8则是未压缩像素格式，两者也不是同一个概念。多字节深度图的字节序将在后续深度课继续。

## 从三维物体到两个消息

```text
个人world.sdf中的几何、材质、灯光与相机参数
  → Gazebo原生camera实际渲染
  → Noetic相机插件
  ├─ Image：实际像素
  └─ CameraInfo：相机模型参数
  → 按相同时间戳配对
  → 颜色区域统计、几何比较与真实帧保存
```

RGB相机依据visual和渲染场景，不是CPU ray使用的collision射线。图像中看得见的区域不自动等于可碰撞区域，第15课的两种几何来源在这里仍然重要。本课使用自发亮的固定颜色目标降低照明变化，便于先研究几何；阈值分色不等于通用视觉识别，也不模拟真实传感器完整的光照、曝光和噪声过程。

## 机体坐标与光学坐标

本课Gazebo相机朝+X，常用机体约定为+X前、+Y左、+Z上；ROS图像的**光学坐标系（optical frame）**则是+Z前、+X右、+Y下。它们描述同一组空间方向，轴的名字和符号不同，见[REP103相机坐标约定](https://github.com/ros-infrastructure/rep/blob/master/rep-0103.rst)。

对于已变换到相机机体原点的点(x_body,y_body,z_body)：

```text
X_optical = −y_body
Y_optical = −z_body
Z_optical =  x_body
```

本课相机轴与世界轴对齐、原点在(0,0,1)，所以世界+Y使目标往图像左移，世界+Z使它往图像上移。不要只看到“+Y”就沿图像行号向下推。插件的frameName仅填写标签，不会自动发布TF，也不会因把标签换成world就旋转像素；把图像用于机器人系统时还须建立正确安装变换，第24课继续。

## CameraInfo与针孔模型

**针孔模型（pinhole model）**用透视投影描述三维点怎样落到图像上；**内参（intrinsics）**包含以像素为单位的焦距与主点等参数。光学坐标中Z>0，当前零畸变单目模型为：

```text
u = fx × X/Z + cx
v = fy × Y/Z + cy

K = [fx, 0, cx
      0, fy, cy
      0,  0,  1]
```

| CameraInfo字段 | 作用 | 本课设置 |
| --- | --- | --- |
| K | 原始图像内参矩阵，行优先3×3 | fx=fy，主点由本版本插件生成 |
| D、distortion_model | 镜头畸变系数与模型 | plumb_bob五项为0，先研究理想透视 |
| R | 校正旋转矩阵 | 单目本课为单位矩阵，不是世界到相机的外参 |
| P | 校正图像的3×4投影矩阵 | 本课左3×3对应K，单目平移项为0 |
| width、height | 这些参数对应的图像尺寸 | 应与同帧Image一致 |

[CameraInfo定义](https://github.com/ros/common_msgs/blob/noetic-devel/sensor_msgs/msg/CameraInfo.msg)中，K[0]=0可表示未标定；不能拿没有有效内参的图像直接套投影。这里内参由已知仿真配置产生，不是程序从照片估计完成了一次真实相机标定。畸变系数也不代表深度、物体大小或图像噪声。

不了解针孔投影和相机内外参，可看[OpenCV官方相机模型说明](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html)中的几何图解；本课先用现成参数验证投影，不要求提前完成标定作业。

本版[Noetic CameraUtils](https://github.com/ros-simulation/gazebo_ros_pkgs/blob/noetic-devel/gazebo_plugins/src/gazebo_ros_camera_utils.cpp)默认采用`f=width/(2tan(HFOV/2))`、`cx=(width+1)/2`、`cy=(height+1)/2`，其中HFOV取相机实际读回值。名义60°的理想计算f约277.1281像素；本设备加载链会将弧度数以6位有效数字写回，实际HFOV为1.0472 rad，收到的f约277.1273，主点仍为(160.5,120.5)。这点小数差来自实现的数值舍入，不能要求名义角度的无限精度计算与它逐位一致。检查程序按当前SDK的有效角度核对元数据，像素投影使用实际收到的K，不改写真实图像或CameraInfo；详细来源见参考答案。不同库的像素中心约定与实际栅格化也须区分，不能偷偷修改主点来凑像素。

## 同一块板的四阶段实验

红板尺寸为厚0.04 m、宽0.6 m、高0.6 m，默认中心(3,0,1) m。相机看到的正面位于X=2.98 m，预测尺寸要用这个表面深度，而不是只用模型中心X=3。

| 阶段 | 红板中心/m | 应观察什么 |
| --- | --- | --- |
| baseline | (3,0,1) | 中央红色区域，建立基线 |
| farther | (4,0,1) | 正面深度从2.98变3.98，区域缩小 |
| lateral | (3,+0.5,1) | 世界+Y移动，区域往图像左移 |
| restored | (3,0,1) | 回到配置基线，图像观测重新吻合 |

正面平行于成像面时，投影宽约为`f×0.6/depth`，高同理；深度增加时，宽高按1/depth缩放，面积按1/depth²缩放。因此红板移远1 m后，宽高约为原来的0.749，面积约为0.561；不能把“宽度缩小比例”直接当作“面积比例”。离散像素计数不要求与连续公式逐位相同。

板有有限厚度，横移后还可能看到侧面。上述尺寸是理解变化的正面近似；完整验收将盒体八个角投影到图像，再求整体包围盒，与真实像素作有容差的比较，不假装一个二维平面能精确覆盖所有侧面。

绿色板位于世界Y=−1，图像中偏右；蓝色板位于世界Z=1.9，图像中偏上。它们提供方向与颜色的固定参照，防止只见红色面积变化就忽略坐标或通道错误。

```sh
python3 verify.py
```

验收记录进入时红板的真实位姿、速度与暂停状态，明确建立上述四阶段位置，随后从实际图像测量区域像素数、包围盒与中心。它会同时核对真实模型状态及相同时间戳的Image/CameraInfo；阶段设置不是受力推动的连续运动，不能把重定位跳变当作动力学轨迹。最后恢复**进入验收时**的真实红板状态和原暂停状态，世界时间不倒回。测量时不要同时拖目标、重置或运行另一套控制。

每阶段先经过0.2仿真秒传播保护，等到第一帧画面符合新位置后，取得至少12对不同时间戳数据、跨度至少0.5 s，配对频率为15到25 Hz。红色包围盒中心距八角点预测不超过2.5像素，宽高误差不超过3像素，颜色区域质心距预测包围盒中心不超过3像素；这些是本课有限像素比较容差，不是经过标定的亚像素精度。

原始报告为当前会话的rgb-verify-唯一编号.json，终端打印trace_path与assets_dir；相邻的报告名-assets目录按SHA保存原始.rgb字节，并保存四阶段真实PNG。也可用`python3 verify.py --report build/my-rgb-check.json`指定位置。移动后面积比与预测相差小于0.07、横移中心u至少减少20像素、恢复后的平均红色像素数距基线不超过2，连同原始帧一起保留用于复核。

## 保存参数与运行状态是两种操作

本课world.sdf是实际个人输入，准备工具检查它，不重写你的场景。一次只改变一项、保存后重载：

```sh
python3 lab.py config --width 640
python3 lab.py config --fov 75
```

width=640同时保持本课4:3比例，height随之为480；同一FOV下焦距像素值约加倍，目标宽高像素数约加倍、像素面积约四倍，物体的米制尺寸与位置没有改变。HFOV 60→75°时，同一分辨率下f变小，视野更宽、目标占据的像素更少；这与把目标移远有相似的尺寸变化，却是不同的三维原因。

要只操作本次运行中的红板，可执行`python3 lab.py target --x 4 --y 0`；它明确重定位这个目标并保留原暂停状态，不修改保存的起点。结束后可回到`--x 3 --y 0`，或重载。提高分辨率不等于获得深度、提高光学测量精度或改变实体焦距毫米数；fx在这里以像素为单位。

## 时间戳配对与图形证据

Image与CameraInfo通过两个主题传输，收到的先后顺序不保证对应；程序按相同header时间戳配对，并检查frame和尺寸一致。不能用“最近收到的一组参数”去解释任意旧图像，更不能将Gazebo外部窗口的截图冒作传感器原始帧。

本版插件的CameraInfo发布还受到图像订阅门控影响，单独echo camera_info可能没有输出。lab.py的ready、observe和view会同时订阅两路；先打开其中之一，再在另一终端查看CameraInfo，避免将订阅条件误判成参数不存在。

原生camera目标20 Hz，插件updateRate=0表示不再额外限流，并不表示相机无限快。[Noetic相机实现](https://github.com/ros-simulation/gazebo_ros_pkgs/blob/noetic-devel/gazebo_plugins/src/gazebo_ros_camera.cpp)使用传感器测量时间，实际频率应从不同图像时间戳的首末跨度估计；电脑墙钟接收频率还受实时因子和渲染负载影响。

原始Image像素、CameraInfo和保存的PNG分别说明字节内容、相机模型与可读画面，三者互补。颜色统计来自真实帧，只适用于本课这些已知颜色与背景；自动通过不代替你实际查看清晰图像和解释单变量结果。

## 文件、故障与独立挑战

| 文件 | 职责 |
| --- | --- |
| world.sdf | 真实相机、三色目标、材质和场景 |
| prepare.py | 检查输入与系统相机/分析依赖 |
| lab.py | 字节解码、观察、查看图像、局部参数编辑与目标操作 |
| verify.py | 四阶段真实采样、几何比较、原始帧保存与恢复 |
| reference.md | 只读矩阵推导、数值预测及练习提示 |

| 现象 | 先检查什么 |
| --- | --- |
| Gazebo看得见目标，相机图像却黑 | 真实相机朝向、视场/裁剪、Image新鲜度与服务器渲染 |
| 红板显示成蓝板 | encoding与RGB/BGR解码顺序，别只改颜色阈值掩盖错误 |
| 图像错行或撕裂 | step、height、data字节数与通道数 |
| +Y目标竟往左 | 先区分世界/机体轴与光学轴，这是当前配置的正确方向 |
| 预测尺寸差一点但方向正确 | 表面深度、内参主点约定、栅格化与有限像素容差 |
| CameraInfo正常，图像没更新 | 真实图像订阅、世界是否暂停、渲染与插件日志 |
| 调分辨率后计算全错 | 新图像尺寸与同时间戳内参是否一起更新，是否重载 |
| 有optical标签但TF报错 | 标签不自动产生安装变换 |

独立挑战：从一帧真实rgb8图像中读取中心像素和红色区域，报告区域中心的归一化光线`((u−cx)/fx,(v−cy)/fy,1)`。提示一：按step定位字节；提示二：先与同帧CameraInfo配对；提示三：这只确定方向，单张RGB图像通常不能凭一个像素唯一确定目标深度。已知板宽可以增加额外几何约束，但须说明用了哪些先验，而不是声称RGB像素本身带有米制距离。
