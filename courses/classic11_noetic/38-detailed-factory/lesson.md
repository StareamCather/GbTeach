# 附加专项 38：把工厂场景做细，同时让碰撞保持可解释

这个项目保留原来所有课程，另做一座可离线打开的小工厂：货架、箱体、工作台、带螺栓与百叶细节的机床、后墙门洞、托盘和有意保留的碰撞空隙。你要回答：**一个视觉上连续的包装面，为什么能被球穿过？做细了外观，是否必须做细碰撞？**

## 实验前先做预测

开始后，三颗半径 0.08 m 的球从 2.3 m 落下。默认工作台高 1.0 m、托盘条高 0.4 m。写下球心最终高度：工作台上应为 1.08 m；托盘条上为 0.48 m；两条之间的空隙中为 0.08 m。最后一种球会穿过托盘上方的透明包装面，因为包装只有 `visual`，没有 `collision`。

这是故意设置的诊断样本。工程项目需要根据用途决定包装是否参加碰撞，不能靠画面猜测。

## 四套描述不要混在一起

- `visual` 决定可见表面、材质、网格和阴影，也影响相机图像。
- `collision` 决定接触求解的几何；雷达具体查询路径也可能依赖碰撞几何。
- `inertial` 决定质量、质心与惯性矩阵。把外壳网格换成更精细的版本，并不会自动算好质量分布。
- `pose`、link 层级与网格自身原点一起决定各部分的位置。导入后大小正确而方向错误，通常先查坐标系，而不是改重力。

静态货架不要求设置动态惯性。落球是动态刚体，给出了正质量与球体惯性 `I = 2mr²/5`。机床外观由多个闭合小长方体组成，碰撞采用一个简化长方体；细小螺栓与百叶不参加接触求解。这种碰撞代理是有边界的近似，不能拿它验证抓手是否能插入机床内部。

## 文件与信息流

| 文件 | 作用 |
|---|---|
| `parameters.json` | 个人练习参数：台面高度、托盘高度、机床宽度和货架通道宽度 |
| `scene.py` | 参数→静态装配与落球 SDF；启动准备时重新生成 `world.sdf` |
| `mesh_builder.py` | 独立的离线网格导出器；闭合箱体→带法线与 UV 的 COLLADA |
| `models/factory_detail/meshes/cell.dae` | 已附带的米制、Z 向上机床外观网格 |
| `native/probes.cc` | WorldUpdateEnd 后读取三个真实模型的位姿与速度 |
| `verify.py` | 等待实际球体稳定，将真实高度与个人参数中的预测比较 |

运行流程是：读取并检查有限参数→生成个人场景→按源文件哈希缓存编译观察插件→启动真实 Gazebo→物理求解→插件读取真实球心与速度→写入本会话的 `physics.json`→验收比较。插件不把预测高度写回模型，也不替物理引擎摆放球。

`prepare.py` 会重新生成 `world.sdf`。因此本课主要修改 `parameters.json` 和 `scene.py`；不要把未保存到生成器中的世界文件修改当作持久输入。个人机床 `cell.dae` 不会被启动流程重写。

## 按步骤做项目

1. 点击“开始实验”。展开 `World → Models`，找到 `cnc_cell`、`table_surface`、`pallet_strip_*` 和 `probe_*`。
2. 点击“运行真实行为验收”。报告应包含三组实际高度、速度、模型总数和网格字节数。
3. 在 Gazebo 菜单中显示碰撞几何，观察机床的简化碰撞体，以及包装面没有碰撞这一事实。GUI 显示位置随版本/菜单布局略有差异，也可选中模型逐层查 link 的 collision。
4. 缩近观察机床：外壳、机床床身、两列螺栓与百叶片。旋转视角检查是否有反面消失或错误法线。
5. 将 `table_height_m` 从 1.0 改为 1.2，先预测新球心高度 1.28，再重启实验、验收。
6. 把 `aisle_width_m` 增加 0.4。两排货架沿 y 方向各移开 0.2 m；货架深度为0.8 m，中心取 `±(aisle_width_m/2 + .4)`，所以两排内侧面净距恰好等于该参数。机床、工作台等独立工位仍占用部分地面，不把这个净距称作经过机器人通行认证的道路。三颗探针位置保持为测量工位，不随货架移动。

### 深入制作一次真正的网格修改

在操作终端运行 `python3 mesh_builder.py` 可重建默认机床网格。打开脚本，查看 `boxes` 中每个六元组 `(cx, cy, cz, sx, sy, sz)`；全部单位为米。将百叶数量从 15 改为 9，并保留机床总体尺寸。每个闭合箱体输出 12 个三角形，边界处共享位置但保留各面的独立法线与 UV；这是硬表面棱角保持清晰的一种直接做法。

重新运行生成器并重启实验。球的物理结果不应变化，因为改的是视觉细节。若改变机床大尺寸，应同步调整碰撞代理与需要避障的通道，不能只缩放 visual。

## 三个容易被忽略的精度问题

**单位。** CAD 常用毫米，Gazebo 使用米。本课 COLLADA 明确 `unit meter="1"`。把 1600 mm 直接写为 1600 会得到千倍尺寸。只在 SDF 外层乘 0.001 能修视觉大小，却不能自动修质量与惯性。

**网格复杂度。** 对静态房间，很多共面的微小三角形只增加加载与渲染负担。先用盒体描述墙、台面、立柱，再把会改变轮廓的细节加入 visual。碰撞是否需要细节由教学问题决定。

**纹理密度。** UV 把模型表面映射到二维图像。不同零件共用材质时，单位米对应的纹理像素数应接近，否则一边清晰、一边模糊。下一附加课会用真实相机测量平铺频率。

## 错误诊断

| 现象 | 先查什么 |
|---|---|
| 网格不显示，碰撞还在 | `model://` 模型目录、DAE 路径、材质绑定、法线朝向 |
| 机床放大后球验收仍通过 | 探针测量的是台面与托盘；它不认证所有网格尺寸，应另量机床包围盒 |
| 球停在空中 | 查看落点处是否有意外 collision，是否误给包装加了碰撞 |
| 改台面后验收失败 | 是否重启实验，让参数生成出的 SDF 与当前服务器一致 |
| 视觉被遮挡但球能穿过 | visual 与 collision 的差异可能正是配置本身，而不是求解器错误 |

## 独立挑战与验收边界

检查现有后墙门洞：左右墙段和上门楣是三个 box collision，净宽1.4 m、净高2.1 m，门洞为空。仿照它改变门宽、门高，并同步推导三个墙段的位置和尺寸。不要以一个完整包围盒覆盖门洞。再放置一个直径小于门宽的球，设计真实穿越实验。说明你选择哪些装配细节进入碰撞，哪些只进入 visual。

自动验收证明三组落球的真实支撑关系与高度。机床轮廓、法线、装配美观、材质与 GUI 碰撞显示仍需要视觉检查；模型数量或插件加载成功不替代这些目标。
