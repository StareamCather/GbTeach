# M23 · ROS 2服务、动作与滑轨闭环

读取滑块当前位置只需一次问答。让滑块移到目标位置则要持续观测状态，中途还可能取消。两种需求分别使用ROS 2服务和动作。课程把它们接到Harmonic中的真实滑动关节，再用节点参数调整控制增益。建议先完成M22的ROS图与QoS。

## 请求、反馈与实际物理状态

| 接口 | 本课用途 | 怎样确认完成 |
|---|---|---|
| 服务 | 取一次当前滑轨状态 | 收到与本次请求对应的响应，核对读数与来源 |
| 动作 | 给滑块一个目标，并观察运动、取消或完成 | 读目标接受状态、中间反馈、最终结果和实际关节状态 |
| 节点参数 | 配置控制增益 | 查设置结果，再读回实际参数 |

服务客户端用异步调用提交请求，获得Future。Future代表将来的结果，执行器需要继续spin，让响应回调有机会运行。等待依次覆盖服务出现、请求完成和响应内容。每次等待都有墙钟上限。超时意味着客户端在期限内没确认结果，若请求可能改变世界状态，应先查真实状态，再决定下一步。

动作内部把目标提交、取消请求和结果查询组织成服务，把执行反馈和状态组织成话题。客户端通过目标句柄关联本次目标。目标被接受意味着服务器愿意执行，之后再看反馈和结果。不同目标可以有不同最终状态。[ROS 2动作设计](https://design.ros2.org/articles/actions.html)

## 闭环从哪里得到位置

Gazebo世界用滑动关节限定运动轴。关节状态发布系统提供物理计算得到的位置和速度，经桥接送给控制节点。控制器读取具有递增仿真时间戳的新状态，计算目标位置减实际位置的误差，按比例增益产生有界速度命令，再经桥接送给Gazebo关节控制系统。滑块实际位移由物理引擎推进。反馈和结果应使用实测位置与速度，目标值只作为参考输入。`/gt/rail/joints`将Gazebo的Model关节状态桥接为ROS 2 JointState。`/gt/rail/velocity_command`把ROS 2 Float64速度命令桥接为Gazebo Double。[Harmonic JointController接口](https://gazebosim.org/api/sim/8/classgz_1_1sim_1_1systems_1_1JointController.html)

比例控制可写成`v_cmd = clip(gain * (target - position), -v_max, v_max)`。速度上限为0.42m/s。距离大时会触及限幅，接近目标后速度逐渐下降。增益越高，同一误差产生的速度命令越大，达到限幅后的命令保持相同。误差进入0.022m后，控制器开始发零速度。连续三次新关节状态的速度绝对值不超过0.02m/s时确认停稳，再按最终位置是否在目标0.035m以内报告成功。观察一次完整运动时，记录目标、误差、速度命令与实际速度。

## 目标生命周期与取消

1. 客户端异步发送Goal，检查服务器是否接受。参数或目标超出约束时，应把拒绝和执行失败区分开。
2. 执行阶段读取Feedback。用实际位置变化确认动作确实推进。
3. 需要提前结束时，向当前目标句柄发送取消请求。取消响应表明请求已被处理，需继续等待最终Result。
4. 服务器在控制循环看到取消后停止施加运动指令，并检查停止后的关节状态，再结束目标。读最终CANCELED状态和结果中的实测值，再检查后续原生位姿是否保持稳定。
5. 正常到达时最终状态为SUCCEEDED。服务器若遇到无法继续的执行条件，应走ABORTED等对应终止路径。

若一个长回调占用所有可运行位置，接收关节反馈和处理取消的回调也会等待。多线程执行器可以给不同回调安排执行机会，回调组控制它们是否可并发。允许并发后要保护共享状态，并保证同一个物理滑块只由已授权的动作更新。[Jazzy回调组指南](https://github.com/ros2/ros2_documentation/blob/jazzy/source/How-To-Guides/Using-callback-groups.rst)

## 参数属于节点

`gain`是控制节点的浮点参数。声明确定参数的类型和默认值，回调检查有效范围。把2.0写成整数2会改变ROS 2参数类型。设置被拒绝时，再读回原值，确认节点仍使用此前的配置。`/control_contract`接受0.3到3.0s⁻¹的有限double，默认1.2s⁻¹。控制器在处理每份新关节反馈时重新读取参数，因此正在执行的目标也能观察到0.8到1.8的切换。实验对比两个增益下未饱和的反馈，逐项用clip公式复算，并在退出时恢复原增益。[Jazzy参数声明与回调](https://github.com/ros2/ros2_documentation/blob/jazzy/source/Concepts/Basic/About-Parameters.rst)

## 在实验终端运行

课程准备时由`build.sh`构建`gazeboteach_rail_interfaces`的srv和action。平台启动关节桥与`/control_contract`。在课程终端加载个人接口工作区，再查看接口并运行对照。

```bash
. ros_ws/install/local_setup.bash
ros2 service call /gt/rail/state gazeboteach_rail_interfaces/srv/ReadRail '{}'
ros2 interface show gazeboteach_rail_interfaces/action/MoveRail
ros2 param describe /control_contract gain
python3 lab.py
```

`ReadRail`的请求为空，响应含`fresh`、`active`、位置、速度和仿真时间。`MoveRail`的目标是`target_m`，接受范围为[−1,1]m。反馈提供实测位置、速度、带符号的剩余误差、实际发送的速度命令、使用的增益与仿真时间。结果返回实测最终位置、速度和说明，最终状态由ROS 2动作协议提供。

脚本用原生`rail_carriage`世界位置对照服务读数，拒绝越界和并发目标。取消测试等待反馈显示已移动超过0.12m且仍在运动，再取消当前目标。收尾时在0.4s仿真时间内检查原生位置漂移不超过0.018m。正常目标在当前位置基础上偏移0.34m，读取两种增益下的反馈，并以原生位置、服务读数和动作Result互相核对最终停稳。新鲜性、执行期限和等待都单独检查。反馈失效或执行超时进入终止路径并发零速度。

若Future超时，先检查接口发现、消息类型和执行器，再查本课世界是否在运行。服务出现但读不到状态时，从Gazebo关节状态发布、桥接方向及接收时刻排查。取消迟迟未结束时，对照取消是否被接受、控制循环是否还有新反馈，以及实际关节是否停下。

独立挑战是实现一个到达后返回初始位置的双目标客户端。第一段完成后读取实际位置与速度，再发送下一段。分别定义到达、超时、取消、反馈失效时的决策，并将各条路径的实际终态记录到表格。

服务可发现时，关节桥可能还没开始传数据。课程启动会等待命令发布端匹配速度桥，并读到两个仿真时间递增的关节状态；正式动作前再次确认。超时先检查桥的两个方向与 Gazebo 是否暂停，不把 DDS 发现当作设备已就绪。
