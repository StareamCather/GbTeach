# M24 · TF2、仿真时间与隔离回放

一个坐标系的位姿会随滑块运动改变。若把过去采到的点用最新位姿变换，即使坐标系名称正确，也会画到错误位置。本课从Gazebo真实位置和时钟出发，练习在指定时刻查TF，再将实时消息保存并隔离回放。建议先完成M22的QoS和发现。

## TF2的方向和时间

一条TransformStamped的`header.frame_id`是父坐标系，`child_frame_id`是子坐标系，变换描述子系相对于父系的位姿。记T_AB为把B系中的坐标变到A系的变换。本课动态边从`world`到`m24_rig`，静态边从`m24_rig`到`m24_sensor`。令W、R、S分别表示这三系，组合为`T_WS(t) = T_WR(t) · T_RS`。逆向查询会取逆变换。

`lookup_transform(target, source, time)`返回从source到target的变换。静态边适用于各时刻，经`/tf_static`的TRANSIENT_LOCAL保留给匹配的晚加入订阅者。动态边由`/tf`发送，随仿真采样时刻更新。在动态边可用的缓存区间内，TF2可以按指定时刻查询并插值。时间为零请求链的最新可用共同时间。它适合先确认连通。处理传感器数据时，用测量自己的时间戳。

查询不到时分三步查。先确认frame名称和发布端，接着确认树连通，最后确认请求时间落在动态历史覆盖内。坐标树连通但时间超出缓存范围，仍会触发时间外推异常。暂停或回退时钟后，等待时限、缓存和控制状态都要按各自语义处理。[TF2 Buffer接口](https://github.com/ros2/geometry2/blob/jazzy/tf2_ros_py/tf2_ros/buffer.py) · [静态广播器QoS](https://github.com/ros2/geometry2/blob/jazzy/tf2_ros_py/tf2_ros/static_transform_broadcaster.py)

本课静态安装偏移为(0.45,0.20,0.15)m，传感器相对车架偏航−0.35rad。车架偏航为0时，安装偏移的世界分量与本地分量相同。车架偏航变成+90°时，世界分量变为(−0.20,0.45,0.15)m。最后再加上车架的世界位置。脚本把车架先设为(−0.65,−0.55,0.65)m、偏航0，再设为(0.65,0.35,0.65)m、偏航+90°。预期传感器世界位置分别为(−0.20,−0.35,0.80)m与(0.45,0.80,0.80)m。动态边来自原生OdometryPublisher在`/gt/m24/rig_pose`发布的Pose_V，经桥接成为`/tf`。静态边由本课节点发布。报告保留两次查询时刻、独立原生车架位姿和实测组合。

## 分开记录四种时间

| 时间 | 在本课中的用途 |
|---|---|
| Gazebo仿真时间 | 物理世界的时间。暂停时停止推进 |
| 消息中的时间 | TF的header标识这次变换的时刻，Clock消息的`clock`字段保存时间值 |
| bag记录时间 | 录包程序给每条记录指定的排序与回放节奏依据 |
| 主机单调墙钟 | 限制等待时间，观察回放到达节奏 |

同一条消息可同时拥有内容中的时间和bag记录时间。即使数值恰好相等，它们也承担不同职责。回放调整的是消息交付节奏。将一段bag以两倍速播放，原始变换或Clock消息内的数值应保持。比较回放速度可记录相邻消息到达的墙钟差，并结合原始bag时间间隔解释。

`use_sim_time=true`让节点的ROS时钟接收`/clock`。世界暂停时，即使ROS时钟停止，客户端仍可用单调墙钟限制连接与查询等待。世界重启引起仿真时间回退时，应重新准备依赖时钟的缓存或控制状态。检查节点自己的`now()`时，也要看设置是否作用于该节点。[ROS 2 Clock与时间设计](https://design.ros2.org/articles/clock_and_time.html)

## 同时保留实时与历史时钟

实时`/clock`来自Gazebo经桥接发布。回放bag中的旧Clock消息时，要将其重映射到独立历史话题。这样实时`use_sim_time`节点继续跟随仿真。历史消息用于检查原始载荷与回放节奏。播放器的`--clock`选项可另外生成播放时钟。本课的隔离方式依赖显式重映射bag中的时钟主题。为历史回放新设TF订阅时，也要检查它绑定的是历史还是实时话题。[Jazzy rosbag2回放选项](https://github.com/ros2/rosbag2/blob/jazzy/ros2bag/ros2bag/verb/play.py)

## 操作与验证

在本课终端运行以下命令。

```bash
python3 lab.py
```

先检查固定边与运动边的父子方向，再对照两个不同采样时刻的变换。记录原生Gazebo时间、ROS节点时间和消息时间，核对测量来自仿真。脚本在两个原生设置的车架位姿采集动态TF，分别按源时间戳查询并和Gazebo位姿组合对照。随后暂停世界，验证20个1ms物理步使原生和ROS仿真时钟各推进20ms，结束时恢复原暂停状态。脚本将实时`/clock`、`/tf`、`/tf_static`的CDR数据写入独立bag，关闭后再读回。确认内容与原始记录一致，再启动真正的rosbag2播放器。它以`--start-paused`启动，等待三个历史话题的订阅者都发现发布端，再通过播放器的resume服务开始回放。三路分别重映射到本次`/gt/m24/replay_<id>`下的clock、tf与tf_static。静态回放沿用TRANSIENT_LOCAL，另外两路使用可靠且易失的回放配置。历史TF由单独的缓存查询，实时`/clock`仍由原有Gazebo桥发布。

保存目录为`recordings/m24-<id>/`。本课选取一部分实时Clock消息，两份被保存的Clock至少相隔40ms仿真时间。录包时间采用原Clock载荷或TF header中的仿真纳秒。sqlite3写入后关闭，再以SequentialReader核对话题、记录时间与原CDR。回放订阅回调再次逐条比较各话题原始CDR顺序，并在历史TF缓存中查询录制时的两个原始时间。报告`bag_counts`、`bag_cdr_sha256`和`replay.received_counts`提供交叉核对。

复查时可用`ros2 bag info`加报告中的`bag`路径查看存储格式、话题和条数。播放器日志路径见`replay.player_log`。脚本验证实时`/clock`发布端的DDS标识保持一致，且回放期间时钟继续前进。更改时间戳做对照前先保存基准记录。若查询动态TF报外推错误，比较请求时刻与缓存最早和最晚时刻。若历史回放有消息但实时节点时钟跳变，核对重映射以及实时`/clock`的实际发布者。

独立挑战是录下同一次运动的LaserScan和TF。选择一个扫描时刻，用该时刻的变换将前向点投到世界坐标，再用最新变换重做一次。比较两种结果，说明误差如何随平移速度和时间差变化。
