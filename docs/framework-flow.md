# 桌面框架的运行流程

本说明对应 G01 的桌面入口、命令行入口和实验会话接入。正式课程按后续目标逐课部署与验收，G01 使用独立的诊断场景验证框架能力。

## 入口和环境

`launch.sh` 先定位自身目录，再调用系统 `/usr/bin/python3 -m gazeboteach`。桌面模式继承启动者的真实显示会话；启动器不会猜测或写入 `DISPLAY`，不会修改系统 Python，也不会自动下载依赖。

输入参数决定后续分支：

- 无参数：打开原生 PyQt5 桌面工作台。
- `--diagnose`：只读检测模拟器、ROS 安装与相关程序，输出 JSON；不会创建练习或启动仿真。
- `--list`：读取本地课包和兼容状态，输出 JSON；不会启动仿真。
- `--smoke ID`：新建独立临时数据目录，准备指定课程、启动真实服务端、运行课程验收、清理本次进程。
- `--smoke-fixture PATH`：同样执行真实实验，但场景直接来自诊断目录，不要求课程已经发布。
- `--gui-check`：显示真实 Qt 窗口，等待环境检测完成，保存本窗口截图并有界退出。

`--smoke` 默认每次使用新的临时数据目录，因此不会误用上次学生副本中的旧场景或旧验收脚本。日志与 JSON 记录保留在输出所列目录中，便于追查失败。只有显式传入 `--data-dir` 才复用指定数据目录。

## 课包选择和阅读

工作台以 `profile + id` 标识课程，而不是只用课号。左侧“教学包 / 运行环境”选择器来自实际课包清单；首批只有 Classic 11 / ROS Noetic，所以单项选择器保持禁用。未来有多套教学包时，可分别筛选，同号课程和学习进度不会串用。

安装检测与当前激活环境分别展示。检测到尚无课程支持的版本时，平台展示检测结果，不把另一版本的实验脚本直接套用。正文始终可读，实验按钮根据对应环境条件启用。

选择课程时，界面载入以下内容：

1. `lesson.json` 的标题、目标、简介和命令；
2. `lesson.md` 的完整讲解；
3. 个人练习目录与初始化说明；
4. 该课独立的运行、验收和历史记录。

正文使用本地有限 Markdown 渲染器转换成 Qt 富文本，兼容 Qt 5.12。HTML 源内容被转义，外部资料链接只接受 HTTP/HTTPS；本地教材无需网页服务或联网资源。

`reference` 为可选的课内相对文件路径。“查看参考答案”在单独的只读页呈现这个文件；加载答案不会写入或替换个人练习。没有单独答案的课程明确显示未提供，不将模板冒充学生已完成的结果。

## 开始实验的数据流

开始按钮先检查课包兼容条件，然后在后台执行：

`当前课程 → 个人副本准备/更新检查 → 本课环境 → 独立会话 → 真实 Gazebo → 就绪观测 → 窗口与终端`

具体顺序如下：

1. 若前一课仍有会话，先结束前一课拥有的进程。
2. 由存储模块准备个人副本。逐文件计算源模板 SHA256，与上次模板指纹及当前学生文件比较：仍等于旧模板的文件可以更新；学生改动和额外文件保留；模板与学生同时修改的文件标记冲突。恢复起点前完整备份，复制失败时回滚。
3. 为本课生成独立 Gazebo Master URI、ROS Master URI 和 Ignition Transport partition。
4. 首先加载本机 Gazebo 安装提供的 setup，保留系统材质、着色器、OGRE 和插件路径；课程需要 ROS 时在此基础上加载对应环境。最后追加本课资源并覆盖隔离参数，随后按需启动本课 ROS Master。
5. 执行 `prepare` 有限准备命令，随后启动本课 `gzserver`。
6. 观察本课世界的通信状态，确认世界就绪；进程刚创建不计为就绪。
7. 执行 `after_start` 准备命令及受管理的辅助节点。
8. 打开 `gzclient`、运行日志终端和实验操作终端。
9. 界面更新运行状态，记录本次环境、会话和日志位置。

后台线程通过 Qt 信号把进度和结果交回主线程。主线程只更新控件，因此构建插件、等待世界或执行验收时，教材窗口仍然可用。耗时操作期间课程树暂时禁用，防止同一会话被连续切换。

“进入课程后自动开始实验”是可选设置。关闭时，可以先读教材；打开时，进入选定课程后走同一套准备流程。

## 命令、控制和文件

课程命令显示原文与用途，学生可以复制，也可以选择“在本课终端执行”。终端继承本课环境并进入个人副本，控制指令指向本课仿真。

- 暂停/继续：先读取本课实际暂停状态，按需发送一次控制，再回读确认。
- 单步：先确认本课实际已暂停，再执行一步仿真，用于观察离散状态变化。
- 重置模型状态：恢复模型初始状态，保留项目文件。
- 重载项目：结束旧会话，再按当前个人文件启动新会话。
- 编辑练习文件：优先用 gedit 打开副本的世界文件；否则打开对应目录。
- 备份并恢复起点：先保存当前副本，再从课程模板建立新起点。

暂停/继续的确认来源是本课 `/gazebo/{world}/world_stats` 中的 `paused`，不是界面上次保存的布尔值。每次读取都通过本会话管理的 `gz topic -e ... -d 1` 子进程执行，继承独立 Master、partition 和会话令牌；输出写入本会话临时文件，读取结束后移除。首次读取限时 3 秒；无法读取实际布尔状态时直接失败，不盲发控制。

若实际状态已等于目标，跳过 `gz world -p`。否则仅发送一次目标布尔值，并在 4 秒确认窗口内只读回查；每次查询使用剩余时限且不超过 3 秒。命令非零或超时也不重发控制：原返回错误和工具日志保留，只有后续实际观测到目标状态才接受，并在日志及事件详情中留下明确警告；状态未知或未变化则失败。缓存、界面状态和暂停/继续事件仅在观测确认且会话仍运行时更新，取消或结束会话不会被后到的观测覆盖。

单步和多步每次都走上述暂停确认流程，因此 Gazebo 窗口或学生终端改变暂停状态后，旧缓存不会让步进在运行中的世界直接执行。确认后仅发送一次 `-s` 或 `-m N`；步进命令错误直接保留失败，不重放脉冲，也不记录步进完成。

编辑器属于学生的文件编辑窗口，自动结束实验时不强制关闭编辑器，以保留尚未保存的编辑。应用只清理本次实验拥有的服务端、客户端、课程辅助节点和终端会话。

## 验收与状态

点击“验收实验”时，在当前练习目录、相同环境中运行课程源目录提供的当前验收脚本。验收读取学生正在运行的实验状态；学生副本里的验收文件可用于学习，但修改它不会替换平台的正式验收。返回值与日志中的真实观测共同形成结果：

- 退出码为零：记录本次自动验收通过；
- 非零或超时：保留失败原因与日志；
- 没有自动验收脚本：提示使用人工观察检查，不标记自动通过。

阅读、启动、参考答案查看和验收分别记录。历史验收通过说明某次实验通过了对应检查，不代表之后任意修改都会继续通过。

界面定期检查核心进程和图形客户端。服务端退出或客户端消失时，状态区显示实际异常，保留“重载项目”或“重开 Gazebo 窗口”的恢复入口。

## 结束、切课和退出

结束过程先设置取消标记，阻止继续创建子进程。每个受管理进程记录 PID、启动时间和随机会话令牌；终端包装器记录自己的 PID、进程组与会话。清理前核对这些标识，避免 PID 复用误伤其他程序。终端先接收 HUP，其他进程有界等待退出；必要时只升级清理本会话拥有的组。ROS 启动器派生的子组仍按会话令牌追踪，即使父进程已经退出也可回收。

共享的 GNOME Terminal 服务不属于某一课程，所以不在清理范围，也不按 `gzserver`、`roscore` 等名称批量杀进程。

VTE/xterm 已为终端子进程建立独立会话，因此终端直接执行受管理的 Python 包装器，保留原生控制终端。包装器记录 PID/PGID/SID、启动时间、会话令牌、TTY 和前台进程组；交互 Bash 加载后再次确认任务控制开启，才报告终端就绪。GNOME 窗口通过独立 role 标记归属；共享终端服务不随课程结束。这样 Ctrl+C、前后台任务与课程结束清理各自作用于正确的进程。

切课与应用退出都先结束当前实验。个人副本、备份和记录保留，下一次进入课程可以继续。

## G01 的独立验证入口

在项目目录下执行：

```bash
./launch.sh --diagnose
./launch.sh --list
./launch.sh --smoke-fixture tests/fixtures/diagnostic --seconds 2
./launch.sh --smoke-fixture tests/fixtures/diagnostic --gui --terminals --seconds 2
./launch.sh --gui-check --smoke-fixture tests/fixtures/diagnostic --screenshot /tmp/gazeboteach-g01.png
```

最后两项需要真实图形会话。GUI 检查的课程数据与 QSettings 均使用临时目录，不修改学生的桌面偏好。JSON 报告会显示 `DISPLAY`、Qt 版本、截图结果、服务端/客户端状态及日志位置；实际验证结论由主维护者写入 `docs/VALIDATION_LOG.md`。
